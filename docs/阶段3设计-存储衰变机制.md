## 一、现状与核心约束

### 1.1 现行机制（将保留/改造）

| 机制 | 现状 | 阶段3 角色 |
|---|---|---|
| Goods[3]（皮革/羊毛/秸秆） | 副产品累积入档，无消耗 | 保留（贸易期用）；粮食另建池 |
| GrowthModel 存储缓冲 | 无状态 relief 系数 | **升级为真实存储池**（见 §3） |
| storage/pottery/settle 能力 | 技术开关 | 决定存储容量/衰变率层级 |
| FLast（当 tick 产出） | Harvest 算，Growth 读 | 存储池的**流入** |
| Surplus（e−1） | 诊断用 | 存储池的净流参考 |

### 1.2 ⚠️ 核心约束：tick = 100 年

`TickYears = 100`（每 tick 代表 100 年）。这直接决定衰变语义：

- **史实**：粮食储存是**年度循环**（秋收存到次年/灾年）；考古上谷物可存 1-3 年（地下粮窖），
  陶器密封可存 3-5 年，定居粮仓（大型储窖）可存 5-10 年（Testart 1982"存储-富足社会"分水岭）。
- **tick=100 年**下，若衰变按 tick 算：一池粮食 1 tick 内腐坏 30%+，则"跨年存储"在模型里只有
  0-1 tick 的缓冲能力——**存储池必须按年度子步进或按比例衰变**才能有意义。

**两个可选方向（需用户拍板）：**

- **方向 A：年度子步进（推荐）**——存储模型内部按年步进（每 tick=100 年 → 100 步），
  每年产出/消耗/衰变细粒度模拟。代价：存储模型每次执行 100 步（O(部落×100)，可接受，部落数百）。
  收益：衰变是**真实的年度腐坏率**（史实锚点直接可用），饥荒涌现自然（年景波动→逐年吃存粮→枯竭）。
- **方向 B：tick 比例衰变**——衰变率按 tick 折算（如"年衰变率 × 100 = tick 衰变率"），
  无子步进。代价：跨年缓冲在整数 tick 粒度下粗糙（存粮只够 0-1 tick）。收益：实现最简。

## 二、机制设计（方案 A 为主体，方向 B 为降级）

### 2.1 动态商品目录（所有可存储商品，可扩展）

> ⚠️ 2026-08-18 用户修正：**不只食物，所有能存储的商品都进存储/衰变体系**；
> 且商品是**动态目录**（后续还能加新商品，不硬编码固定槽位）。

**设计：静态注册表 + 每部落 Stocks 数组**（与 TechTable 同模式）：

- `CommodityTable`（静态注册表）：每商品一条 `CommodityDef`：
  | 字段 | 含义 |
  |---|---|
  | `Id` | 商品 id（"grain"/"berry"/"leather"…） |
  | `Kind` | 大类：`Food`（参与饥荒）/ `Material`（只存+衰变，贸易备货） |
  | `BaseDecay` | **商品自身年衰变率**（"特定食物耐存储"——谷物低、浆果/肉高） |
  | `Consumed` | 是否被人口消耗（Food=是，P 人当量·年/人） |
  | `Produce` | 每 tick 流入（从 FLast 分量提取） |

- 部落新增：`float[] Stocks`（长度 = 目录数，惰性初始化；索引 = `CommodityTable.Index(id)`）。
- **加新商品 = CommodityTable 注册一行**（+存档 bump）——不碰机制代码，动态扩展。

**商品目录（初始 6 类）**：

| Id | Kind | 流入（Produce） | 消耗 | BaseDecay/年（史实） |
|---|---|---|---|---|
| grain 谷物 | Food | FFarmLast（农业谷物） | P | **0.08**（谷物可存数年——耐储） |
| berry 浆果 | Food | FBerryLast（浆果采集） | P | **0.5**（鲜果数天-数周——不耐储） |
| meat 猎物/奶肉 | Food | FHuntLast−FBerryLast + FHerdLast | P | **0.4**（肉/奶短期） |
| leather 皮革 | Material | FHuntLast × 0.10 | 无 | 0.03（鞣制耐久） |
| wool 羊毛 | Material | FHerdLast × 0.15 | 无 | 0.02 |
| straw 秸秆 | Material | FFarmLast × 0.05 | 无 | 0.01（干草耐久） |

> **"特定食物耐存储"落实**：grain BaseDecay=0.08 远低于 berry 0.5/meat 0.4——
> 农业谷物成为唯一可长期囤积的粮食（史实：新石器革命=谷物耐储才使定居囤粮成为可能，
> Testart：采集社会无耐储主食 → 无法囤积 → 无定居）。**这是农业→定居→文明的因果链涌现。**

### 2.2 衰变率（技术分层 × 商品基础耐储）

`effectiveDecay = BaseDecay × techMult`，techMult 按技术层级（Testart 锚点）：

| 技术 | techMult（乘在 BaseDecay 上） | 史实 |
|---|---|---|
| 无 storage | 1.0 | 游群随取随食 |
| storage（粮袋/土窖） | 0.6 | 可存 1-3 年 |
| +pottery（陶器密封） | 0.3 | 可存 3-5 年 |
| +settle（定居粮仓） | 0.15 | 可存 5-10 年 |
| grinding 加工态 | 再 ×0.7 | 磨盘去壳/鞣制提升耐久 |

例：grain+storage+pottery+grinding → 0.08×0.3×0.7 = 0.0168/年（谷粒+陶罐+去壳，可存数十年）。
berry 即使全技术 → 0.5×0.15×0.7 = 0.0525/年——仍不耐储（鲜果物理本质，技术救不了）。

### 2.3 仓库建筑（定居格上）——总容量载体

- **建筑 = settle 派生的总容量上限**：`WarehouseCap = SettleCap × P`（10×P 人当量·年，够 10 年口粮）。
- 容量按 Kind 分配：`Food` 类合计 ≤ 6×P（主仓存粮）；`Material` 每类 ≤ 1.3×P（附仓存皮毛草）。
- **容量饱和**：超限部分腐坏（不能无限囤积——史实：仓储有限）。
- storage/pottery 无 settle：容量小（2×P 总量，随身携带随取随食）。
- 建筑不单独入档（settle+P 派生），**Stocks[] 入档**。

### 2.4 饥荒涌现（非硬标志，Food 类枯竭驱动）

- GrowthModel 读**有效粮食** `FoodEff = 当年 FLast 食物部分 + Σ Food 类 Stocks 净贡献`：
  - Food 类合计未枯竭：`FoodEff = FLast`（当年产出直接消费，存储为缓冲）。
  - 枯竭：缺口 `deficit = P − (FLast + ΣFood Stocks)` → 饿死因子按缺口算。
- **涌现路径**：连续坏年 → 逐年吃存粮 → 衰变+消耗 → 枯竭 → 缺口扩大 → 饿死。
  自然产生"存储文明灾年幸存、无存储文明灾年崩溃"分野（Testart 分水岭涌现版）。

### 2.5 存档（阶段3架构化红利）

- `Stocks[目录数]` 入档（CivArchiveSchema SinceVer=12）→ 持久字段，SettleDerived 不冲突。
- 衰变/流出是**副作用**（每 tick 一次）——`AccumulateStorage` 放 AccumulateGoods 同层，绝不在 SettleDerived 里。
- **旧 Goods[3] 并入**：v11 读入时 Goods[皮革/羊毛/秸秆] → Stocks[leather/wool/straw] 槽；新 Food 槽默认 0。
- 未来加商品：目录数 +1 → v13 数组变长，旧档读入补 0（同 TechTable 扩展模式）。

### 2.6 grinding 的合理效果（用户指定：粮食耐储 → 泛化为"商品耐储"）

> 用户原话方向：grinding 不做生产倍率（防双计），候选 = **粮食耐储（衰变降低）**。
> 2026-08-18 扩展：耐储通道对**所有商品**生效（加工 = 统一提升储期）。

- **史实依据**：研磨去壳 → 谷物更耐储（未去壳稻/麦可存更久，但研磨后更易受潮——需陶器配合；
  实际史实是**去壳谷粒 + 陶罐密封**组合最优）。石器磨盘（grinding）本身主要是**加工**，
  真正的耐储提升来自干燥+密封。皮革鞣制（加工）同样提升耐久（生皮→熟皮）。
- **设计**：grinding 不直接降衰变（防与 pottery 双计），而是**解锁"加工耐储"通道**——
  有 grinding 的部落，商品以"加工态"存储（衰变按 storage 档低一档）；
  无 grinding 的部落即使有 storage，商品以"生/鲜态"存储（衰变高一档，如 +0.1/年 粮食 / +0.03/年 非食物）。
- 效果：grinding 在存储文明里价值显现（存粮更耐久），在游群阶段无感——史实正确
  （磨盘/鞣制是定居文明工具，狩猎采集不用）。

### 实施中关键修正（相对设计稿）

- **年度子步进 → tick 尺度缓冲**：年度波动（0.5-1.5/年）在 100 年聚合下均值≈1 无机制意义；
  改为 **tick 尺度**（每 tick 产出 = FLast 直接，无额外波动；存储 = 跨 tick 缓冲）。
  衰变按**年率折算 tick**（decayTick = 1−(1−BaseDecay×techMult)^100）——保留史实锚点量级。
- **时序分工**：AccumulateStorage（tick 开头，上 tick FLast）做 Material 流入 + 全类衰变/容量；
  Growth（Order 20，本 tick FLast）做 Food 缺口/盈余。避免双算口粮。
- **CellF 对齐修复（T02/T04 分叉根因）**：测试对比前演化端只 RebuildInfluence 导致 CellF 与
  CellOwner 脱节 → 统一用 `SettleDerived`（唯一入口全自洽）。
- **T04b 预热**：ChiefdomModel.Rebuild 的继承窗口 SuccessionUntil 是已知副作用 → 幂等断言前
