# 设计 · 季风气压场的架构

- 状态：**架构设计**（2026-10-24）；**Step 0 已实施**（气压事实 + 气压图 + 3 个测试），Step 1–4 未动
- 前置：[`方案-季风气压场重建.md`](./方案-季风气压场重建.md)——物理、公式、标定、验收数值都在那里，本文不重复
- 范围：`scripts/Logic/Climate/` 的模块切分、`ClimatePipeline` 装配、`WorldFacts` 契约、地图变体轴、`ClimateSpec`、测试
- 非目标：不加垂直层、不加时间积分、不引入瞬变涡旋、不动洋流求解器内部、不重构 `ClimateGrid`

**一句话**：把"季风"从一个风场里的经验项，改成**"气压是一个世界事实，风是它的一个响应"**——一份状态、一个梯度、三个闭合、三个视图。

---

## 一、这是结构问题，不是公式问题

方案 §一 已经证明"放大季风项没用"。在架构上还有四条独立于物理的结构问题：

1. **一个函数干三件事**。`DiagnosticWindModel.Build` 里同时住着：气候态查表（`BandU/V/W`）、热力响应（`geo` / `mon`）、显示标定（软饱和 + 地形减速）。三者绑死 ⇒ 删风带必须同时重标定，改季风必须重跑整张风场，任何一项都不能单独验证。方案 §E 的"整段删除"清单，本质是在拆这三件事，而不是换公式。

2. **一份风扛三种下游语义**。地面风（出图、风反转验证）、低层风（水汽输送、地形雨）、自由层风（洋流）是三个不同的东西，现在共用 `MonthWind`。代码里没有任何地方能表达"洋流该吃哪一层"——`ClimatePipeline.cs:78` 把地面风的年合成直接喂给洋流，这是当前唯一可能的选择，不是正确的选择。

3. **派生量与源数据双份存储**。`Wind` 同时存 `Monthly`（矢量）与 `MonthlySpeed`（标量），而 `|wind| == speed` 是隐式不变量；`WindFlowOverlay.cs:198` 甚至先算了一遍 `len`，再读 `speeds[i]`。同源靠约定维持——这正是"底色和风丝打架""图上吹东风、洋流按另一套转"这类 bug 的土壤。

4. **因果断链**。`MonsoonStrength` 用"水汽 × 月辐射"（`MonthlyClimate.cs:202`），与风向、气压都没有因果关系，却占着"季风"这个名字。它的下游为空（只有 `WorldFacts` 携带 + 冒烟打印），所以改口径便宜；但"名字承诺了它没有的因果"这件事本身要修。

结论：**换公式不够，要让"风只能来自气压"在类型和调用图上成立**；否则半年后又会有人往风里加第五项。

## 二、目标结构

```
        ClimateGrid（既有只读事实：dirs / 邻接 / 海陆 / 海拔 / 距离 / NeighborKm）
                              │
              CoarseLayer（res4 → res2 父格映射）
                              │
                              ▼
              PressureFieldModel.Prepare ──► PressureStatic
              （p_z 样条 / eff / B / E / 两套核 —— 只算一次）
                              │
   月温 ──► seaLevelTemp ──► BuildMonth
                              │
                      PressureField（逐月 p，hPa）
                        │                     │
                 ∇p（每格一次）          MonsoonIndex（Δp 口径）
                        ▼
                WindSolver.SolveAll
              ┌─────────┼─────────┐
        r_surface    r_low     r_free
              ▼         ▼         ▼
        WindSet(地面) WindSet(低空) WindSet(自由)
              │         │         │
              ▼         ▼         ▼
      地图/风丝/侵蚀  水汽/地形雨  洋流（年合成）
```

六条规则，按重要性排：

- **R1 唯一编排者**：`MonthlyClimate` 是唯一知道"月温 → p → ∇p → 三套风 → 水汽 → 降水"顺序的地方。**模型之间不互相调用**——`PressureFieldModel` 不认识风，`WindSolver` 不认识温度、也不认识 `ClimateGrid` 以外的东西。跨模型的数据只经参数传递，谁依赖谁在签名上一眼可见。
- **R2 状态与响应分离**：气压是状态（逐月、可出图、可判读），风是它的一次局部响应。拆开的判据不是"代码多少行"，而是**能不能只换响应而不动状态**——这正是要做的 A/B（`WindPressureDriven`）。
- **R3 一个梯度三份响应**：`SolveAll` 在同一遍邻居循环里写三个目标数组。结构上**不可能**出现"两套风来自不同的 p"——它们没有第二个梯度可拿。
- **R4 事实只读、构造即校验**：`PressureField` / `WindField` 在构造之后不再写；长度校验沿用 `WorldFacts.Aligned` 的纪律。事实对象是下游唯一取数口。
- **R5 回退只在一处**：`WindPressureDriven` 只在编排者读一次。两条分支必须产出**同样形状**的事实（回退时三套风指向同一份数组，见 D5），否则下游要分叉。
- **R6 显示不生产**：地图只读事实；能从事实导出的（逐月风速）不落库；地图不为显示改数据、也不算第二遍物理。

## 三、模块与契约

| 模块 | 职责 | 明确不做 | 依赖 |
|---|---|---|---|
| `CoarseLayer`（新） | res4 → res2 父格映射、粗层邻接与方向、粗层格距 | 不做平滑、不做物理、不持有气候场 | `Ball`（仅装配时） |
| `CoarseKernel`（新） | 固定核一次卷积（大圆距离权重、按行归一化） | 不迭代、不 SOR、不做上采样 | `CoarseLayer` |
| `PressureFieldModel`（新） | 三项气压合成；静态部分 `Prepare` + 逐月 `BuildMonth` | 不认识风；不做季风判定；不做显示 | `ClimateGrid`、`ClimateSpec`、`CoarseLayer` |
| `PressureField`（新事实） | 逐月/年均 p（hPa），构造即校验 | 不存中间量（异常场、粗层场、核） | — |
| `TangentField`（新工具） | 切平面梯度（唯一实现） | 不认识任何气候量 | `ClimateGrid` |
| `WindSolver`（新） | 带线性摩擦的定常解；三闭合一次算完；出口软饱和；地形只乘地面 | 不认识温度/气压场本身；不做降水；不读地图 | `ClimateGrid`、`ClimateSpec`、∇p |
| `WindField` / `WindSet`（新事实） | 三份视图 + 年合成；逐月风速派生 | 不存逐月风速；不做显示 | — |
| `MonthlyClimate`（改） | 唯一编排者；年合成；季风口径接线 | 不含任何物理公式 | 以上全部 |
| `MonsoonIndex`（新，纯函数） | Δp 口径的季风强度 | 不认识降水；不读地图 | 逐月 p + 海陆掩码 |
| `ClimatePipeline`（改） | 装配；洋流第二遍改吃自由风年合成 | 不解释物理 | 以上 |
| `WorldFacts`（改） | 气压段 + `WindField` | 不存算法 | — |
| `PressureMode`（新）/ `WindMode`（改） | 气压图；风场变体行 | 不生产、不改数据 | `WorldFacts` |

关键签名（省略 XML 注释，形状即契约）：

```csharp
sealed class CoarseLayer
{
    int Count { get; }
    int[] CoarseOfCell { get; }        // res4 格 → res2 格（逐格，长度 = n）
    int[][] Neighbors { get; }         // 粗层邻接
    Vector3[] Dirs { get; }
    double NeighborKm { get; }
    static CoarseLayer Parent(Ball ball, int targetRes);   // 生产：res4 → res2
    static CoarseLayer Identity(ClimateGrid grid);         // 测试：恒等映射，同一条卷积代码
}

sealed class PressureFieldModel
{
    static PressureStatic Prepare(ClimateGrid grid, ClimateSpec spec, CoarseLayer coarse);
    void BuildMonth(ClimateGrid grid, ClimateSpec spec, PressureStatic s,
        float[] seaLevelTempC, float[] destinationHpa);
}

static class WindSolver
{
    // 一遍循环写三个目标；地形只乘 surface；软饱和只在出口做一次。
    static void SolveAll(ClimateGrid grid, ClimateSpec spec, Vector3[] pressureGradient,
        Vector3[] surface, Vector3[] low, Vector3[] free);
}

public enum WindKind { Surface, Low, Free }

sealed class WindSet
{
    public WindKind Kind { get; }
    public Vector3[][] Monthly { get; }    // [month][cell]
    public Vector3[] Annual { get; }       // 12 个月矢量均值
    public float[] AnnualSpeed { get; }    // 12 个月 |v| 的算术均值（不可由 Annual 导出）
    public int MonthCount { get; }
    public float SpeedAt(int month, int cell) => Monthly[month][cell].Length();   // 逐月；年均用 AnnualSpeed
}

sealed class WindField
{
    public WindSet Get(WindKind kind);
    public WindSet Surface => Get(WindKind.Surface);
}
```

**为什么 `Prepare` / `BuildMonth` 要分开**：`Prepare` 里的东西（E 指示场、两套核、`p_z` 样条）与季节无关。方案 §六 A 特意强调过"第③项整项可一次算好，不进月循环"；把它放进 `BuildMonth` 就会有人忍不住按月亮调它。**用接口形状保证"静态"这件事**，比注释可靠。

**为什么 `WindSolver` 只吃 ∇p**：它一旦能拿到温度，就又会有人加 `+∇T′`。它拿不到 `PressureField` 本身，也就没法偷偷重算一遍气压。

## 四、月度时序与存储

`MonthlyClimate.Compute` 的月循环变成：1 → 9，顺序不可换（后段吃前段）。

```
1. BuildMonthTemperature            → T[m], seaLevelTemp（临时数组，不存 12 份）, radiation
2. beltShift = PressureBeltShiftFactor × 太阳赤纬 → 编排者把 deltaRad 传进 PressureFieldModel
3. PressureFieldModel.BuildMonth     → p[m]（hPa，存档）
4. grad = TangentField.Gradient(p[m])→ 临时，用完即弃
5. WindSolver.SolveAll               → surface[m] / low[m] / free[m]（存档）
6. BuildMoisture(low[m])             → 水汽（临时）
7. BuildMonthPrecip(low[m])          → 月降水（存档）+ 地形雨
8. MonsoonIndex 记账                 → 每月 Δp（临时；Finalize 里定强度）
9. Finalize                          → 年均温/年降水/三套年合成/年均标量风速/p 年均/季风强度
```

★实施调整（2026-10-24，Step 0）：月温先整轮算完（`MonthTempC` 本来就要存档），第二段再跑气压/风/降水。
理由只有一个——热力项的年均偏置必须用**真实的 12 个月平均 T_sl** 扣；用年基温近似会在高纬留下几 hPa 的常年偏差。
不多存一份 `seaLevelTemp`（从 `MonthTempC` 现重建）。

存储账（res4 = 288,122 格，单份逐月矢量 = 41.5 MB）：

| 数组 | 单份 | 现状 | 重建后 |
|---|---:|---:|---:|
| 逐月风矢量 | 41.5 | 1× = 41.5 | 3× = 124.5 |
| 年合成风矢量 | 3.5 | 3.5 | 10.4 |
| 逐月显示风速 | 13.8 | 13.8 | **0（派生：矢量长度）** |
| 年均标量风速 | 1.2 | 1.2 | 3.5（三套） |
| 逐月气压 | 13.8 | 0 | 13.8 |
| 年均气压 | 1.2 | 0 | 1.2 |
| **合计** | | **60.0** | **153.4（净增 ≈93 MB）** |

- **不存**：∇p（每格一次，用完即弃）、每月 `seaLevelTemp` 的 12 份副本（在循环内消费）、粗层中间场、核以外的一切。
- **必须存**：逐月 p（气压图 + 季风口径 + 调试都要按月份看）；年均标量风速（`|mean v| ≠ mean |v|`，见 D4）。
- 若内存吃紧：p 只存"年均 + 1/7 月"可降到 ≈142 MB（净增 ≈82 MB，方案 §G 的口径），代价是气压图没有逐月参数——与温度/降水/风场的交互不一致。**建议全存**，这 11 MB 不值得换一个特例。

## 六、接缝审查（跨模块数据流）

树形分解会漏掉横向依赖。逐条列出这次改动穿过的每一段，**每段必须有归属**：

| # | 数据流 | 源 → 中间 → 消费 | 归属 | 已知陷阱 |
|---|---|---|---|---|
| F1 | 温度 → 气压 | `seaLevelTemp`（含 6 °C/km 回补）→ `T̄_λ` 偏差 → p | `PressureFieldModel` | 回补用的是硬编码 `6e-3`（`MonthlyClimate.cs:174`），而 spec 有 `LapseRateCPerKm`。改成读 spec，默认值下逐位不变 |
| F2 | p → ∇p | hPa → 切平面梯度 | `TangentField` | 极点退化（复用 `NorthTangent`）；不做经度环绕特判，靠球面切平面 |
| F3 | ∇p → 三套风 | 一个梯度 × 三个 r | `WindSolver.SolveAll` | r 的顺序（D7）；软饱和会压平三套风的差异（验收要在未饱和格上做） |
| F4 | 低空风 → 水汽 | 上游邻格 → 步数 → 衰减 | `MonthlyClimate.BuildMoisture` | 风场成环时整条链判无海（现有栈解析保留）；`MoistureDecayPerStep` 必须重标定 |
| F5 | 自由风 → 洋流 | 年合成矢量 → 风应力旋度 | `ClimatePipeline` | 自由风比地面风快 ⇒ 旋度变大 ⇒ 洋流变强（`OceanStrengthGain` 可能要重标） |
| F6 | p → 季风 | 逐月 Δp（对同纬海洋均）→ 强度 | `MonsoonIndex` | 高纬无海带 ⇒ 均值 NaN ⇒ 该带不判（沿用 `BuildOceanMean` 口径） |
| F7 | 风 → 地图/风丝 | 同一 `WindSet` | `WindMode` / `WindFlowOverlay` | 底色与风丝必须读同一 `kind`；但 `_meshCache` 只按月份做键（`WindFlowOverlay.cs:142`），切档时月份没变 ⇒ 会命中旧档的风丝网格。**缓存键必须扩成 (month, kind)**，否则"底色换了、丝没换" |
| F8 | 粗层 → 细层 | res2 卷积 → 父格上采样 → 2 遍 res4 平滑 | `PressureFieldModel.BuildMonth` | 六边形台阶；平滑归气压模型，不归 `CoarseLayer` |

**三处"不归任何人"的中间层**，必须显式认领，否则就是并行/分步实施时的盲区：

1. **上采样后的收尾平滑**：`CoarseLayer` 只负责"映射"，`CoarseKernel` 只负责"粗层卷积"；"上采样后再抹 2 遍 res4"是**气压场的平滑**，归 `PressureFieldModel.BuildMonth`。没人认领的话，最可能的结果是两个模块都以为对方做了。
2. **"年合成"的定义**：三套风各有一个年合成，是**矢量均值**；年均显示风速是**标量均值**。两者不是同一个统计量（F5 吃前者、地图吃后者）。定义只写在 `Finalize` 一处，三个 `WindSet` 用同一个函数算。
3. **风速量纲**：事实里的风是 **0–1 的软饱和代理量，不是 m/s**。方向是物理的，大小是标定的。所有下游（洋流应力、水汽、地图）都在用这个代理量——谁都不能在别处再乘一次饱和或再归一化。

另外登记一处**两个 ITCZ**：降水骨架用太阳赤纬（`deltaRad`），气压用热赤道（`Δc`）。真实行星上两者近似重合，本世界因海陆不对称会分开。本轮不统一（统一会动降水，属另一次改动），但它是"同一概念两处定义"的典型，写进 §十三。

还有一条**启动项**不属于本轮改动，但必须说清楚：洋流第一遍仍吃 `PrevailingWind`（解析盛行风）——它发生在月温之前，气压场还不存在。这条边是无环因果链的启动项，第二遍（自由风 + 热成风）才是存档场。不要为了"统一风源"去把第一遍也换成气压，那会引入一个真正的循环。

## 七、新实体的公民权

气压是新增的世界事实，必须像温度/降水一样能参与所有活动，而不只是"算出来了"：

| 维度 | 检查项 | 落点 |
|---|---|---|
| 数据消费 | 能读到逐月/年均 p | `WorldFacts.PressureMonthlyHpa` / `PressureAnnualHpa` |
| 行为消费 | 能被 ∇ 消费；能驱动风；能判季风 | `TangentField` → `WindSolver`；`MonsoonIndex` |
| 可见性消费 | 所有月份参数下可见；回退开关两种状态下都可见 | `PressureMode`（参数行 = 年均 + 1–12 月） |
| 可解释性 | 冒烟能打印极值/中心/反转格数 | `--world 4` 冒烟段 |

三套风同样是新实体：`WindSet(kind)` 必须能在**同一个世界快照**里取到三份不同数组，且重复取返回同一引用（切档零重算）；地图切档只换数据源，不触发重新生成。

## 八、关键决定

**D1 · 气压独立成模型**（备选：并进风模型）。
若并进，气压就没有"事实"身份：气压图只能从风反推，季风口径也只能寄生在风里。**选独立**。代价是多一个类、多一次 `Prepare`（≈5 ms）。

**D2 · 粗层用 `CoarseLayer` 注入，不改 `ClimateGrid`**（备选：方案 §八 的 `ClimateGrid.Res/CellIds`）。
`ClimateGrid` 的立身之本是"纯数组、不认 Ball、可在合成网格上单测"（`ClimateGrid.cs:13-15`）。父格映射需要 H3，把它塞进 `ClimateGrid` 会把 Ball 依赖带进纯托管测试。**选注入**：pipeline 用 `Ball` 建 `CoarseLayer.Parent`，测试用 `Identity`，同一条卷积代码两种分辨率都跑。

**D3 · 三套风全存（A），不现算（B）**。
方案 §C 把 B 描述成"省内存、切档 10 ms"。真正的代价是**事实端口要么可变、要么表现层要会求解**：切档发生在重烘路径上，风丝还在 worker 线程读数组，惰性物化会直接踩数据竞争。**选 A**（+93 MB，桌面端可接受）；把"现算"留成 `WindField.Get` 的内部替换，等真有内存压力再说。

**D4 · 删逐月风速数组，保留年均标量风速**。
逐月风速 = `|v|`，可派生（`WindFlowOverlay.cs:198` 本来就在算），删掉 3 × 13.8 MB，同时消灭"两套值"这一类 bug。但**年均不能删**：`|mean v| ≠ mean |v|`，季风区年合成矢量会互相抵消，而"年均风速"要的是标量均值（否则季风区在年均图上显示成无风）。规则一句话：**能从事实导出的不存，导不出的才存**（年均标量 1.2 MB × 3）。

**D5 · 回退语义：只切风，不切气压；三份别名。**
`WindPressureDriven=false` 时：p 照算（气压图与季风口径不依赖这个开关，也是 A/B 的对照基准），风走旧 `DiagnosticWindModel` 写入 surface，**low/free 与 surface 指向同一份数组**。这样下游代码零分叉，回退测试是逐位等价。"同引用"有可写性风险——现有消费方全部只读（地图/洋流/水汽），登记即可；等回退开关退役时一起消失。

**D6 · 契约改名，不留兼容别名**（见 §五）。

**D7 · 摩擦系数必须单调：`r_地面 > r_低空 > r_自由`。**
方案 §C 写 `r_850 ≈ 0.3–0.5 r_s`、`r_自由 ≈ 0.5 r_s`，而 §九.7 要求 `|v_free| ≥ |v_850| ≥ |v_surface|`。定常解在固定 ∇p 下风速随 r 单调减（f→0 时 `|v| = |∇p|/(ρr)`），两组数对不上：取 0.3 的那层会比取 0.5 的那层快。**按物理改默认**：`1 : 0.5 : 0.3`（地面 : 低空 : 自由），并在 `WindSolver` 构造期断言单调 + 单测钉住。旋钮命名随之改成 `FrictionLowFactor` / `FrictionFreeFactor`，不再叫 "Moisture"。

**D8 · E 项是几何量，不用卷积求。**
"东侧 12–24° 有陆的洋面"是一个**经度方向的存在性判定**，不是扩散问题。用跳数/卷积去逼近，会在高纬（经线收敛）和日界线处失真。做法：1–2° 经纬栅格上标陆，逐海格向西扫 12–24°（含环绕）得指示场，采样到粗层，再做 `G_300` 平滑。归 `Prepare`，只算一次。

**D9 · 名字不承诺数据结构没有的东西。**
三套风不是三层大气，是**同一个诊断平衡的三个摩擦闭合**；"850 hPa"承诺了一个不存在的气压面（青藏高原上 850 hPa 在地下）。文案用"地面 / 低空 / 自由"，枚举用 `Surface/Low/Free`。等真做了垂直层再叫 850。

## 十一、验收：架构级不变量

这些不是物理数值（那些在方案 §五），是**结构必须成立**的东西：

1. **同源**：三套风由同一次 `SolveAll` 产出；扰动 p 的任一格，三套风在同一处同时变化（可做成单测）。
2. **派生一致**：`SpeedAt` 与矢量长度逐格相等；没有任何地方存第二份逐月风速。
3. **回退位等价**：`WindPressureDriven=false` 与改动前逐格 ≤1e-4。
4. **因果方向**：p 的符号反转 → 风反转；不允许"风反转但 p 没动"的路径存在（三套风没有第二个梯度）。
5. **事实对齐**：`WorldFacts` 构造即校验 p/风/月的长度；缺段抛。
6. **预算**：气压增量 < 0.5 s；气候阶段 ≤ 现状 × 1.5；内存峰值有记录。
7. **无纬度环**：p 与风沿经度扫描，0°/±30°/±60° 不进台阶前八（沿用方案 §五.5）。
8. **可见性**：回退开关两种状态下气压图都可看；三套风都能在坞里取到。

## 十三、子课题（识别，不在本文展开）

- **E 指示场的几何定义**：经度环绕、高纬经线收敛、12–24° 用角距还是大圆距离。D8 给了做法，但阈值与纬度带仍需标定。
- **两个 ITCZ 的统一**：降水（太阳赤纬）与气压（热赤道）何时合并成一个事实？合并会动降水，需单独一轮。
- **垂直结构**：`r` 偷带进来的"高度"只是三个标量。真要 850/500 的垂直反向，必须有层——那是另一次架构。
- **`p_z` 13 节点表的来源**：现在只能靠参考模型读数反推；换倾角/辐照的行星是否需要重新生成节点，未定。
- **洋流对风量级的敏感性**：风是 0–1 代理量，洋流强度直接吃它；三套风里自由风最快，可能把 `OceanStrengthGain` 顶到饱和。Step 2 要先出这张敏感性表，再决定是否重标。

## 十四、实施记录（2026-10-24）

### Step 0 · 气压事实

**新增**：`CoarseLayer`、`CoarseKernel`、`MonotoneCubic`、`LatitudeBands`、`PressureFieldModel`、`PressureField`、`PressureMode`；
`MonthlyClimate`（两段式月循环 + 年均偏置）、`ClimatePipeline`（粗层装配 + 气压事实）、`WorldFacts`（气压段）、
`ClimateSpec` + 两份 JSON、`MapDock.tscn`（第 9 个模式按钮）、3 个测试。

**res4 实测**（288,122 格；`--world 4`）：

| 项 | 读数 |
|---|---|
| 1 月陆地最高压 | 1028.6 hPa @27°N/−78°，离海 49 跳（锚 1029–1032，−0.4 ✓） |
| 7 月陆地最低压 | 974.9 hPa @59°N/−145°，离海 31 跳（锚 1001–1008，−26 ✗） |
| 20–60°N 年均 陆−海 | +1.3 hPa（年均偏置已扣掉） |
| Δp 符号反转 | 73,459 / 73,511 陆格（\|Δp\|>2 hPa） |
| 气压增量 | 粗层 42 ms + `Create` 95 ms + 12 个月 178 ms ≈ **0.3 s**（< 0.5 s） |

**口径修正 1（设计改动）**：**Δc 不再用热赤道**。实测热赤道（海温口径）1 月到 −27.5°、7 月到 +22.5°，
整条 p_z 平移 25° ⇒ 副高跑到赤道、中纬全变成东风（实测 30–50°N 平均纬向风 −0.3）。
改为 `Δc = PressureBeltShiftFactor × 太阳赤纬`（默认 0.3 → ±7°，与参考模型的"6° 级"一致）。
热赤道的病根是温度场：湿冷却把赤道压低、大陆放大把副热带抬高，季节极值被推到 ±25° 以外，撑不住这个全局量。

**偏差 2（温度模型的缺陷被气压场暴露）**：7 月 58–59°N 的大陆**月温高达 60 °C**（冒烟打印的低压中心温度）。
`ContinentalResponse × rad` 把高纬大陆的夏季增幅放大到 `1 + 3.5·c·rad ≈ 3.6`，热力异常 −20 hPa 级，
低压因此又深又偏北（974.9 @59°N）。修它要动温度/降水全链（另一次改动），Step 4 再决定；
在此之前，7 月锚点不可能达成——这不是气压式能修的。

**另**：`PressureThermalGain` 由参考模型的 1.7 改为 **1.2**（两季异常实测对称，α 只能同时缩放冬夏）。

### Step 1 · 摩擦解（`WindPressureDriven`，默认关）

**新增**：`TangentField`（梯度唯一实现；`DiagnosticWindModel` 改用它，逐位不变）、
`WindSolver`（摩擦定常解 + 物理量纲换算）、`ClimateSpec` 4 个旋钮
（`WindPressureDriven=false` / `FrictionSurface=4e-5` / `FrictionLandFactor=2` / `WindSpeedRefMs=12`）、
`MonthlyClimate` 分支、4 个测试。

**验证**：

- 赤道 `f=0` 无奇点、顺梯度直吹；偏转角随 r 单调（单测）。
- 纯 p_z（无海陆）20° 东风 / 40° 西风（单测）。
- **回退逐位等价**：`WindPressureDriven=false` 的 res4 年合成风指纹 `292668156.4359729` 与改动前完全一致。
- 开气压驱动后 res4：10–20° 东风、40–50° 西风；东岸冬夏反转 ≥120° 的格 **1374/3182（43%）**，
  旧风 898/3182（28%）；平均风速 0.26（旧 0.08）。

### Step 3 · 季风 Δp 口径

**新增**：`MonsoonIndex`（纯函数：同纬海洋均压 + 冬夏极值 + 符号门控）、`MonsoonStrengthScale=30 hPa`（旋钮）、
2 个测试；删掉 `_monsoonPeak/_monsoonTrough` 记账（只服务旧口径）。

**口径**：`Δp_i(m) = p_i(m) − 同纬海洋平均 p(m)`；强度 = `clamp((max Δp − min Δp)/scale, 0, 1)`，

**res4 读数**：陆格 `Δp` 反号且强度 > 0.2 的有 **71,702 / 101,783（70%）**，峰值 1.0；海格恒 0；零倾角恒 0（测试钉住）。

### 后续修正 · 风场环状条纹（2026-10-24，实机截图暴露）

**症状**：风场图出现沿纬向/海岸的长条环带，粗层格边界处有锯齿状亮带；气压图本身看起来是平滑的。

**测量**（res4，逐边 `|Δp|`，按"是否跨 res2 父格"分组）：

| | 跨父格边 | 父格内边 | 比值 |
|---|---:|---:|---:|
| 修正前 | 0.357 hPa | 0.174 hPa | 2.05× |
| 修正后 | 0.174 hPa | 0.181 hPa | 0.96× |

纬度差对照（`|Δlat|`）：跨父格 0.2570° vs 父格内 0.2570° —— 两组边的几何朝向没有偏差，
所以 2× 是真实的值跳变，不是"跨边界边更偏南北"的统计假象。

**两个根因**（都在"粗层 → 细层"重建）：

1. **副高不对称项仍是最近父格赋值**：`A·B(φ)·G_300[E]` 的值直接从父格取，E 的等值线在 res2 边界上
   变成 0.2 hPa 级台阶；`∇p` 把台阶放大成风带（用户截图里的长条环带）。
2. **热力异常也是最近父格赋值 + 5° 分桶均值是阶梯**：同样在父格边界和 5° 纬度带留下跳变。

**修正**：

- `BuildUpsampler`：紧支撑距离加权重建（候选 = 父格 3 环邻域，核 `(1−(d/R)²)²`，R = 1.35×粗层格距）。
  权重只看距离、在 R 处值与导数都为 0 ⇒ 候选集切换时插值面连续（Shepard 1/d 与"父格+一邻域高斯"
  都会在父格边界留下梯度堆积或值跳变，已弃用）。
- 纬向带均值：两遍 `[1,2,1]/4` 平滑 + 按纬度线性插值（不再用分桶常数）。
- 不对称项：用同一插值器重建，`B(φ)` 取细层纬度。
- 恒等层（`coarse.Count == 细层格数`，合成网格 / res2）直接原值映射，不做重建平滑。

**验证**：跨父格/父格内 `|Δp|` 比 2.05 → **0.96**；风带纬向平均的功率谱主峰在 120° / 24° / 30° / 60°
（没有 5° 或 1.7° 的峰）；res4 读数基本不变：1 月高压 1028.4、7 月低压 975.0 hPa、降水 1040 mm/yr、
季风陆格 71,791、河网 7040/294，23 个测试全绿。

**诊断入口**：`--world N --csv` 的 CSV 末尾新增 `wsurf,p_jan,p_jul` 三列，方便把风/气压场
直接落到经纬栅格上复核（本次修正就是靠它定位的）。
