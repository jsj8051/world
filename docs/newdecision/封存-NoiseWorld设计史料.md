## 1. 板块划分的八次迭代史

B 线的 `NoisePlates` 是"在 H3 球面网格上划分板块"这一问题的**完整求解史**。
每一步的失败都指向下一步的改进方向，这条链本身就是最有价值的部分。

| 次序 | 方法 | **失败表现** | 失败原因 |
|---|---|---|---|
| 一修 | 前沿随机填充（细格直接生长） | 板界太圆 | 各向同性 ⇒ 无方向性构造感 |
| 二修 | 噪声偏置生长（顺噪声脊蛇形） | 超级板包圈 | 噪声脊是全局的 ⇒ 必然形成单一巨构 |
| 三修 | 加权 Dijkstra | 大圆弧 | 全场单一噪声 ⇒ 最短路必是大圆弧 |
| 四修 | 每板噪声调价（让折扣被"挑着走"平均掉） | 还是圆弧 | 平均化等于抹平差异 |
| 五修 | 直接距离 + 每板加性噪声（扭曲 Voronoi） | 圆斑 + 两个巨板 | 加性噪声的基波长 > 板块周长 ⇒ 扭曲不足 |
| 六修 | 波长 2000×4 倍频 + 尺寸压缩 | 碎弯出来了，仍有解析斑块气质 | 扭曲是各向同性的 ⇒ 仍是解析味 |
| **七修** | **撒 1000 点 → 粗 Voronoi 层 → 选 n 起源 → 粗图随机吞并** | **成功** | 吞并是**过程**，天然产生非解析边界 |
| **八修** | ① 面积拟合 ② 大陆聚簇 | **成功** | 见下两节 |

**七修的关键突破**：从"给每格打分"转向"**模拟生长过程**"。
板块边界是竞争的结果，不是距离函数��零点 ⇒ 形状必然非解析。

**八修的两点补充**：
- ① 面积拟合（份额贴合目标层级，见 §2）
- ② 大陆聚簇（1–2 个陆簇焦点，双簇强制角距 >60°）⇒ 大陆聚成地球式的
  一两个超级陆块 + 广阔大洋，而非均匀散布

> **为什么这条链值得封存**：它证明了"**形态的真实性来自过程的真实性**"。
> 七修之前每一步都在"给规则找更好的函数形式"，七修之后改成"**让正确的过程自己长出正确的形态**"。
> 这个思维范式转移在别处也成立。

## 2. 面积拟合迭代（platec 式权重校准）

> 原实现：`NoisePlates.Generate` 内层循环，`AreaFitIterations = 5`

**问题**："速率随机 ⇒ 份额随机"。随机给每板一个生长速率，吞并完的**面积份额**完全不可控。

**解法**：把"速率"与"份额"解耦——速率只是**迭代变量**，份额是**目标**。

```
① 目标份额取自层级分布：targetShare[p] = 0.2 + rng.NextDouble()   （归一化后）
   ⇒ 巨板 ≈ 6× 小板，地球式层级
② 迭代 5 次：
     plateOfCoarse = GrowCoarse(...)                // 按当前速率生长一次
     actual[p] = coarseCounts[p] / C                // 量出实际份额
     rates[p] *= (targetShare[p] / actual[p])^0.5    // 平方根修正
   ⇒ 收敛快且不过冲（指数 0.5 = 阻尼）
```

**关键点**：
- 平方根阻尼（`(t/a)^0.5`）而非线性 —— 线性会过冲振荡
- **饿死板提速**：`actual < 1e-6` 的板 `rate *= 1.5`（防止边缘板永远抢不到格）
- 速率钳制在 `[0.05, 1]`

> **可迁移价值**：**"随机速率导致随机结果"是生成式系统的通病**。
> 任何"随机分配 + 期望份额"的需求（资源点、聚簇大小、势力范围）都适用这个迭代校准。

## 3. 分水岭检测护栏（HasFineBottleneck）

> 原实现：`NoisePlates.HasFineBottleneck`，静态方法，纯图论

**要检测的病态**：某个板块被一条窄颈切成**两个大流域**（沙漏形）。
这种形状在视觉上极刺眼（像被刀切过），但**份额护栏完全检测不到**——份额可能完全正常。

**旧方案的盲区**：早期用"拔掉一格看是否分裂"的检测，对**2–4 格宽**的走廊有盲区。

**现行方案（三步BFS）**：
```
① 边界距离BFS：边界格 = 有异板邻居的格；dist=0 为源，算到板边界距离
② 深核组件：dist >= 2 的格按连通分量标记；comp >= 2 ⇒ 多核流域
③ 流域归属：全板格归入最近深核（多源 BFS，同距离先到先得）
   若 >= 2 个流域的规模都 >= max(2格, 板格数 × 0.15) ⇒ 判定为沙漏/窄颈
```

**为什么用"深核"而不是直接找任意割点**：深核连通分量天然对 peninsula/海湾免疫
（半岛只有一个深核），而沙漏必然有两个。

**确定性保证**：多源 BFS 的归属与处理序无关（同距离时先到先得，而序固定）。

> **可迁移价值**："**份额正常 ≠ 形状健康**"。任何迭代生成的分区算法都需要
> 独立的**形状质量护栏**，不能只有面积/份额护栏。

## 4. 地球实测拟合数据（唯一带数据源标注的常量表）

> 原实现：`NoiseTerrain` 中的4 个`static readonly float[]`

这是全仓库**唯一标注了数据来源与采样规模**的常量表。

### 4.1 海洋深度剖面

```csharp
OceanDepthLutKm = { 0, 100, 200, 300, 450, 650, 900, 1200, 1600, 2100, 2600, 3200, 4000 }
OceanDepthLutM  = { -60, -250, -600, -1200, -1900, -2500, -3000, -3500, -3800, -4050, -4250, -4300, -4300 }
```

**数据源**：OpenTopodata / ETOPO1 1° 全球采样（**64800 点，NOAA 公有领域**）
+ Natural Earth 110m 海岸线离岸距离（BFS 跳数 × 111km）

**实测结论**：
- 岸边均值 −523m → −3116m（555km 处）→ 渐近 −4300m（远洋均值）
- 浅水（−200m 内）仅占洋面 **10.2%**
- 近岸 2 跳由浅水环钳制（≥ −80m）

### 4.2 陆地高程分布（hypsometry）

```csharp
LandHypsoRank = { 0, .0833, .1667, .25, .3333, .4167, .5, .5833, .6667, .75, .8333, .9167, 1 }
LandHypsoM    = { 1, 56, 122, 201, 303, 418, 582, 855, 1257, 1887, 2593, 3052, 6094 }
```

**实测结论**：
- 25% 陆地 < 200m
- 46.5% 陆地 < 500m
- 长尾到 6094m（**珠峰量级**）

### 4.3 两条关键设计手法

**① 秩 = 面积分位**
"噪声在陆域内的秩"直接当"面积分位"用⇒ 噪声的百分位自动获得正确的面积语义。
这是一个零成本、零额外数据的**语义绑定**。

**② 海平面 = 分位切点，不是独立旋钮**
海平面 = L0 噪声的切分位位置，由"目标陆地占比"**直接**控制。
文档明确记录了为什么不设独立 `SeaLevelM` 旋钮：

> "同一海平面的两种口径，双旋钮会互相打架。"

**这是参数设计的典范**：**当两个参数在语义上冗余时，砍掉一个，而不是让用户自己权衡。**

## 5. Fritsch–Carlson 单调样条与反解保分布

### 5.1 单调三次切线（Fritsch–Carlson）

```csharp
// 结点严格递增 ⇒ slope 恒正 ⇒ 无除零
tan[0] = slope[0]; tan[n] = slope[n-1];
for k in 1..n-1:
    if (slope[k-1] * slope[k] <= 0) { tan[k] = 0; continue; }   // 符号变号 → 置零保单调
    hw1 = 2*dx[k] + dx[k-1]
    hw2 = dx[k] + 2*dx[k-1]
    tan[k] = (hw1 + hw2) / (hw1/slope[k-1] + hw2/slope[k])       // 调和加权平均
```

**为什么是调和平均**：加权算术平均可能使切线超过相邻段的斜率 ⇒ 插值曲线回折（overshoot）。
调和平均天然被两端斜率夹住，**不需要额外钳制**。

**单调样条的真正价值在这里**：地球高程分布要求"海拔随高度秩单调上升"。
普通三次样条会在数据点之间过冲，产生**负海拔的陆地**或**高于珠峰的平原**。

### 5.2 `SplineInverse`：反解保分布（最值得保留的单件）

```csharp
// 目标海拔(米) → 归一化h ∈[-1,1]
for k in 0..4:
    if (elevM <= y[k+1] || k == 4):
        return SplineX[k] + (SplineX[k+1]-SplineX[k]) * clamp((elevM - y[k])/(y[k+1]-y[k]), 0, 1)
```

**用法**：
```
陆格：目标米数（来自 hypsometry LUT） → SplineInverse → 归一化 h
洋格：目标米数（来自深度剖面 LUT）   → SplineInverse → 归一化 h
最后 MapQuantileToElevation 再用同一份结点正算 → 真实米域海拔
```

**为什么这个设计精妙**：
1. **结点高度可调**（面板滑块）⇒ 造型可玩
2. **地球分布不变**（LUT 喂的是米数，经反解再正解）⇒ 改参数不破坏真实感
3. **正反解共用同一份结点**（`ComputeKnots` 单源）⇒ 不可能失配

> **这解决了"可调性vs 真实性"的经典矛盾**：不是二选一，而是**把"分布"锚在米域、
> 把"可调"锚在结点域**，用反解搭桥。
>
> 封存要点：这个思路（**把不变量锚在物理域、把可变量锚在参数域、用反解搭桥**）
> 比任何具体的 LUT 值都更值得复用。

## 6. PropagateMax 带权多源扩散（收敛性论证）

```csharp
static float[] PropagateMax(float[] source, int[][] neighbors, int width, float decayPerHop)
{
    var carry = (float[])source.Clone();      // carry 初值 = 源强度
    while (queue.Count > 0) {
        int i = queue.Dequeue();
        if (carry[i] <= 0f || hop[i] >= width) continue;      // 宽度上限
        foreach (int j in neighbors[i]) {
            float cand = carry[i] * decayPerHop;               // 每跳衰减
            if (cand > carry[j]) { carry[j] = cand; hop[j] = hop[i]+1; queue.En(j); }
        }
    }
    return carry;
}
```

### 收敛性论证（原注释，值得完整保留）

> "max 松弛的收敛点与处理序无关 ⇒ **确定性**；
> carry 逐跳严格缩减 ⇒ **必然终止**。"

**为什么这个论证重要**：多源扩散的**顺序敏感性**是这类算法的经典陷阱。
BFS 距离场天然顺序无关（每格只算一次），但**带权max 扩散**会反复松弛同一张格，
若源强度与遍历序耦合，同一 seed 就会给出不同结果。

这里的**顺序无关性来自 max 算子的幂等 + 逐跳衰减**：
- `max` 满足交换律与幂等 ⇒ 多次松弛结果一致
- `decay < 1` ⇒ 路径越长值越小 ⇒ 只有"更短的更强路径"能赢 ⇒ `hop[]` 单调收敛

### 与 BFS 的能力边界

| | BFS 距离场（`FinalSpatialIndex` 用的） | PropagateMax |
|---|---|---|
| 语义 | "最近源有多远" | "源强度向外衰减多少" |
| 输出 | 整数跳数 | 浮点强度 |
| 多源聚合 | min | max |
| 能否加权 | 否 | 是 |
| 能否表示"影响半径" | 能（等值线） | 能（衰减场） |

**结论**：新线只有 BFS，**无法表达**带权多源扩散。
若将来出现"构造强度向内陆衰减""迎风坡影响范围"这类**非距离场**语义，需要它。

> **当前无消费者 ⇒ 决策 08 决定暂缓迁入。** 此处封存算法本身 +收敛性论证。

## 7. 确定性纪律的偏移常量表

B 线全部随机消费都走 `DeterministicRandom` 的**固定偏移**：

| 用途 | 偏移 | 位置 |
|---|---|---|
| 撒点（粗 Voronoi 层） | `seed + 5333` | `NoisePlates` |
| 重采样（护栏触发） | `seed + 31 * attempt` | `NoisePlates` |
| 陆/洋身份 | `seed + 999` | `NoisePlates` |
| 板块运动向量 | `seed + 7919` | `NoisePlates` |
| 温度噪声 | `seed + 101` | `NoiseClimate` |
| 降水噪声 | `seed + 102` | `NoiseClimate` |
| 地形层种子 | `rnd.Next()` **按固定次序** | `NoiseTerrain` |

### 最关键的一条：层种子派生与开关状态无关

```
L0 → W1 → W2 → W3 → 山带 → 细节     // 固定次序，无论哪层开着
```

> "开关状态不改变次序 ⇒ **开关不挪别的层的场**。"

**为什么这条纪律值���钱**：交互式调参时最恼人的失败是"我只想关掉细节层，
结果大陆场也变了"。把派生的**消费次序**与**开关状态**解耦，一次性消除这类困惑。

**新线已继承并成文**：`worldgen/SeedDerivation.cs` 集中 13 个标签，`seed ^ tag`。
但"消费次序与开关无关"这一条在 B 线是隐含的（写在注释里），值得在新线保持显式。

## 8. 分层缓存的快照判据

四个快照 struct + 逐字段对比，判据是"**上游真变更才重算**"：

```csharp
struct RawSnap    { Seed, ContOctaves, WarpOctaves, ContWl, WarpWl, WarpAmp, ... }
struct DomainSnap { SeedUsed, PlateCount, LandTarget }
struct BeltSnap   { SeedUsed, PlateCount, ConvThreshold, BeltWidth }
struct ElevSnap   { W0, W1, W2, Sharp, DetailAmpM, CoastWobble, BeltWeight, Spline*... }
```

**为什么值得记**：调参面板每次拖动滑块都会路过全链重算。
没有这套缓存，交互体验是"每帧10秒"。

**设计要点**：
1. **诚实直写**——逐字段列出，不试图用脏标记推断"哪个参数变了"
2. 参数量少（每个快照 4–10 个字段）⇒ 逐字段比较的成本可忽略
3. 段间依赖显式：`elevDirty = _dirty || rawDirty || domainDirty || beltDirty || !_elevSnap.Equals(...)`

> **注**：新线是**一次性 `Regenerate()` 全链重建**，无交互式微调 ⇒ 当前无消费者。
> 但若将来加实时调参面板，这套模式可直接复用。

## 9. 反射式调参面板机制

```csharp
[AttributeUsage(AttributeTargets.Field)]
public sealed class NoiseParamAttribute : Attribute {
    public string Group { get; }// 面板分组标题
    public string Label { get; }     // 行标签
    public float Min, Max, Step;     // 滑块范围
    public bool SkipPanel { get; }    // 种子等离散参数不入面板（走按钮）
}
```

**三条设计约定**：
1. **字段声明顺序 = 面板行顺序**（分组切换处插空行）
2. **导出 JSON = 同一结构** ⇒ 不存在"面板值与数据不一致"
3. `int` 字段自动取整；`skipPanel` 参数仍进 JSON

> 核心判断（原文）：
> > "全部参数收进本类；调参面板由 `[NoiseParam]` 特性**反射自动生成**
> > （**手写数十个控件必错**）。"

**封存的是判断，不是代码**：新架构工作方式已变（改 `const` 跑测试，而非拖滑块看球），
**面板机制当前无消费者**。但"**参数声明即面板、声明即存档**"这个约定在
将来任何"参数超过 20个且需要交互调节"的场景都成立。

## 10. 不该继承的东西（反例清单）

封存必须同时记录**失败**，否则下一个人会重走一遍。

| 反例 | 为什么不该继承 |
|---|---|
| **板块身份定海陆**（陆板全陆、洋板全洋） | 离散身份 ⇒ **无法分出半岛/海湾**。新架构走连续场 + 分位校准路线，这是**范式升级**不是等价替换 |
| **陆地占比 = 陆板数占比** | 面积**跟随吞并结果**，用户拖"目标占比"滑块得不到想要的面积。双事实源风险的源头 |
| **域内秩 + 海拔符号硬钳 ±1m** | 用**浮点符号**承载**离散身份**。虽有不变量测试，但语义上是用数值通道传枚举 |
| **L0–L5 命名层级** | 层号隐含"执行顺序"，实际数据流是**DAG**（域扭曲影响三路噪声、碰撞带独立计算后合成）。层级名误导 |
| **增量叠加语义**（`elev += shape * belt * MountainM`） | 新架构 `HeightComposer` 已改为**绝对高度 lerp**：`lerp(当前, TargetM, Influence)`。增量语义无法表达"覆盖"与"保底" |
| **`NoiseMapMode.CreateAll(terrain, plates, climate)`** | 签名绑死三个旧子系统。新线已改为 `CreateAll(planet)` —— **持引用现取数据**，避免"拿到旧场快照" |
