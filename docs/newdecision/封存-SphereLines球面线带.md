## 0 ★封存理由（先读这段，防止误解）

| 问 | 答 |
|---|---|
| **当前需求还在吗？** | ❌ **已消失**。地质区域现用**色块相邻**表达（`RegionTypeMode` 逐格七色），不画边界线；`WorldGenMapModes` 四个模式全是逐格填色|
| **它被替代了吗？** | ➖ 严格说**不是被替代，是需求本身不存在**。唯一在用的球面线带是 `RiverLineOverlay`（河流），走**径向抬升**路线，与本类无关 |
| **要不要接回生产？** | ❌ **不要**。若将来出现"球面线带"需求（如区域边界描边），**应重新设计与当前渲染规范（见 §4）一致的方案**，而不是复活这套 |
| **那为什么封存？** | ★**它解释了后来 `NDC depth bias` / `UV2.y` 规范是从哪来的** —— 它是该规范的**前身实践**（2026-09-10 两遍深度预写 → 2026-10-04 收敛为 `UV2.y`） |
| **它解决的问题现在被解决了吗？** | ⚠️ **没有**。"重叠线带每像素只混色一次"这个问题**现役系统仍未解决**（抬升路线只是让干流盖住支流末端）。本类的方法是**现成参考**，不是现成方案 |

★**一句话**：留它的理由是**解释规范演进 + 提供问题参考**，
**不是**"它是个好工具，等着被用"。

## 2 ★三层机制（封存的真正内容）

### 2.1 第一层· 两遍深度预写 → 重叠线带每像素只混色一次

**要解决的问题**（原文注释）：

> 线带与端帽在角点处**必然几何重叠**、弦高各不相同，
> 单遍"首片元入深度"**挡不住弦高恰更近的后到片元**（实测端帽仍双混变深）。

**解法**：拆成两遍渲染。

| 遍 | shader | `render_mode` | 作用 |
|---|---|---|---|
| **第一遍** | `boundary_line_depth` | `depth_draw_always` | 以 `ALPHA=0` **隐形光栅化但写深度**。对格面通过的片元按"更近者覆盖"沉淀该像素上线几何的**最近深度**；被星球挡住的背面片元**不写** |
| **第二遍** | `boundary_line_color` | `depth_draw_never` | 作第一遍的 `NextPass`。在沉淀的最近深度上做常规深度测试（**反向 Z 下"更近或等深"通过**）⇒ 同像素上**只有深度恰为最近层的那组片元通过**，更远的重叠层全部落选 |

**效果**：**每像素恰好混合一次线色** ⇒ 半透明线色**也绝不叠加变深**，
端帽 / 三板交汇处处与线身同色度。

**两个必要约束**：
1. ★**遍顺序必须由 `render_priority` 钉住** —— 透明队列按深度排序会乱（原文注明"实测必钉"）。
2. ★**不能靠 stencil** —— 原文明确记："**stencil 两遍制已试已弃**：模板只能挡跨物体重复，
   **挡不住同网格自重叠**"。

### 2.2 第二层 · miter 补偿 → 线宽在接头处保持稳定

正 m 边形下"角点的径向"恰好是**内角平分线** ⇒ 标准 miter 接头，六个转角不断、不豁口。

**但沿平分线偏移 h 时，环带垂直于边的净宽度 = h·cos(π/m)**
（两端点垂距相同 ⇒ 外边界与边平行，整条边等宽，转角**不会**变细）
⇒ 必须**预先补 `1/cos(π/m)`**，才能使实测宽度等于 `halfWidth`。

> ★与 `Render/CellQuery.AddCellRing` 的 miter 补偿**同源**（那里也补了 `1/cos(π/m)`）——
> 说明这是球面线带/环带的**通用几何事实**，不是本类独有技巧。

### 2.3 第三层 · 端帽坐标去重 → 避免端点重复覆盖

端帽 = 角点处角半径 α 的**扇形圆盘**（三点扇心 + 首尾重复接缝环），用来填线带在转角处的**楔形缺口**（圆角衔接）。

**去重规则**（`SphereLines.cs:77`）：

```csharp
var capped = new HashSet<Vector3>();   // 每个角点坐标只补一次帽
...
if (!capped.Add(p)) return;             // 共享角点只补一次
```

★**为什么必须去重**：多条线串共享同一个角点时，若各补一次帽，
该角点会被画 N 个圆盘 ⇒ 叠加变深（与 §2.1 要解决的问题同源）。

## 3 ★诚实记录：它也有 radial lift（与规范冲突）

`SetLines` 有 `surfaceOffset` 参数，默认 `halfWidth * 0.1f`：

> `surfaceOffset = 线相对球面的悬浮高度（防与宿面 z-fighting，默认半宽的 10%
> ——只须压过线/宿面两套三角的弦高差与深度量化）`

⚠️ **这与现行规范冲突**。`architecture.md §6` 明确：

> **地图表现层不得通过 world-space radial lift 实现图层排序。**
> ⚠️ 严禁 `radius * 1.0005f` 这类径向抬升：掠射角下会换算成横向屏幕位移
> （实测旧写法在 1.02R 最近视距的屏幕边缘位移 14.6px ≈ 10% 格宽）

⇒ ★**两层含义必须分开看**：
- 本类的**分层**（谁画在谁上面）靠**两遍深度预写**解决，**不用抬升**；
- 它的 `surfaceOffset` 只是**防同网格 z-fighting 的微量抬升**（10% 半宽），
  **不是分层手段** —— 与"用抬升做分层"是两回事。

★但**这个区别很细**，也正说明为什么后来规范要**一刀切禁止 radial lift**：
"微量防 z-fighting"与"分层抬升"在代码上都是 `rTop = radius + lift`，
**难以区分 ⇒ 规范干脆全禁，改用 NDC depth bias / stencil / overlay pass**。

## 4 ★与现行渲染规范的血缘关系（封存的最重要一条）

| |本类（2026-09-10） | 现行规范（2026-10-04 起） |
|---|---|---|
| 分层手段 | **两遍深度预写 + 遍顺序钉死** | **NDC depth bias（`UV2.y`）** |
| 世界位移 | 微量 `surfaceOffset` 防 z-fighting | **零位移**（几何必须贴真实表面） |
| 厚度表达 | 世界空间 `halfWidth` | **屏幕空间恒 px**（`UV2.x`） |
| 用在| 板块边界描边（已随`new_HexWorld` 删除） | 河面（`river_surface.gdshader`）+ 选中环带（`CellQuery`） |

`shaders/river_surface.gdshader:18` 原文：

> ★**UV2.y = 深度偏移（NDC）**——代替物理抬升，见下方"为什么不用 lift"

⇒ ★★**理解这条血缘，才能理解现行规范为什么那样写**：
规范不是凭空发明的，它是把"两遍预写 + render_priority"这套**更重**的做法
**收敛**为"一个 uniform + 一行 clip-space偏移"。

## 5 方案固有语义（非本类缺陷，多实例时须知晓）

> · **实例之间不混色** —— 深度预写按实例计，屏幕重叠时**只有更近实例的线可见**；
>   需要共存的线（如板块边界 + 标注线都要半透明可见）**应塞进同一次 `SetLines`**。
> · **隐形深度会挡住其后渲染、被线盖住像素上的透明几何**（不透明几何先渲染，不受影响）。

## 6 将来若需要"球面线带"，该怎么起步

⚠️ **不要复活本类**。按现行规范重新设计的起点：

1. **几何贴真实表面**（顶点 = 方向 × R，零位移）
2. **分层用 `UV2.y` NDC depth bias**（不用 `surfaceOffset`）
3. **厚度用 `UV2.x` 屏幕空间恒 px**（不用世界空间 `halfWidth`）
4. **重叠线带一次混色问题** ⇒ 参照 §2.1 的思路（但用现代方案：
   stencil 已试已弃；可考虑先做 chain 化+ 边去重，
   参照 `RiverLineOverlay.BuildChains` 的做法）
5. **接头与端帽** ⇒ §2.2 / §2.3 的几何结论仍适用（球面通用事实）
