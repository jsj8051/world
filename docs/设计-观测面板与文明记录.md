# 设计：观测面板与文明记录

> 2026-08-24 · 用户拍板：先做可读性层——**⑫ 观测面板 → ⑪ 文明记录**（战争/主体/关系层搁置）
> 架构红线：**高度可扩展、方便修改、零坏味道**——每一处设计决策都写"防什么坏味道 + 将来怎么扩"。

---

## 〇、定位：为什么这两层可以先行

文明层审计（07/08/09 缺、10 悬空）结论：观测面板与文明记录是**横切的可读性层**——
它们只读现有 1-6 层的涌现结果，**不依赖 7-9 层任何机制**，所以现在做不产生悬空依赖。
反过来它们为将来 7-9 层落地后立刻提供"可看见的出口"（关系/外交字段就位 → 快照加字段，面板自动出现）。

**铁律（本设计的一切约束）**：
1. **模拟层永不依赖 UI**：CivSim 不知道面板存在；新增机制不改任何 UI 代码。
2. **UI 永不直达模拟内部**：面板只读投影 DTO（Snapshot），不碰实体字段——模拟重构时 UI 零改动。
3. **事件是旁路记录**：只写不读、不参与任何模拟分支——事件系统想关就关（零成本），开了也不改变模拟结果一比特。
4. **确定性不受影响**：事件不产生 Rng、不改变遍历序；同一 seed 演化结果与无事件系统时逐比特一致。

## 一、架构总览（四层三明治）

```
┌─────────────────────────────────────────────┐
│ 呈现层 MapViewer.UI（面板卡片/事件流视图）      │  ← 改 UI 只动这层
├─────────────────────────────────────────────┤
│ 投影层 CivSnapshot（只读 DTO，纯函数组装）      │  ← 加字段只动这层 + 模拟
├─────────────────────────────────────────────┤
│ 模拟层 CivSim（Context/实体/机制，无 UI 依赖）  │  ← 加机制只动这层
├─────────────────────────────────────────────┤
│ 记录层 CivEvents（旁路：模型关键时刻 append）   │  ← 新事件类型注册一行，机制零侵入
└─────────────────────────────────────────────┘
```

- **投影层**：`CivOverlay.Observe(CivSimContext) → CivSnapshot`——纯函数、可单测、可缓存。
  面板永远从 Snapshot 取数；Snapshot 组装读哪些字段全在**一个文件**里（好查好改）。
- **记录层**：`CivEventRecord` 结构化记录 + `EventTypes` 注册表；发事件 = 模型里一行 `ctx.Events.Add(...)`（纯附加，不改逻辑）。

## 二、文明记录（事件旁路系统）

### 2.1 事件结构（轻量、可压缩、入档体积可控）

```csharp
public readonly struct CivEventRecord
{
    public int Tick;            // 演化 tick
    public short TypeIndex;     // EventTypes 注册表顺序号（入档用数字，不为字符串浪费空间）
    public int SubjectId;       // 主体政体 Id（-1=无）
    public int TargetId;        // 客体政体/聚落 Id（-1=无）
    public float Value;         // 数值（人口/贡赋/胜场等）
}
```

文本展示不进记录、不入档——由 `EventTypes` 注册表的格式化器在展示端还原中文文本
（如 吞并 → "✕殁，土地并入✓"）。记录是数据，文本是派生——改文案不动数据、不 bump 版本。

### 2.2 事件类型注册表（可扩展的关键：加事件≠改 switch）

```csharp
public static class EventTypes
{
    // Register(key, name, formatter) —— 注册表序 = 入档索引（追加式，不删旧序）
    public static readonly EventTypeDef FarmStart;      // 文明纪元：首转农
    public static readonly EventTypeDef StateEmerge;    // 国家涌现（三条件达成）
    public static readonly EventTypeDef StateGone;      // 国家崩溃/消失
    public static readonly EventTypeDef WarDeclared;    // 宣战（A vs B）
    public static readonly EventTypeDef WarAnnex;       // 吞并（国家战争结算）
    public static readonly EventTypeDef WarTribute;     // 朝贡开始
    public static readonly EventTypeDef WarPeace;       // 停战/朝贡终止
    public static readonly EventTypeDef Invention;      // 政体首次发明科技（Subject=政体, Target=科技序）
    public static readonly EventTypeDef TechSpread;     // 科技传入政体（首次获得）
    public static readonly EventTypeDef Split;          // 政体分裂（Subject=母, Target=子）
    public static readonly EventTypeDef PolityDied;     // 政体灭亡
    public static readonly EventTypeDef HabUpscale;     // 聚落升级（camp→settlement→集镇→城市）
}
```

- 加新事件 = `EventTypes` 加一行静态字段 + 模型里加一行 `ctx.Events.Add(...)`——**零 switch、零 if 链**。
- 发事件时刻**全部在领口时刻**（Annex/DeclareWars/StateAssign/Invention… 内部），不带额外遍历——性能开销 ≈ 0。

### 2.3 首批发事件点（领口清单——都是"政体级宏观时刻"，非逐格/逐 tick 微观）

| # | 事件 | 插入点（现有代码） |
|---|---|---|
| 1 | 首转农 FarmStart | CivEngine.Run 终止判断处（FirstFarmTick 置位时） |
| 2 | 国家涌现 / 崩溃 | `StateAssign`（重建时 StateId 变化） |
| 3 | 宣战 / 吞并 / 朝贡 / 停战 | `WarModel`（DeclareWars / Annex / StartTribute / 超时移除） |
| 4 | 发明 / 首次传入 | `InventionModel` / `SpreadModel`（TechKeys 新增且首见即记） |
| 5 | 分裂 | `SplitMigrateModel`（生成新实体时） |
| 6 | 灭亡 | 实体 Dead 置位处（或演化收尾扫描） |
| 7 | 聚落升级 | `HabitationModel`（形态/职能等级变化处） |

> 边界：**不记录**格级冲突/逐 tick 数值（那是洪水，不是历史）；事件 = 历史叙事的最小单位。

### 2.4 存档：EVNT 新段（.cmp）

- 段名 `EVNT`，跟随"一系统一段"惯例（ArchiveChunk 段表，注册 4 字符 magic）。
- 内容：`Count + [Tick, TypeIndex(short), SubjectId, TargetId, Value]` 紧凑数组。
- 段缺失 = 无历史（兜底为空，不阻断读档）——同现有"死场重算/缺段语义"一致。
- 体积估算：600 tick × 数十件大事 ≈ KB 级，完全可控。
- **读档路径**：读档即把 EVNT 段还原到 Context.Events——事件历史跨会话保留（"文明记录"的意义所在）。

> ⚠️ 版本策略：**不 bump .cmp 版本**。段表支持缺段——EVNT 缺失按空处理；
> 但写了 EVNT 的档被旧版本读会……旧版本忽略未知段（段表寻址按 magic），兼容无碍。

### 2.5 确定性/线程/测试

- **线程**：`CivEngine.Run` 后台线程演化——`ctx.Events.Add` 在主模拟循环内（单线程写，无锁）；
  演化完成/读档后主线程读——与现有 onProgress 回调同一纪律。
- **确定性**：事件不读 Rng、不改变遍历，纯 append——T04（读档续跑无分叉）继续成立；
  新增 T-测试：
  - T88：吞并/宣战/发明各产生 1 条正确记录（构造场景直接断言）
  - T89：EVNT 段往返（写档→读档→事件序列逐条相等）
  - T90：事件旁路=纯附加——同 seed 有无事件系统演化结果完全一致（回归红线）

## 三、观测面板

### 3.1 投影 DTO：CivSnapshot（面板的唯一数据源）

```csharp
public sealed class CivSnapshot
{
    public int Tick;                       // 演化终止 tick
    public long TotalPop;                  // 总人口
    public int PolityCount, StateCount, ChiefdomCount;   // 政体计数
    public List<PolityRow> Polities;       // 政体列表（Prestige 降序）
    public List<StateRow> States;          // 国家卡片
    public List<TechRow> Techs;            // 科技卷轴（谁持有）
    // 事件流（文明记录完成后接入）：List<EventRow> Events  ← 追加字段，面板自动多一页
}
public readonly struct PolityRow { Id, 类型阶段(band/tribe/...), 人口 P, 领地格数, 科技数, 声望, 所属国家, 所在聚落, 生产方式 }
public readonly struct StateRow   { Id, 都城聚落, 君主(Prestige 最高成员), 贡赋池, 成员数, 税制, 科技(文字?), 关系(未来) }
public readonly struct TechRow    { Key, 名称, 持有者列表 }
```

- `CivOverlay.Observe(ctx)` 纯函数：**所有字段读取集中在一个文件**——将来加"关系值/战争状态/意图"，
  只改 Observe 一处 + 面板加一行——**UI 代码零改动**。
- 不反射、不序列化实体——显式字段拷贝，类型安全、快照即契约（模拟重构编译器立刻报错，不会静默挂）。

### 3.2 面板形态（UI 组织）

- 挂载点：MapViewer 场景 `UiLayer`（CanvasLayer=100，与进度面板/图层行同层）；
  新场景 `scenes/ui/CivPanel.tscn`（Control 骨架：标题栏/页签/滚动列表/可折叠），场景化优先（项目惯例）。
- 页签（第一版）：**总览 / 政权 / 国家 / 科技**；文明记录完成后加 **事件** 页。
- 主题：复用中世纪羊皮纸（SaveRowStyle 色板 + themes/ui_medieval.tres）；
  5 枚图标（力量/财富/金融/合作/社群）正好做国家卡片条目图标。
- 渲染：SnapBuilder 按 Snapshot 纯渲染（无状态逻辑）；页签切换 = 重建列表，不做逐帧刷新。

### 3.3 数据流（两条路径，都无并发问题）

```
路径A 读档：CivMapArchive.Read(.cmp) → Context → 主线程 Observe() → Snapshot → 面板渲染
路径B 演化完成：CivEngine.Run(onProgress…) 完成回调（主线程）→ Observe() → 面板渲染
```

## 四、可扩展性红线（为什么这设计没有坏味道）

| 设计决策 | 防的坏味道 | 将来怎么扩 |
|---|---|---|
| 模拟层零 UI 引用（单向依赖） | 双向耦合/循环依赖——改面板炸模拟 | 新 UI 组件只读 Snapshot，模拟永不知情 |
| Snapshot 投影集中一处 | 字段散落各处读取、模拟重构静默挂 | 加字段=Observe 一处+面板一行；编译器护航 |
| 事件 = 旁路只写 | 事件系统污染模拟分支（开/关改变结果） | 加事件=注册表一行+领口一行；关掉零成本 |
| 事件类型注册表（索引入档） | switch 地狱——新类型要改 N 处 | 注册表追加式，旧索引不动（入档兼容） |
| 事件文本展示端派生 | 记录/文案耦合——改文案 bump 版本 | 改文案不碰数据不碰存档 |
| EVNT 段缺失兜底为空 | 版本升级爆炸（新段强制旧档失效） | 缺段=无历史，读档永不阻断——同缺段惯例 |
| 面板页签注册（总览/政权/国家/科技/事件） | 单页越堆越长、状态混乱 | 新页签=新卡片模板+注册一行 |

**总结一句话**：模拟只负责事实，投影只负责搬运，UI 只负责呈现，事件只负责说"发生了"——四层各司其职，
任何一层修改都不穿透到其他层。
