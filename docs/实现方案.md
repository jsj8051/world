# Project: Godot Hex Planet Terrain Generator

## 项目定位
基于 Godot 4.7 C# 的六边形星球地形生成系统。核心思路受 Songs of the Eons (SotE) 启发，但将方形网格替换为 Goldberg 多面体（六边形+五边形）网格。

## 整体架构

### 目标管线（分 Phase 实现）

```
Phase 1 🔄 : 六边形星球骨架（进行中）
  Icosahedron → Subdivided Mesh → Goldberg Polyhedron → Godot Mesh

Phase 2 📋 : 海拔生成 + 海陆分离  
  球面噪声采样 → 海拔赋值 → 海洋/陆地判定

Phase 3 📋 : 气候模拟
  粗网格气候模拟 → 插值到细网格
  因子：纬度、哈德莱环流、ITCZ、大陆性、雨影、地中海效应

Phase 4 📋 : 河流模拟 + 侵蚀
  水流累积 → 河流网络 → 地形侵蚀

Phase 5 📋 : 省/区域聚合
  种子填充 + 河流引导 + 海岸生长
```

## Phase 1：六边形星球骨架（进行中）

### 思路概述

Phase 1 的核心目标是构建 Goldberg 多面体星球骨架，而不是直接写渲染代码。这个阶段要把二十面体细分成一个稳定的球面瓦片结构，并生成可用于后续地形和气候阶段的拓扑数据。

### 核心目标

- 生成高分辨率三角形网格，覆盖整个球面。
- 对细分网格进行顶点去重和邻接关系构建。
- 基于去重后的网格构建对偶多边形，每个原始顶点对应一个瓦片。
- 识别并区分 12 个五边形与其余六边形。
- 输出每个瓦片的顶点序列、中心位置、邻居关系。

### 设计原则

- **先数据后渲染**：构建拓扑数据是第一位，渲染仅用于验证和展示。
- **分层拆分**：细分、去重、邻接、对偶、可视化各阶段独立。
- **可验证性**：每一阶段靠拓扑和数量关系验收，不靠肉眼猜测。
- **后续可扩展**：Phase 1 结果要能直接作为海拔、气候、河流、区域等后续系统的输入。

### 实现思路

1. **细分二十面体**
   - 从标准二十面体出发，对每条边均匀细分，得到更密集的三角形网格。
   - 确保细分后网格仍保持球面形状。

2. **去重与邻接**
   - 对细分结果建立唯一顶点集合，消除重复顶点。
   - 构建顶点到三角形的映射关系。
   - 通过共享边确定三角形邻接关系。

3. **构建对偶多边形**
   - 每个原始顶点对应一个对偶面，这个对偶面由其相邻三角形的重心组成。
   - 按极角对相邻三角形重心排序，生成闭合的对偶面顶点序列。
   - 这个过程把原始三角形网格转换成五边形/六边形瓦片拓扑。

4. **瓦片拓扑输出**
   - 为每个对偶面记录中心点、角点列表、邻居瓦片索引。
   - 通过邻居关系保证瓦片之间的拓扑连续性。

5. **渲染准备**
   - 用对偶瓦片数据生成可视化三角形扇形网格。
   - 保持渲染结果与构建出的瓦片拓扑一一对应。

### 验收标准

Phase 1 的成功标准：

- 对偶面数量接近 `10n² + 2`。
- 五边形数量恰好为 12，其余为六边形。
- 六边形邻居数应为 6，五边形邻居数应为 5。
- 对偶多边形在球面上连续无断裂。
- 可视化结果能反映瓦片拓扑结构。

### 关键输出

Phase 1 应当输出：

- 细分三角网格的顶点、索引和邻接信息。
- 去重后的唯一顶点集合。
- 对偶瓦片集合及其拓扑描述。
- 五六边形分类和邻居关系。
- 可渲染化的瓦片网格数据。

### 验证要点

- 细分网格是否按预期生成。
- 去重后顶点数是否满足 Goldberg 公式。
- 对偶面和五六边形分布是否正确。
- 瓦片邻接关系是否符合球面拓扑。
- 渲染结果是否真实反映构建出的对偶结构。

完成后，该阶段将成为后续海拔、气候、河流和区域系统的稳固基础。

### Step 快速验证计划

| 步骤 | 验证方式 |
|------|---------|
| Step 1 (Icosahedron 面内剖分) | 直接用 SurfaceTool 渲染 n=4 看三角网格 |
| Step 2 (SubdividedMesh 去重) | 打印顶点数 = 10n²+2 |
| Step 3 (GoldbergBuilder 对偶) | 12 个五边形 + 其余六边形，邻居数正确 |
| Step 4 (HexPlanetGenerator) | 场景渲染无缺面，五边形红点均匀分布 |
| Step 5 (HexPlanet 节点) | [Tool] 模式下直接调整参数即可预览 |

### 关于绕序（重要）

所有步骤中注意三角形的绕序一致：
- **Icosahedron 输出**的面内三角形需保证逆时针绕序（从球外看）
- **HexPlanetGenerator** 的三角形扇形按 (center → v0 → v1) 顺序，其中 v0→v1 是 corners 的顺序方向，确保绕序朝外
- 实现后如果不确定，参考现有 `IcosahedronSphere.cs` 中的绕序修正方法（叉积检测法线方向）

## Phase 2 设计思路（未实现）

### 海拔生成
- 在球面上采样 3D Perlin/Simplex 噪声
- 多层 FBM（Fractal Brownian Motion）：叠加 4-6 个不同频率的噪声层
- 海拔归一化后设置阈值区分海陆
- 球面噪声采样方式：每个 hex 的 center 单位向量作为采样点，输入 3D 噪声函数

### 数据扩展到 HexTile
```
HexTile 新增字段：
  Elevation: float    // -∞ 到 +∞，0 = 海平面
  IsLand: bool        // elevation > 0
  Moisture: float     // 后续气候模拟
  Biome: BiomeType    // 后续生态模拟
```

## Phase 3 设计思路（未实现）

### 双层网格架构（继承 SotE 思路）
- 气候网格使用低细分层（如 n=8 或 n=16），约 642-2562 个面
- 每个气候单元格存储：温度（1月/7月）、降水（1月/7月）、大陆性、雨影等
- 气候模拟完成后插值到 n=64 的精细网格

### 气候因子（参考 SotE `climate-simulation.lua`）
1. **纬度基值**：温度/降水基础值由纬度决定
2. **哈德莱环流**：副热带高压 → 增温减雨
3. **ITCZ**：热带辐合带 → 增雨
4. **大陆性**：距海越远 → 冬冷夏热、降水减少
5. **雨影**：山脉背风面 → 降水锐减
6. **地中海效应**：特定纬度冬湿夏干

## 与 SotE 的设计差异

| 项目 | SotE | 本项目 |
|------|------|--------|
| 网格形状 | 方形网格 (lat/lon) | Goldberg 六边形 |
| 引擎 | Love2D (Lua) | Godot 4.7 (C#) |
| 细分机制 | 无（固定网格） | 可变频率 n |
| 极地扭曲 | 严重 | 无（六边形均匀分布） |
| 海陆判定 | Perlin 噪声阈值 | 球面 FBM 噪声阈值 |
| 气候系统 | 代码移植 | 直接移植算法 |
| 省系统 | 代码移植 | 类似但适配六边形 |
