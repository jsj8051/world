# 固定格地壳演化

模型版本 4。主世界的地壳材料、地形与地图共用 H3 res4 网格。

## 运行方式

- 用 F5 启动 `scenes/core/WorldGenWorld.tscn`。主世界从暂停的 0 Ma 启动，右上角支持单步、播放、暂停和向前跳转。
- 0 Ma 先铺初始陆壳、洋壳和基础高程。陆面有噪声起伏与浅槽，海底按初始洋壳年龄设定基准深度，并向近岸过渡为大陆架。构造图在 0 Ma 即按初始板块速度标记边界，碰撞山带、洋中脊、海沟和裂谷的高程随演化形成。
- 需要直接生成指定时代时，可在主场景的 `WorldManager` 设置 `InitialEvolutionSteps`。默认每步为 0.1 Ma，100 步对应 10 Ma。跳转仅在目标时代生成完整地形、气候和水文。
- `res/params/world_params.json` 中的 `Evolution.StepYears` 控制提交间隔。设置为 `1000000` 时每步提交 1 Ma。求解器按位移限制自动拆分构造子步，每个子步重算边界和材料收支，启动日志的 `substeps` 给出拆分数。
- `tests/scenes/WorldEvolutionCheck.tscn` 直接实例化主场景，验证 res4 单步、跳转和地图刷新。诊断脚本仅进入 Debug 构建。
- 计算失败后保留已显示的年代。面板上的「恢复」清除故障状态，回到该年代的暂停态。

## 数据流

1. `scripts/Logic/Evolution/Grid/` 定义固定网格及共享球面边。`Materials/` 负责通量、格内材料槽和构造收支。材料按格、板块、壳型汇总，每个格块连续存放有值的材料槽。固定子步的跨边比例只计算一次，跨边输运只读取源格中已有的材料。搬运和覆盖结算复用同一格的工作区，结算后每格占地之和等于宿主面积。
2. 陆陆汇聚压缩占地并保留体积；俯冲只消耗活动下盘的洋壳，优先沿同一活动下盘从邻格结算余量。混合格的非构造覆盖修正优先调整洋壳占地，陆壳溢出时转移材料及其历史。陆侧张裂先减薄并累积应变，达到破裂阈值后才补洋壳。走滑保留切向速度与材料搬运。
3. `scripts/Logic/Evolution/Surface/` 由材料生成 `CrustProjection`，包含海拔、板块、壳型和边界。碰撞剖面在模拟格心重分布已计入的增厚抬升，重分布的面积积分为零。混合格按陆壳和洋壳各自的海拔计算露出面积比例，供地形图、选中格和演化面板读取。气候和水文使用最终高程派生的整格海陆掩码。跨分辨率映射由测试工程独立诊断。
4. `WorldEvolutionSession` 独占播放、暂停、跳转和故障状态。求解器从已发布帧计算候选帧，后台再生成气候、水文和索引，最后由主线程一次发布为 `WorldFacts`。查询通过 `WorldFacts.Evolution` 取得同一年代的地质帧。取消、失败和已经被替换的任务不会发布候选帧。

表层壳型由本格主板块携带的材料判定。地壳图和拾取使用该口径，格内洋壳占比仍按所有板块的材料汇总。火山弧使用上盘积累的弧火山体积，在主网格上做面积归一的高程重分布。陆洋张裂的陆侧保持被动陆缘，洋侧生成洋壳和洋脊。

版本 4 使用种子 42 重跑 res4 的 10 Ma 和 30 Ma。两期均出现陆陆、陆洋、洋洋的汇聚和张裂。俯冲边识别的陆壳上盘格分别有 61 和 235 个，表层图中均保持陆壳。合成网格回归分别检查碰撞山带、陆弧与岛弧、海沟、裂谷、洋脊及物质收支。

## 验证命令

```powershell
dotnet run --project tests/World.Tests.Local
dotnet run --project tests/World.Tests.Local -- --evolve 1 100
dotnet run --project tests/World.Tests.Local -- --evolve 2 100
dotnet run --project tests/World.Tests.Local -- --evolve-session
dotnet run -c Release --project tests/World.Tests.Local -- --evolve-audit 4

& 'D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe' `
  --headless --path . res://tests/scenes/WorldEvolutionCheck.tscn -- --evo-check
```

`--evolve` 先跑真实 H3 的静止和共同旋转对照，再推进默认板块。主场景的 `--evo-check` 在 res4 演化步未提交、投影未应用或面板不可见时返回非零退出码。

`--evolve-audit` 读取项目的默认档和用户档，以格实际面积加权比较 0、50、100 Ma。模型版本 3 在当前种子 42 的 res4 对照中，100 Ma 时陆壳材料占地由修复前的 28.23% 提高到 33.08%，高程判定的整格陆地从 13.90% 提高到 23.57%。混合格分相统计的露出面积为 29.53%。陆陆碰撞边相邻格最高海拔从 400 m 提高到 1,175 m。

在运行前设置 `$env:WORLD_BUILD_PROFILE = '1'`，可输出构造步、地表适配、两遍洋流、月度气候、水文、索引及地图重烘耗时。主场景还报告进程峰值工作集和材料槽容量。`dotnet run --project tests/World.Tests.Local -- --evolve-world 4 1` 提供同网格的纯逻辑对照，开启诊断时会输出高程、温度、降水、气压与洋流方向的 SHA-256 摘要。

## res4 对照

同机交替运行 Debug 的 `--evolve-world 4 1`，固定种子 42 和 288,122 格。基线沿用已有稀疏材料槽、月度并行及气压插值缓存。对照版额外复用两遍洋流的求解格列表、缓存气压粗层卷积核，并将不随月份变化的温度振幅、极锋和副高项移出月循环。

| 后端地表到世界事实 | 两次实测 |
|---|---|
| 基线 | 11.60 秒、11.66 秒 |
| 优化后 | 4.14 秒、10.88 秒 |

五项字段的 SHA-256 摘要在四次运行中逐项一致。运行时间受当时负载影响，样本尚不足以估算稳定提速比例。

主场景 Debug headless 的一次完整回归中，单步到地图刷新为 12.26 秒，随后向前跳两步为 14.14 秒。进程峰值工作集为 2,408.7 MiB，第 3 步有 311,058 个占用槽，材料槽容量约 33.8 MiB。按同样的格数和 8 个板块估算，旧密集槽数组仅槽数据就需约 422 MiB。进程峰值还包含地形、气候、水文及引擎资源。

## 模型边界

一阶迎风输运会扩散细窄地貌。占地结算和边界剖面是程序化近似。裂解发生在已有板块边上，模型暂不自动分裂、合并板块，也不持久化历史。res4 发布一帧需要全量重建气候和水文。
