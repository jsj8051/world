# 星球格子策略游戏 —— 项目设计记录

> 记录时间：2026-08（会话共识，后续开发以此为纲）

## 项目本质

**中世纪国家策略游戏（4X/文明类）**，玩家扮演一个国家进行游戏。
星球表面 = 游戏地图（格子策略玩法），**不是**可探索地形。

玩法链路：精细格子 → 地形/气候/生态群落模拟 → 文明发展（国家/城市/人类发展）→ 中世纪可游玩时代 → 玩家扮演国家。

## 核心架构决策（已确认）

### 1. 生成与游玩解耦（关键决策）
- **生成阶段**（离线/编辑器，可花费几十分钟）：生成地图 → 产出**地图存档**
  - 可跑重模拟：板块构造、气候迭代、侵蚀
  - 分辨率不受运行时限制（25km²/格 = 2011 万格数据生成可接受）
- **游玩阶段**（运行时，毫秒-秒级）：加载地图存档 → 只跑逻辑层模拟
  - 玩家可选**预制地图**，或花费时间**生成全新地图**
  - 参考模式：Dwarf Fortress 世界生成 / Civ 地图编辑器
- **地图存档 = 游戏内容管道的核心**（种子/版本/可复现性要设计好）

### 2. 双层架构（渲染与逻辑解耦）
- **纹理层**（25km²/格观感，静态）：海拔/气候/生态 → 立方体贴图（每像素 ≈ 25km²）
  - 几何格子到 25km² 不可行（2011 万格 × 10 三角形 = 2 亿三角形，内存 4GB+）
  - 纹理路线：6×2048² 立方体贴图 ≈ 2500 万像素 ≈ 25km²/像素 ✓
- **逻辑层**（文明模拟载体，几何格子）：n=64（4.1 万格）~ n=128（16.4 万格）
  - 每格数据：地形/气候/生态/归属/城市/人口……
  - 模拟性能：4-16 万格 C# 逐格运算可承受
  - 游戏交互（点击/高亮/管理）在此层

### 3. 视角：欧陆风云式（战略地图视角）
- 上帝视角地图，可缩放（全球 ↔ 区域），不落地
- 视觉：3D 球体 + 地图纹理 + 格子高亮/国家边界/城市图标（游戏层叠加）
- "拉近看不清格子分界" = 视角设计问题（限制最近距离 + 描边 + 游戏层高亮），与 LOD 无关

### 4. 动态 LOD：已放弃（2026-08 决策）
- 自研 chunked hex LOD 反复出 bug（归属/风暴/环带/缺角/追平窗口），本质是 hex dual mesh 的 LOD 无成熟方案
- 调研结论：纯裙边方案在 hex 上不可行（混合 LOD 缝 = 网格粒度级，几十 km，裙边盖不住）
- 静态烘焙 + 地图存档替代（无缝 + 秒加载）
- 保留的资产：LocalGoldberg（每面级别缝合数学，验证 <1m 配对）、环带裁剪、PlanetColors、SurfaceGenerator、描边 shader（A 通道边缘距离）

### 5. 网格拓扑：Goldberg hex（保留）
- 20 面体 + dual hex，无极点问题，均匀邻接（策略游戏理想网格）
- 半径 6330km（地球尺度）
- 格数与粒度对照：n=64→4.1 万格(111km)/n=128→16.4 万格(55km)/n=256→65.5 万格(27.7km)/25km² 目标→n≈1414(2011 万格,纹理层)

## 烘焙管线（生成阶段，下一步实施）

1. 地形：板块/噪声 → 海拔场 → 纹理（每像素）+ 逻辑格汇总
2. 气候：纬度 + 海拔 + 洋流 → 温度/降水场（纹理 + 逻辑）
3. 生态：气候 → 植被/地形类型（纹理 + 逻辑）
4. 输出地图存档：
   - 立方体贴图（海拔/气候/生态）
   - 逻辑网格数据（tile 属性表，序列化）
   - 渲染网格（顶点色 = 生态色 + 描边）
5. 运行时：加载存档 → 球体 + 游戏层

## 待讨论

- 逻辑层最终 n 值（64 vs 128）
- 地形生成风格（现有 SurfaceGenerator 噪声 vs 板块化大陆）
- 地图存档格式（种子/版本/二进制 vs .tres）
- 25km² 是"必须的格子粒度"还是"观感目标"（纹理层已满足观感）
