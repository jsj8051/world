## 二 `Plate` 数据载体

```
Plate {
    int     PlateId;
    float   SeedTheta, SeedPhi;   // 种子点位置（原 ThetaV/PhiV 改名，语义不变）
    Vector3 Omega;                // 欧拉矢量：方向 = 极轴，模 = 角速率
    CrustType Crust;              // 壳型（生成期判定）= 本板块唯一的陆海身份
    float   Density;              // 密度（随机量，与壳型无关）：只在汇聚边界上分上下盘
}
```

**命名事故**：`ThetaV/PhiV` 注释写「种子点极角/方位角」、赋值 `ToEuler(...)` ⇒ 值是**位置**，
但没有 `V` 后缀才知道它是什么——改名后 `VTheta/PhiV/ThetaV` 这组字段才真正名副其实（该组已于 D7 整体被 `Omega` 取代）。

**运动物理含义**：整块板块绕 `Omega` **刚体**转动，逐格线速度 `v = Omega × 格心方向`——
角速度逐板块恒定、线速度随位置变。`MinSpeed` / `MaxSpeed` 就是 `|Omega|` 的值域，
`BuildSeeds` 由种子点处的切向速度反解 `Omega = 方向 × v切`（`Omega ⊥ 方向` ⇒ 种子点速度恰为该切向速度）。

> ⚠️ **本节整体已废（2026-10-17）**：锚点 / 影响场 / 判陆阈值全删，改见 §十。

## 八 板块运动与汇聚角色（D7 / D8）

### 8.1 运动：逐块一个欧拉矢量

- `Plate.Omega`（`Vector3`）= 方向（极轴）× 角速率；逐格速度 = `Omega × 格心方向`（`PlateBoundaryOps.TangentVelocity`）。
  **角速度逐板块恒定，线速度随位置变**。
- **旧口径的缺陷**（已废）：`VTheta/VPhi` 存的是**种子点**的 θ̇、φ̇，却被当作全场常量套到任意格上
  ⇒ 同一块板块各格实际角速度不同，**不是刚体**。取纯经向（ψ=0）时场退化为 `v ≡ e_θ`，
  散度 `div v = cotθ ≠ 0`（刚体转动恒为 0）。
- `BuildSeeds` 由种子点处的切向速度反解 `Omega`：`Omega = 方向 × v切`，`v切 = V·(cosψ·e_θ + sinψ·e_φ)`。
  `Omega ⊥ 方向` ⇒ 种子点速度恰为该切向速度；抽样次序不变 ⇒ 种子点位置与旧版逐位相同。
- `MinSpeed` / `MaxSpeed`（`PlateSpec`）语义不变：`|Omega|` 的值域。**边界相对运动场整体改变**
  ⇒ 后续按它塑造的构造带分布会变；板块划分、锚点、陆地掩码不受影响。

### 8.2 汇聚角色：上盘 / 下盘

> ⚠️ **本节的角色取值已废**（2026-10-17）：`BoundaryRole` 扩成四档 `None / Upper / Lower / Arc / Slab`，
> 见 **§十三 13.2**。下面的扩散机制与"角色 = 板块对的纯函数"这两条**仍然成立**。

- **`BoundaryRole`**（`Data/Constants/BoundaryRole.cs`）：`None` / `Overriding`（上盘）/ `Subducting`（下盘）。
  与壳型是**两个正交维度**——同一个上盘落在陆壳上成山脉、落在洋壳上成岛弧；下盘洋壳成海沟。
- **`PlateBoundaryOps.BoundaryRoles(ball, plateOfCell, plates)`**：
  ① 边界格取「异板块邻居里**最负**的那一对」（迎面最强的对手）定出**对侧板块号**；
  ② 对侧板块号沿邻接图扩散，**只在同板块内扩散**（不跨边界 ⇒ 两侧角色天然分开）；
  ③ 逐格按「本方板块, 对侧板块」现算角色。
- **判据（`PairRole`）**：陆×洋 ⇒ 陆侧恒上盘、洋侧恒下盘；同壳型（陆×陆 / 洋×洋）⇒ `Density` 小的当上盘。
  角点格（一个格同时挨两块异板块）由「最负的那一对」拍板，而**是否汇聚**仍按 `BoundaryMotion` 的均值口径。
- `Plate.Density` 走**独立种子流** `SeedDerivation.Plate_Density`，不混进 `Plate_Seeds`。

### 8.3 边界输入留给高度塑造

`PlateBoundaryOps` 的三个算子在 ⓪ 阶段是**纯产物**，① 阶段做地形塑造时按需消费：

| 算子 | 逐格语义 | 塑造用途 |
|---|---|---|
| `BoundaryHops` | 到板块边界的跳数（边界格 = 0） | 带状的**距离场**（待接：其余四类构造项） |
| `BoundaryMotion` | 边界法向相对运动（`< 0` 汇聚 / `> 0` 张裂） | 定抬升还是下陷（**已接：山脉强度**） |
| `BoundaryRoles` | 汇聚侧角色（上盘 / 下盘） | 定谁隆起（**已接：山脉上盘**；陆 ⇒ 山脉、洋 ⇒ 岛弧）、谁俯冲（洋 ⇒ 海沟） |

- **km 折算**：`SpatialScale.CellEdgeKm`（等积格边长 ≈ 26 km）低于真实邻格中心距，
  实测比值 ≈ 1.78（见 `SpatialScale.HopDistanceKm` 标定）⇒ 按「跳数 × 边长」折算会低估约 1.8 倍，
  定带宽时须按真实格距算。
- `BoundaryRoles` + `BoundaryMotion` 已由 ① `TerrainManager`（山脉）消费；`BoundaryHops` 仍待用
  （原消费者是已删的世界图地质区域子系统，现留给其余四类构造项）。

## 九 ① 构造项：山脉（已实施 2026-10-16）

> ⚠️ **本节的参数表与"斜率制"已废**（2026-10-17）：山带改成**按角色分档 + 归一压峰**，
> 实现搬进 `HighlandOps`；`UpliftPerMotionM` / `MountainBandKm` 两个字段已删，见 **§十三**。
> 下面"作用域 = 陆壳板块的格（不论海陆）"「同板块内扩散」这两条**仍然成立**。

`TerrainManager` 在陆面合成之上**加性**叠一层构造抬升，作用于**陆壳板块的格（不论海陆）**。规则：

| 环节 | 口径 |
|---|---|
| 只在哪 | **顶起侧**（`BoundaryRoles == Overriding`）的边界格——源集**不逐格卡"算不算汇聚"**；「汇聚才算山」由连续强度门 `max(0, −motion)` 负责（张裂段平滑淡出，不硬断） |
| 作用域 | **陆壳板块的格（不论海陆）**——陆壳的水下边缘同样被顶起；抬升过海面即自动成陆（基底由壳型选，海陆由高度定） |
| 侧向范围 | 从边界格向陆内按**跳数**衰减；BFS 只在「同板块 + 同属顶起侧」的格上扩散 |
| 衰减核 | smoothstep（边界格 = 1、带宽外 = 0，二阶连续无折痕） |
| 带宽 | `MountainBandKm`（km）÷（`CellEdgeKm × 1.78`）= 跳数 |
| 峰值 | **斜率制**：`UpliftPerMotionM × max(0, −motion)`——无"山峰高度"上限，高度由板块速度差定 |
| 沿带 | 乘非负噪声调制（`MountainRidgeWavelengthKm` / `...Octaves` / `...Floor`）⇒ 山口与高峰，非等高墙 |
| 收尾 | 抬升量场过**一层邻域平滑**（`MountainSmoothWeight`，加权混合 `(1−w)·自身 + w·邻居均值`）⇒ 削毛刺与段端台阶、保住峰高 |

- 参数全在 `TerrainSpec`（`UpliftPerMotionM` / `MountainBandKm` / `MountainRidge*` / `MountainSmoothWeight`）。
- **口径纪律**：`BoundaryRoles` 判「是否汇聚」与 `BoundaryMotion` **同用邻接对均值**——原先是
  「异板块邻居里最负的单对」，两者在**三结点 / 边界拐角**处会打架（role 说上盘、强度却过零），
  表现为山脊的**锯齿状硬断**。另：源集不再逐格卡汇聚（见上表），硬断的两条来源都已拔掉。
- 接线：`TerrainManager.Run` 新增 `plateOfCell` / `plates` 入参 ⇒ `TerrainPipeline.Run` +
  `WorldGenSimulation.Run` 同步加参（`PlatePipeline` 早已产出这两份）。
- **契约变化（2026-10-16）**：抬升扩到「陆壳板块的格」后，「海格恒 = `SeaLevelM`」**不再成立** ——
  陆壳的海格 = `SeaLevelM` + 抬升（可为 0）；**唯一口径变成 `FinalLand = 高度 > SeaLevelM`**
  （`PlacementLand` 后于 2026-10-17 彻底删除，见 §十）。洋壳的海格仍是平的（= `SeaLevelM`）。
  下游（Facts / 水文 / 渲染）本就按高度判海陆，无需改动。
- 未做（留后续独立分支）：岛弧（洋壳上盘成陆）、海沟下沉、洋中脊隆起 —— 洋壳海底仍是平的，
  要做得先给海底一个基准深度（否则"海底"就贴在海面上）。

## 十一 地形尺度重标定（2026-10-17）

用户验收反馈：「海岸过于分散，并且山脉起伏太小海拔高度太低」。诊断 → 重标定幅度旋钤，
**不改算法**。

### 11.1 诊断

- **海岸碎**：`SphericalFbmNoise` 值分布近高斯（σ ≈ 0.29 × 标称幅值）。原三档（45 / 27 / 15）
  合成后 σ ≈ **16 m**，而陆面基线 `LandBaseM` = **10 m** —— 两者同量级 ⇒ 海面（0 m）恰切在
  分布**中心** ⇒ 陆面在 0 上下高频交错 ⇒ 海岸是"盐和胡椒"式碎斑。且大尺度项只占总 σ 的 55%，
  海陆分异被中 / 细节尺度揉碎。
- **山矮**：峰值 = `UpliftPerMotionM`(3000) × `max(0,−motion)` × `falloff` × `mod`；`motion` 是
  速度差法向投影（`|Ω| ≤ 1`），强汇聚处也就 0.3~0.5 ⇒ 峰值几百米；带宽 400 km ÷ 46 km ≈ **9 跳**
  （窄），再被 `MountainSmoothWeight` = 0.5 削峰。
- **海拔低**：陆面均值 = 基线 10 m ⇒ 大陆是贴在海面上的一层薄皮。

### 11.2 口径（用户拍板）

**地球尺度**（大陆主体 200~800 m、山脉峰值 2000~4000 m）+ **少数大块大陆**（全球 ≈ 2~4 块）。

### 11.3 参数（旧 → 新）

| 参数 | 旧 | 新 | 意图 |
|---|---|---|---|
| `PlateCount` | 12 | **8** | 板块更大 ⇒ 陆壳更少更大（≈4 块）⇒ 大陆少而大 |
| `Terrain.LandBaseM` | 10 | **180** | 抬离海面 ⇒ 陆壳约 3/4 成陆，海岸集中 |
| `Terrain.LargeVariationM` | 45 | **900** | 海陆分异**主导项**（占合成 σ 的 99%）|
| `Terrain.MediumVariationM` | 27 | **90** | 陆地丘陵 |
| `Terrain.RegionalNoiseM` | 15 | **35** | 细节 |
| `Terrain.LargeWavelengthKm` | 5000 | **8000** | 大陆尺度（全球约 5 波长）|
| `Terrain.UpliftPerMotionM` | 3000 | **8000** | 山脉峰值抬到数千米 |
| `Terrain.MountainBandKm` | 400 | **800** | 山带加宽（≈17 跳）|
| `Terrain.MountainRidgeWavelengthKm` | 600 | **1000** | 山脊更长 |
| `Terrain.MountainSmoothWeight` | 0.5 | **0.3** | 少削峰 |

重标定后：合成 σ ≈ **263 m**（大尺度占 99%）⇒ 海陆由大尺度场定、海岸随它成片；
P(陆壳陆面 &lt; 0) ≈ 25%；陆地上均值 ≈ 290 m、+1σ 处 ≈ 440 m（再叠山脉到数千米）。

### 11.4 影响面

- 只动两份参数档（`res/params/world_params.json` + 用户档）+ `TerrainSpec` / `PlateSpec` 属性初值
  与注释；**`TerrainManager` 算法一字未改**。
- 连带（未动，待观测）：`ElevationBands` 档界（0 / 300 / 900 / 1800 / 2800）此前因低平台
  "全部陆地挤在低地档"——重标定后 300 / 900 两档开始被用到，山地档（1800+）仍留给山脉。

| 深海丘陵 | 两档噪声（7680 / 1707 km）叠在年龄剖面上 |
| 大陆架 | 按**离岸距离**：−30 m（贴岸）线性到 −180 m（架缘）；宽度 60 → 565 km，被动边缘宽、**俯冲带一侧窄**（汇聚强度调制），离岸 &lt; 400 km 再放宽 1.3× |

| 岛弧 | **上盘**（`Overriding`）的**洋壳**、在海沟后 215 km 一条 175 km 宽带上隆起成海底脊（脊顶 −1600 m）；沿带噪声峰处再叠 2400 m ⇒ **抬过海面成一串岛** |
| 海沟 | **下盘**（`Subducting`）的**洋壳**、紧贴边界挖一道窄槽：深度 = (3200 + 3300×汇聚强度) × 汇聚强度；离岸 &lt; 40 km 不挖、&gt; 270 km 达满 |
| 钳制 | 深度 ∈ [`OceanDeepestM` −10500, `OceanShallowestM` −20] |

**符号**：参考的 `convergence` 是**正 = 汇聚**，我们的 `BoundaryMotion` 是**负 = 汇聚**（`(v_B − v_A)·n̂`）——
移植时已整体翻转；强度统一为 `clamp(|motion| / 0.9, 0, 1)`，活动边界阈值 `|motion| > 0.25`。

**单位**：参考以"世界单位"给距离（1 单位 ≈ 19.5 km，赤道 2048 单位），本项目一律换算成 **km**；
深度一律**米**。因此本项目必须用 `DistanceFieldOps`（真实 km），**不得**用跳数 × 常数折算
（跳数只在同 res 内自洽、且有 ±25% 偏）。

## 十三 ① 构造项：山带按角色分档 + 归一压峰 + 高原底座（2026-10-17）

借鉴参考项目 `civ-atlas` 的造山链（只借算法口径、C# 重写，不复制代码）。

### 13.1 起因

用户反馈上一轮重标定后「山脉起伏太小」，并且参考里山的**形状**与我们不同。四块差距：

| 差距 | 参考的做法 | 我们原来的做法 |
|---|---|---|
| **按角色分档** | 四档角色各有带宽 / 内移 / 系数 | 所有上盘共用同一个带宽与系数；下盘**完全不长山** |
| **古老山系 + 丘陵** | ridged 噪声做细长残丘 + 丘陵场 | 没有，只有当代山带 |
| **高原底座** | 山带背后一大片平坦高地（独立加性层） | 没有 |
| **幅度归一 + 压峰** | 第 99.7 百分位映射到目标峰高，折点以上压缩 | **斜率制**，峰高完全由板块速度差定 ⇒ 峰高飘忽 |

### 13.2 `BoundaryRole` 扩成四档

`None` / `Upper` / `Lower` / `Arc` / `Slab`（`Data/Constants/BoundaryRole.cs`）。

| 档 | 什么时候是它 | 画面上是什么 |
|---|---|---|
| `Upper` | 陆×陆，密度小的一块 | 宽带高山 + 背后高原 |
| `Lower` | 陆×陆，密度大的一块 | **同样成山**（碰撞带两侧都是山） |
| `Arc` | 陆×洋的**陆侧**；洋×洋的上盘 | 陆上是一条**内移的窄山链**（安第斯）；洋上是岛弧 |
| `Slab` | 俯冲下去的那块 | 陆上是低矮增生楔；洋上是海沟 |

`PlateBoundaryOps.PairRole` 按「本方壳型 × 对侧壳型 × 密度」定档，扩散机制不变
（仍是"边界格定对侧板块号 → 同板块内 BFS 扩散 → 逐格现算"）。

### 13.3 新类 `HighlandOps`

`scripts/Logic/Geology/HighlandOps.cs` —— 与 `OceanDepthOps` 同分工、互为陆海两侧：

```
Build(...) → Field { MountainM, PlateauM }      // 都只对陆壳格有效
```

`TerrainManager` 退成纯装配：铺陆面基底 → `HighlandOps.Build` → `OceanDepthOps.Build` → 合成。

**山带公式**（`cd` = 到汇聚边界的距离（由跳数 × `CellEdgeKm × 1.78` 折算）；`cs` = 汇聚强度 ∈ [0,1]）：

```
Upper / Lower : coef × Peak × cs × band(cd, 0, UpperBandKm + SpreadKm × cs)
Arc           : coef × Peak × cs × band(cd, ArcInlandKm, ArcBandKm)
Slab          : coef × Peak × cs × band(cd, 0, SlabBandKm)
band(d,c,w)   = exp(−((d−c)/w)²)，|(d−c)/w| > 4 ⇒ 0
```

再乘山脊沿带调制（`MountainRidgeFloor`）与张裂压低 `1 − RiftSuppressStrength × divStr × band(divDist, 0, RiftBandKm)`。

**幅度归一**（第 ⑦ 步，在平滑**之后**）：
`gain = MountainPeakM / 全场构造抬升的第 99.7 百分位`；
`u > knee` ⇒ `u = knee + (u − knee) × MountainKneeCompress`，`knee = MountainKnee × MountainPeakM`。
⇒ 峰高跨 seed / 跨板块数可比，且不会冒出万米高峰。**`UpliftPerMotionM` 随之删除**（归一后斜率会被约掉，留着就是死旋钮）。

**古老山系 + 丘陵**：`SampleRidged`（新写的 ridged fBm，`(1−|n|)²` 逐层压权、按振幅和归一、值 ∈ [0,1]）
的峰处冒头，再乘丘陵场门；丘陵本身另加一层低矮起伏。**冒头门按分位取**（不作固定阈值）——
老山 97.5% → 99.8% 分位、丘陵 90% → 99%、高原沿走向 55% → 85%、大陆内部 55% → 90%、盾状台地 45% → 85%。
用分位而不是固定阈值 ⇒ 换噪声实现不用重调（参考里的 0.78 / 0.96 是按其噪声分布调的，搬不过来）。

**高原底座**：`Upper` / `Arc` 且 `cs > PlateauConvMin` 时，自边界 `PlateauInnerRampKm` 起、
内伸 `reach = PlateauXxxReachKm + PlateauReachSpreadKm × 噪声`、外缘再收 `PlateauOuterRampKm`，
高度 `PlateauUpperHeightM` / `PlateauArcHeightM`；大陆内部另加盾状台地 `PlateauShieldHeightM`。
最后整体乘 `smoothstep(0, PlateauCoastFadeM, 陆面基底 − 海面)` ⇒ **海岸不起高原、不成悬崖**。

### 13.4 参数

`TerrainSpec` **46 → 72**：删 2（`UpliftPerMotionM` / `MountainBandKm`）；
构造高地段共 32 个（山带 16、老山丘陵 2、裂谷 2、高原 12），其中 4 个（`MountainRidge*` /
`MountainSmoothWeight`）沿用旧名 ⇒ **净新增 28**。两份参数档同步。

⚠️ 与海底段同口径：**噪声的波长 / 层数 + 冒头门的分位**不进 spec，作为实现常量留在 `HighlandOps`
（算法内部的纹理尺度与形状常量，不是能改画面的物理旋钮）。要变成旋钮加字段即可。

### 13.5 契约与影响

- **海陆口径不变**：`FinalLand = 高度 > SeaLevelM`。
- **离岸距离的源**改为「陆壳 且 陆面 + `MountainM` + `PlateauM` > 海面」。
- **`BoundaryHops` 有了消费者**（`HighlandOps` 用它判"是不是边界格"）。
- **性能**：新增 **1 次**多源 Dijkstra（到活动张裂边界，截断 `4×RiftBandKm`）+ **6 次分位抽样排序**
  （分位只抽样，上限 26.2 万格 ⇒ 与 res 解耦）。总计 ① 阶段 4 次 Dijkstra。
- **`PlateCount`**：8（不变）。

- **草图 / 手动编辑**。

## 十四 画面反馈与二次调参（2026-10-17）

§十三 落地后用户看画面反馈两条：

> 「1. 山脉保住整个海洋，这种地形有可能生成吗」「2. 一层一层的，太平单调了」

### 14.1 「山带围成一圈」是可生成的

环太平洋火山带就是一圈俯冲 / 碰撞边界围起来的海洋。8 块板块下边界本来就少，
一片超级大洋的整条岸线很可能落在**同一条**汇聚边界上 ⇒ 一条闭合的环，属正常结果。
要更自然有两条路：`PlateCount` 回到 12~14（板块边界变多、岸线被切成几段不同性质的边界），
或让山带本身**断成一段一段**（见下 `MountainRidgeFloor`）。

### 14.2 「一层一层、太平」的成因

陆面 = `LandBaseM` + 三档幅值 × 各自变化场，各场 σ ≈ 0.29 × 幅值：

| 档 | 波长 | 幅值（旧） | σ 贡献 |
|---|---|---|---|
| 大尺度 | 8000 km | 900 | **261 m** |
| 中尺度 | 600 km | 90 | 26 m |
| 细节 | 90 km | 35 | 10 m |

大尺度波长与大陆同量级 ⇒ 陆面就是**几坨平滑大块**；中/细节的 σ 加起来不到大尺度的 1/9
⇒ 档界（300 m / 900 m）几乎不被跨越 ⇒ 画面"一层一层、太平"。
另：900 m 落在 **+2.7σ** ⇒ 理论上只有 ~0.4% 的陆格能自然进 Highland 档。

### 14.3 参数（旧 → 新）

| 参数 | 旧 | 新 | 意图 |
|---|---|---|---|
| `MediumVariationM` | 90 | **300** | 600 km 一级的丘谷 —— **打散大色块的主力** |
| `RegionalNoiseM` | 35 | **120** | 谷坡与碎斑 |
| `MountainUpperBandKm` | 140 | **260** | 山带变胖（不是变高） |
| `MountainBandConvSpreadKm` | 175 | **400** | 满强度带宽 315 → **660 km** |
| `MountainRidgeWavelengthKm` | 1000 | **700** | 山脊更密更碎 |
| `MountainRidgeFloor` | 0.35 | **0.15** | 沿带谷处只留 15% ⇒ 山带**能断**，不再是一堵绕圈的墙 |
| `OldMountainHeightM` | 1000 | **2000** | 跨进 Highland 档（900–1800）才看得见 |
| `HillsHeightM` | 250 | **600** | 同上（250 m 整块闷在 Plain 档里） |
| `OceanSmoothPasses` | 5 | **8** | 削弱距离场等值线的多边形折痕 |

`HighlandOps` 的冒头门同时放宽：老山 97.5%→99.8% 改为 **90%→99%**（覆盖 ~10% 陆格）、
丘陵 90%→99% 改为 **70%→97%**（~30%）。

合成 σ：263 → **277 m**（大尺度占比 99% → **89%**）；P(陆壳陆面 < 海面) 仍是约 1/4
⇒ **海岸成片这一条没有被破坏**，只是陆内多了层次。

### 14.4 一处已知的取舍

老山 / 丘陵是**加性**叠在构造抬升上的，而构造抬升已过归一 + 压峰 ⇒ **老山不受压峰管**，
「主峰 + 老山」可以超过 `MountainPeakM`（4800 m）。这是有意的：压峰的目的是防离谱高峰，
而"最高的山在造山带上"这条直觉要求老山不被算进归一（否则老山面积一大就会把主峰拉矮）。
若哪天要"最高峰恒 ≈ `MountainPeakM`"，把老山也并进 percentile 那一步即可。

## 十五 ① 构造项：山体细化 + 虚拟侵蚀（2026-10-17）

### 15.1 起因

用户看过 §十四 的画面后：

> 「山脉的细化用分形柏林噪声 + 梯度模拟侵蚀算法」
> 「用虚拟的侵蚀来做就行」

即：山带已经**分档、加宽、能断**，但成形工艺只有"构造抬升 + 一层平滑"
⇒ 山体是一堵**等高的、光滑的墙**。要的是**脊谷相间的山系**。

### 15.2 落点

新类 `scripts/Logic/Geology/ErosionOps.cs`（静态算子，与 `HighlandOps` / `OceanDepthOps` 同级）。
它由 `HighlandOps.Build` 在**合成完 `mountain` 之后、返回之前**调用：

```
mountain = ErosionOps.Build(ball, seed, spec, continental, mountain);
```

⇒ ① 阶段仍是 `TerrainPipeline`（编排）→ `TerrainManager`（装配）→
`HighlandOps` / `OceanDepthOps` / `PlateBoundaryOps` / **`ErosionOps`**（实现）。
`TerrainManager` 一行未改。

### 15.3 口径

两步，**顺序不能反**：

**① 分形细化**
```
mult[i] = 1 + MountainDetailAmount × (ridged(seed, dir) × 2 − 1)     // ∈ [1−A, 1+A]
height[i] = relief[i] × mult[i] / mean(mult)
```
- 用 ridged 分形（`SphericalFbmNoise.SampleRidged`，基波长 180 km / 4 层 ⇒ 180-90-45-22.5 km）；
- **按均值归位** ⇒ 细化只改形状、**不改平均幅度**（否则整条山带会被悄悄削掉一截）；
- 必须在排水**之前**做：光滑面上的单流向会退化成规则的径向纹，出不来树枝状沟谷。

**② 虚拟侵蚀**（迭代 `ErosionSteps` 步，每步）：
```
填洼（副本） → 单流向（严格更低、平局取小索引） → 汇流累积 A → 逐跳落差 S
cut[i] = ErosionDepthM × (A[i] / A_max)^ErosionExponent × min(1, S[i] / S_90)
height[i] -= min(cut[i], ErosionMaxCutFraction × height[i])
```
- **填洼**：priority-flood（Barnes 改进版），出口 = `height ≤ 0`（构造抬升为 0 的平原 / 洋壳格）。
  **只改副本**——与 ④ 阶段 `HydrologyRoutingSurface` 同纪律，绝不回写世界高度。
- **访问序顺手复用**：填洼的弹出序是**升序**，逆序即拓扑序 ⇒ **不必再排序**（省掉一次 O(n log n)）。
- **坡度用逐跳落差**（米 / 跳）并按其 **90 百分位**归一 ⇒ 不必换算物理坡度，也躲开了 km↔跳的折算。

**「虚拟」的界线**：不做时间演化的物理求解（参考口径是 dt / K / m 迭代几十步的隐式解），
每一步都是"按当前的汇水量与坡度**直接切一刀**"——只要**形状**，不要量纲、不要量级可比。

### 15.4 参数

`TerrainSpec` **72 → 77**（新增 5 个，全部在"构造项：山体细化与虚拟侵蚀"段）：

| 参数 | 出厂值 | 说明 |
|---|---|---|
| `MountainDetailAmount` | 0.35 | 分形细化幅度 ∈ [0,1)；0 = 关断 |
| `ErosionDepthM` | 900 | 汇水量最大那一档的下切（米） |
| `ErosionExponent` | 0.5 | `(A/A_max)^本值`：越小谷网越密、越大只有主河道深 |
| `ErosionMaxCutFraction` | 0.6 | 单步下切 ≤ 当前抬升的这一档比例（防削穿） |
| `ErosionSteps` | 3 | 迭代步数（0 = 关断） |

两份参数档（正库 + 用户档）同步。
与 §13.4 同口径：**细化噪声的波长 / 层数 + 坡度参考分位**不进 spec，作为实现常量留在 `ErosionOps`。

### 15.5 契约与影响

- **只刻构造抬升，不碰陆面基底** ⇒ **海岸线基本不动**（海岸由基底穿过海面定）；
  唯一的变化是山体变矮后原本勉强露出水面的少数格会回到水下（`aboveSea` 顺带重算）。
- **抬升恒 ≥ 0** 保持：单步下切被 `ErosionMaxCutFraction` × 当前抬升封顶。
- **最高峰仍 ≈ `MountainPeakM`**：脊顶格的汇流量极小 ⇒ 下切 ≈ 0，
  归一（§十三）定下来的峰高不会被侵蚀吃掉。
- **世界事实口径不变**：`FinalLand = 高度 > SeaLevelM`。
- **性能**：新增 `ErosionSteps` 次 priority-flood（O(n log n)）+ 若干 O(n) 扫描；
  无新增 Dijkstra。嫌慢就把 `ErosionSteps` 调到 1~2 或 0。

### 15.6 与参考的差距（有意保留）

| 参考（`erosion.ts`） | 本次 |
|---|---|
| 隐式解 `h = (h + dt·uplift + F·hr) / (1+F)`，`F = K·dt·A^m / dist` | 直接切 `ErosionDepthM·(A/A_max)^m·S/S_ref` |
| 18 步时间演化 + 每步抬升项 | 默认 3 步，无抬升项 |
| 降水加权汇流 | 均一权重（① 阶段在 ③ 气候之前，拿不到降水） |

有物理意义的量（降水、流量、时间）都在 **④ 水文**那一侧；① 阶段这一段只要形状。
