# 方案 · 气候链闭环迭代（温度 ⇄ 洋流）

- 状态：**待实施**（2026-10-23 用户拍板：先出方案，暂不动代码）
- 范围：`scripts/Logic/Composition/ClimatePipeline.cs`、`scripts/Data/Spec/ClimateSpec.cs`、
  `res/params/world_params*.json`、`tests/World.Tests.Local/`
- 前置：赤道台阶已修（`OceanCurrentModel` 的冷暖权重，见 `设计-气候链` §五.8）——本方案**不得**回退它
- 非目标：不引入盐度/温跃层，不改地图模式，不处理 `PrevailingWind` 的 30°/60° 硬切换（那是独立的 B 项）

## 一、要解决的问题

当前因果序（`ClimatePipeline.Run`）：

```
解析盛行风 ──→ 洋流① ──→ 沿岸冷暖 ──→ 年基温 ──→ 月循环（风/降水）──→ 温度/降水事实
                                                        └──→ 洋流②（真实风 + ∇T 热成风）──→ 存档场
```

温度**吃**洋流①的冷暖，但洋流②（真正读温度的版本）**不回写**温度。
结果是：温度图上那层 ±5 °C 的冷暖洋流修正，来自"不含温度反馈"的洋流。用户问题原文：
「为什么洋流不会根据实际温度来改变」——准确说，洋流②读了，温度没读回来。

环是这三条边：

```
温度 ──(+5·warmth)──→ 风（∇T→诊断风场）──→ ψ（SOR）──→ 冷暖 warmth ──(+5·warmth)──→ 温度
```

## 二、目标 / 验收

1. 温度事实与存档洋流**同源**：最终温度用的冷暖 = 最终洋流算出的冷暖（残差 ≤ 0.02）。
2. 闭环收敛且可判读：每轮残差入日志，不收敛有上限与兜底，**不抛异常、不毁世界**。
3. 视觉：温度图不新增任何纬度带/接缝（赤道、30°、60° 都不许出现折痕）。
4. 预算：res4 全链耗时 ≤ 现状 × 1.6；超了就用方案 §七 的成本杠杆降档。
5. 确定性：同 seed + 同 spec ⇒ 同轮数、同结果。不引入新随机源。

## 三、不动点定义

**只把 `coastalWarmth`（逐格 ∈ [−1,1]）当状态量**，理由是它是洋流进入温度公式的**唯一**入口：

| 消费方 | 用法 | 位置 |
|---|---|---|
| 年基温 | `+ warmth × OceanCurrentWarmthC`（5 °C） | `TemperatureModel.Compute` |
| 湿润降温 | 纬向降水估计 `× (1 + 0.25·warmth)` | `PrecipitationModel.EstimateAnnualMm` |
| 月降水 | 月骨架 `× (1 + 0.25·warmth)` | `MonthlyClimate.MonthPrecipBase` |

其余输入（海陆 / 海拔 / 噪声 / 倾角）都与洋流无关，不进状态。ψ 是派生量，只做热启动。

不动点映射：

```
F(w) = BuildCoastalWarmth( OceanCurrents( Wind( Temperature( w ) ) ) )
求 w* = F(w*)
```

**为什么必须迭代**：`w` 同时被正反馈（暖流→更暖→沿岸更强）与负反馈（暖→雨多→湿润降温）拉扯，
不能一次解出；也不该假设 F 是压缩映射（见 §八 风险）。

## 四、算法

```csharp
Run(...)
{
    // 0) 预热：解析盛行风把 ψ 拉起来（保留现状，120 遍）
    //    只在第 1 轮之前用；之后全部用真实风
    prevailing = PrevailingWind.BuildAll(...);
    currents.Compute(grid, spec, prevailing, oceanTempC: null, iterationCap: BootstrapSweeps);

    // 1) 迭代：每轮 = 基温 → 月循环 → 洋流 → 冷暖；残差够小就停
    w = currents.BuildCoastalWarmth(grid);           // 第 1 轮的输入
    prevT = null;
    for (k = 1; k <= maxRounds; k++)
    {
        // a) 温度基场（吃 w）
        base.Compute(grid, spec, w, seed);
        TemperatureModel.ApplyWetCooling(base.AnnualC,
            PrecipitationModel.EstimateAnnualMm(grid, w), spec);

        // b) 月循环（月温 → 风 → 水汽 → 月降水）
        monthly.Compute(grid, spec, base.AnnualC, w, seed);

        // c) 洋流（真实风 + 热成风），ψ 热启动（传副本，见 Compute 的 Array.Copy）
        currents.Compute(grid, spec, monthly.WindYear, monthly.AnnualTempC,
                         initialPsi: (float[])currents.Psi.Clone(), iterationCap: RoundSweeps);

        // d) 残差 + 欠松弛
        next = currents.BuildCoastalWarmth(grid);
        deltaW = MaxAbs(next - w);
        deltaT = prevT == null ? float.NaN : MaxAbs(monthly.AnnualTempC - prevT);
        prevT = monthly.AnnualTempC;
        if (deltaW < tolerance && k >= MinRounds) { w = next; break; }   // 收敛
        w = Lerp(w, next, relaxation);
    }

    // 2) 收尾：终版洋流（300 遍）→ 用**它自己**的冷暖重算温度/月循环 → adopt。
    //    这样"温度用到的冷暖"与"存档洋流"逐格同源（用户问题的正解）；
    //    与循环里那一轮的差记为收尾残差，超 tolerance 只记日志（不再迭代，防无限尾）。
    currents.Compute(grid, spec, monthly.WindYear, monthly.AnnualTempC,
                     initialPsi: (float[])currents.Psi.Clone(), iterationCap: FinalSweeps);
    wFinal = currents.BuildCoastalWarmth(grid);

    base.Compute(grid, spec, wFinal, seed);
    TemperatureModel.ApplyWetCooling(base.AnnualC,
        PrecipitationModel.EstimateAnnualMm(grid, wFinal), spec);
    monthly.Compute(grid, spec, base.AnnualC, wFinal, seed);
    Temperature.Adopt(monthly); Precipitation.Adopt(monthly); Wind.Adopt(monthly);
    FixedPointResidual = MaxAbs(wFinal - w);          // 诊断读数
}
```

要点：

- **轮次内的 SOR 遍数可以低**（`RoundSweeps ≈ 100`）：ψ 是热启动的，且下一轮还会再解；
  只有终版要 300 遍。
- **收尾必须用 `wFinal` 重算温度**：循环里最后一次温度用的是 `w_{k-1}`，而存档冷暖是 `w_k` 之后
  又解了一遍的终版值。少这一步就会留下"温度与洋流差一轮"的旧病。
- **`MinRounds = 2`（固定常数，不开放）**：`w` 从 0 起步，第 1 轮残差天然很大（0.5 量级），
  判据只在 `k ≥ 2` 起作用，否则会假收敛。
- **`maxRounds = 3`**：第 3 轮通常已到 0.01 量级以下，再加轮只烧时间。
- 不收敛：保留最后一次欠松弛结果，写日志（`RoundsUsed` / `FixedPointResidual`），**照常出世界**。
- 收尾那遍 `Compute(300)` 的右端项是**上一轮的**月平均风（`monthly.WindYear`）——
  这是唯一保留的"差一轮"，由 `FixedPointResidual` 度量；不收敛也不许再回头（会来回振荡）。

## 五、参数（新增 `ClimateSpec` 旋钮）

| 旋钮 | 默认 | 含义 |
|---|---:|---|
| `ClimateFixedPointRounds` | 3 | 最多轮数；**≤ 1 = 退回今天的"两遍折让"行为**（回退开关） |
| `ClimateFixedPointTolerance` | 0.02 | 收敛判据：`max|Δwarmth|` |
| `ClimateFixedPointRelaxation` | 0.5 | 欠松弛系数 ω（`w ← w + ω(next − w)`） |
| `ClimateRoundSweeps` | 100 | 每轮 SOR 遍数（终版固定 300，不开放） |

- 四个都进 `world_params.json`（本档必须写全，见该文件头注释）与 `world_params.user.json`。
- `设计-气候链` §四 的"49 项"改为 53 项。
- 不上面板：这是生成期收敛参数，不是世界语义，不进地图坞。

## 七、成本预算

实测基线（同一台机器，`--world 4`）：

| 项 | 本机实测 | 设计文档表（另一台） |
|---|---:|---:|
| 气候阶段 | 2.44 s | 5.2 s |
| 全链 | 5.09 s | 7.6 s |

增量 ≈ `(K−1) × 每轮`，每轮 = 温度/风/水汽/降水（约 1.5 s）+ 100 遍 SOR（约 0.9 s）：

| 方案 | K | SOR 总遍数 | 预留增量 | 全链预估 |
|---|---:|---:|---:|---:|
| 现值 | — | 120 + 300 = 420 | — | 5.1 s / 7.6 s |
| 推荐 | 2 | 120 + 2×100 + 300 = 620 | +2.4 s | ~7.5 s / ~11 s |
| 上限 | 3 | 120 + 3×100 + 300 = 720 | +4.8 s | ~10 s / ~14 s |

**成本杠杆**（超预算时按序动）：

1. `ClimateRoundSweeps` 100 → 60（ψ 只当中间量，误差由下一轮吸收）；
2. `ClimateFixedPointRounds` 3 → 2；
3. `maxRounds = 1` 即完全回退（不推荐，但可用）。

**备选（A2，只在预算被否时用）**：轮内用"年均风"（年温 → 诊断风场 → 梯度）代替 12 月循环，
每轮降到 ~0.5 s；代价是轮内风与终版月平均风不是同一个场，收尾要多一次温度重算来对齐，
并在文档登记"闭环按年均风收敛"这条近似。

## 八、风险与处置

| 风险 | 判据 | 处置 |
|---|---|---|
| 振荡 / 发散 | 残差比值 `r_{k+1}/r_k > 1` 连续两轮 | 降 ω（0.5 → 0.35）或降 `OceanCurrentWarmthC`；方案第 0 步先测增益再定 ω |
| 正反馈跑飞（暖流区更暖） | 全球均值漂移 > 1 °C，或单格 \|ΔT\| > 8 °C | 同上；必要时给 `warmth` 加"上一轮 ±0.5"的夹子（只在超限时生效，不改常态） |
| 耗时超预算 | res4 全链 > 1.6× | §七 杠杆 |
| 世界读数整体偏移 | 年均温 / 降水 / 河数变化 > 10% | 属预期（闭环会改沿岸 ±1–2 °C）；重测 §八 表并更新文档，不静默 |
| 参数文件漏字段 | 读档后用出厂值 | 两份 JSON 都写；`WorldParamStore` 已有"不补齐也不报错"的语义，测试里显式断言四个字段非默认 |
| 回退不了 | — | `ClimateFixedPointRounds=1` 必须逐位复现今天的结果（做成测试） |

## 九、测试计划

现有 13 个必须全绿（含 `赤道没有温度台阶`、`纬度剖面没有台阶`）。新增：

1. **闭环一致性**（合成网格）：`RoundsUsed ≥ 2` 且 `FixedPointResidual < tolerance`；
   并且用最终 `w` 重算的温度与 `Facts` 里的温度**逐格相等**（≤ 0.01 °C）——钉住"收尾重算"这一步。
2. **回退等价**（合成网格）：`ClimateFixedPointRounds = 1` 时，温度场与"手工按旧顺序跑一遍"
   的结果逐格相等（≤ 1e-4）——钉住回退开关。
3. （可选）**残差单调**：不减阻尼连跑 4 轮，`r_{k+1} ≤ 0.8·r_k`；不满足就把实测比值写进文档，
   作为选 ω 的依据。

res4 冒烟门槛（`dotnet run --project tests/World.Tests.Local -- --world 4 --csv`）：

- `rounds=` / `dW=` / `dT=` 三个读数在日志里；
- 全球年均温与现值差 ≤ 0.5 °C；温度域仍在 −36…+27 量级；
- CSV 复算：跨赤道最大温差 < 1 °C（回归）、逐纬度台阶扫描里 0°/±30°/±60° 均不进前八。

视觉验收：实机温度图（年均 + 任一月）看不到横线/圆环；洋流·冷暖图在赤道平滑过渡。
