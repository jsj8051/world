## 二、推荐方案总览

三条规则：

1. **纯数据在后台**：读包、校验、解码、`WorldFacts` 装配、生成管线只碰 .NET 与 H3，不碰 `Node`/`Resource`/`GD.*`。
2. **Godot 对象在主线程**：`ArrayMesh`、`ImageTexture`、`MeshInstance3D`、场景挂载一律主线程，按每帧预算分片。
3. **进度只走一个契约**：后台任务只写 `LoadOperation`（线程安全、无 Godot 类型）；页面加载由 `AppRoot` 按需创建的加载层轮询渲染，演化计算由独立 `EvolutionPanel` 场景轮询渲染；页面不实现进度逻辑。

```text
点击 / 开始计算
   │
   ├─ 主线程：创建 LoadOperation，显示进度层，先渲染一帧
   │
   ├─ 工作线程：Job 执行纯数据阶段 ── Report(百分比/阶段) ──► LoadOperation
   │
   └─ 主线程每帧：轮询 Job 完成？→ 分帧装配 Godot 对象（每帧 ≤8 ms 预算）
                     └─ 全部完成 → 进度 100% → 隐藏进度层 → 可交互
```

### 2.1 方案 A 的取舍

- 选择“后台数据 + 主线程分片装配”，放弃“所有工作都后台”的幻想：Godot 的资源创建不能离开主线程。
- 选择“轮询完成”而不是 `async/await` 跨线程续体，避免 Godot 主线程同步上下文不确定导致的续体跑错线程。
- 选择“页面加载用 AppRoot 按需加载层、演化用独立面板场景”，两者共用 `LoadOperation` 契约与 `LoadProgressView` 组件；放弃“所有进度都塞进一个浮层”，因为演化面板本身就是独立场景，进度跟随面板更自然（1B）。
- 选择“加载期间冻结输入、直接构建 res4”（3B 修订），放弃“预览球先开放”：代价是等待期间不能操作，但画面不会出现粗档跳变，验收口径保持单一。

## 三、关键流程

### 3.1 浏览所选地图

```text
MapLibrary 点击「浏览所选地图」
  → host.OpenMap(path)
  → AppRoot:
      op = progress.Begin(Modal, "加载地图")
      禁用重复点击；渲染一帧（进度层可见）
      job = Task.Run(() => MapBrowseJob.Run(path, op, token))
  → 主线程每帧:
      job 完成?
        失败: op.Fail(issue)；状态条显示错误码/位置；停留地图库
        成功: 用 op 继续装配 MapBrowser：
              ① 颜色纹理分片烘（每帧 3.2 万格）
              ② 每帧建 4–8 个 res0 块的 res4 高档与 res3 低档
              ③ 河线分批
              ④ 拾取器、取景、初始模式
              ⑤ op.Complete() → 隐藏进度层，开放相机/点选/模式切换
```

装配期间进度层是 Modal：相机、点选、模式切换都被挡住；100% 后才开放（3B 修订）。拾取仍按 res4 球现算，不依赖当前已建到哪一批网格。

`MapBrowseJob`（纯数据）内部顺序：

```text
1. 打开 zip、读清单、校验目录与引用（快）
2. 把数据块按清单顺序切给 N 个 worker（N=4–8），每个 worker 独立 FileStream + ZipArchive
   每块：解压 → SHA-256 → 直接解码为类型化数组 → 按块 id 归位
   进度上报：已完成块数 / 总块数（块大小已知，可换算字节）
3. 装配 ImportedWorldFactsSource（Ball 几何、板块、地形、气候、水文、索引）
   按子阶段上报（几何 / 板块 / 地形 / 气候 / 水文 / 索引）
```

并行只做“解压 + 哈希 + 解码”：这三步互不依赖，且不碰 Godot。`Ball` 几何与事实装配仍在单 worker 内顺序执行（第 5 步再评估是否拆分）。任一块失败立即取消其余 worker，只报第一个错误。

主线程装配阶段：

```text
WorldView 分步：
  a. 建 BallView 外壳（相机/材质/空节点）
  b. 颜色纹理按 3.2 万格一片烘，按片上报
  c. 每帧建 4–8 个 res0 块的 res4 网格 + res3 低档
  d. 河线按线批分片建
  e. 建拾取器、取景、应用初始模式
```

### 3.2 地理演化页生成

```text
MapGenerationPage 点「生成」
  → host.StartGeography(config)（现有入口不变）
  → AppRoot 实例化 WorldGenWorld，注入 (config, progress, onFailure)
  → WorldRoot._Ready:
      只绑定节点与参数（快）
      op = progress.Begin(Modal, "生成世界")
      CallDeferred → 下一帧开始
  → 工作线程：WorldGenerationJob.Run(spec, res, radius, op, token)
      建 Sim → 板块 → 地形 → 气候 → 水文 → 索引
      按管线阶段与气候子阶段上报
  → 主线程：WorldManager.Adopt(sim, state, solver)
      → 发布 WorldFacts（唯一发布点仍在主线程）
      → Render 分帧装配（复用 3.1 的分步，全程 Modal 到完成）
      → UI → 菜单 → op.Complete()
  → 失败：op.Fail → onFailure → 回配置页并提示（现有行为）
```

要点：`WorldGenSimulation` 已注明“引擎耦合必须为零”，演化会话也已在工作线程运行 `PrepareEvolution` + 气候/水文/索引，说明纯逻辑后台化有现成先例（`scripts/Scene/Evolution/WorldEvolutionSession.cs:125-141`）。

### 3.3 演化播放 / 单步 / 跳转

```text
WorldEvolutionSession.Start(targetStep)
  → operation = new LoadOperation("演化计算")   // 由独立面板渲染，不经 AppRoot 浮层
  → 工作线程:
      for step = current+1 .. target:
          CalculateToStep 单步（现有）
          operation.Report(step / totalSteps, $"构造步进 {step}/{total}")
      operation.ReportIndeterminate("世界重建")
      PrepareEvolution(...)
  → 主线程 Tick: 完成 → 禁用交互 → Publish → 分帧重烘（纹理/河线）
                  → operation.Complete() → 恢复交互
  → EvolutionPanel 每帧: ProgressView.Bind(session.Operation)
```

- 单步（total=1）：只显示阶段文字 + 已用时间 + 不确定态（步级粒度）。
- 跳转 N 步：按步推进百分比。
- **计算期间**：上一已发布帧保持完整可用——相机、点选、信息卡、地图模式切换都正常；只有播放/单步/跳转/倍率因忙碌禁用。模式切换会重烘颜色纹理，同样走每帧预算分片，不能把同步重烘留在计算期间。
- **完成瞬间**：先禁用交互，主线程发布候选帧并分帧重烘，进度条显示“应用新帧”，完成后再恢复交互（C8）。

## 四、架构与接口影响

### 4.1 新增/调整的契约（只到签名级，字段在第 3 步定）

```csharp
internal interface ILoadProgressSink
{
    LoadOperation Begin(string title);
}

internal sealed class LoadOperation
{
    public float? Progress { get; }          // 0..1；null = 不确定
    public string Stage { get; }             // 当前阶段文字
    public bool IsTerminal { get; }
    public CancellationToken Token { get; }

    public void Report(float? fraction, string stage);   // 线程安全
    public void ReportIndeterminate(string stage);
    public void Complete();
    public void Fail(string message);
    public void Cancel();
}
```

- `PageContext` 增加 `ILoadProgressSink Progress`（宿主注入；F6 单跑为 null）。
- 迟到提交/取消规则由 `LoadOperation` + `LoadOperationBinding` + `LoadCommitGuard` 实现（`scripts/Scene/Navigation/LoadCommitGuard.cs`）；`LoadOperation` 同时是唯一的进度真源，不另起一套状态机。
- 页面加载：页面拿不到 `LoadingOverlay` 类型，只拿 sink；进度层由 `AppRoot` 创建。
- 演化计算：`WorldEvolutionSession` 只发 `WorkSignal`；`GeologyPanel` 自己的观察操作订阅后经邮箱显示，不经过 AppRoot 浮层。
- `LoadProgressView` 是可复用的进度视图子场景（进度条 + 阶段 + 百分比 + 已用时间）；`LoadingOverlay` 与 `EvolutionPanel` 各自实例化它，保证两处显示逻辑只有一份。
- 进度显示是观察者：`LoadOperation.Subscribe` 在锁外投递不可变快照，UI 侧用 `LoadProgressMailbox` 收件并在主线程消费；不再逐帧轮询操作状态。

#### 4.1.1 信号解耦（第 5 步返工）

生成/读取/演化不再接收进度回调，改为发领域信号：

```csharp
// World.Data.Work —— 不引用 Scene / LoadOperation / Godot
public enum WorkSignalKind { StageStarted, UnitCompleted, StageCompleted, JobCompleted, JobFailed }
public readonly record struct WorkSignal(WorkSignalKind Kind, string StageId, string Stage,
    long Done, long Total, string Message);
public interface IWorkSignalSource { event Action<WorkSignal> Signal; }
```

- `WorldGenSimulation` / `WorldGenerationJob` / `MapBrowseJob` / `WorldEvolutionSession` 只发 `WorkSignal`。
- `LoadProgressMonitor`（Scene）独立订阅信号源，按 `LoadStagePlan` 推进 `LoadOperation`；可 `Attach/Detach/Dispose`。
- 不创建监控器时，生产照常运行；生产者不知道监控器存在。
- 浏览/生成/演化分别由 `AppRoot`、`WorldRoot`、`EvolutionPanel` 创建监控器并指定进度区间（浏览 0–0.75、生成 0–0.70、演化 0–1）。
- 验收：`WorldGenerationJob.Run` 参数不含 `LoadOperation`/`ILoadProgressSink`；`World.Logic`/`World.Data.Work` 不引用 `World.Scene`。

### 4.3 线程规则（硬约束）

- 工作线程只允许：`System.*`、H3 纯函数、`World.Data`/`World.Logic` 的纯数据类型；禁止 `GD.*`、`Node`、`Resource`、`Image`、`Material`、`RandomNumberGenerator`（Godot 版）。
- 工作线程返回的必须是纯数据（数组、纯 C# 对象）；主线程负责转成 Godot 对象。
- 完成/失败只通过 `LoadOperation` 状态表达；主线程轮询，不在工作线程里发信号。
- 取消令牌贯穿每个块、每个阶段、每个分片；退出应用或演化页卸载先取消再释放。

### 4.4 F6 单跑与无宿主

- `PageContext.IsStandalone` 为真时 sink 为 no-op；`WorldRoot` 仍走异步路径但不显示进度（或退回同步初始化，二者取一，第 5 步按测试结果定）。
- `MapBrowser` 单跑仍显示“没有地图数据”，不引入隐式加载。

## 五、进度模型

- **浏览**：读包/清单与并行解码按“已完成块数 / 总块数”（可换算字节）；事实装配按子阶段；渲染按块/纹理片/河线批。总进度 = 已完成加权阶段 / 总权重。
- **生成**：板块、地形、气候（含子阶段）、水文、索引、渲染六段加权（权重用本机 res4 实测校准，写入常量并注明基线）。
- **演化**：按步计数；单步内不确定态。
- 规则：单调不回退；阶段文字与真实阶段一致；无法细分显示不确定态；完成瞬间 100%。
- 浏览与生成的进度层全程 Modal：挡住相机、点选与模式切换，完成即隐藏并开放；演化面板内进度条不挡查看，计算期间地图完整可用，仅完成瞬间短暂禁用并分帧重烘。
- 演化面板内进度条直接绑定会话操作，样式与 `LoadProgressView` 相同。
- 权重是“估算工作量”，不是定时器；F1 抽检以加权阶段为准，并在第 6 步报告校准依据。

## 六、并行解压/解码（A）

- 每个 worker 使用独立 `FileStream` + `ZipArchive`，避免共享流 seek 竞态；中央目录各自解析一次。
- 数据块按清单顺序切分给 N 个 worker（N=4–8，按核数与内存定），每块：解压 → SHA-256 → 解码，结果按块 id 归位。
- 进度按“已完成块数 / 总块数”，阶段文字带块号；块大小已知，可换算字节。
- 任一块失败或取消：取消其余 worker，只上报第一个错误；已分配缓冲释放。
- 全局校验语义不变：每块 SHA-256 仍校验，清单/目录/引用/解码结构校验仍执行；只是并行，不跳过。
- 内存：块缓冲解码后立即释放；峰值约为“最终数组 + N × 最大块”。并发数按峰值上限回收。
- 不做：跨块合并解码、跨机分布式、缓存解码结果。

每项独立可验证；3 依赖 2 的读包入口，可在 2 之后单独合入。

## 八、依赖与前置

1. **H3 并发验证（先做）**：现有演化会话已在工作线程跑 H3，但仍需一个对照测试（同输入主线程 vs 工作线程，结果逐字节一致）才能把生成与导入也搬过去。不通过则启用兜底 B。
2. **帧预算基线**：本机 8 ms/帧预算需在第 0 项实测后确认（渲染分片大小按它定）。
3. **进度层视觉**：沿用现有主题（`themes/ui_app.tres`）；页面加载用 Modal 遮罩，演化面板用内嵌条，第 4 步前定稿。
4. **第 3 步数据结构**：`LoadOperation` 字段、阶段权重常量表；本步不写。

## 九、风险与兜底

| 风险 | 触发信号 | 兜底 |
|---|---|---|
| H3/纯逻辑并发不安全 | 对照测试结果不一致或崩溃 | 生成与导入退回主线程时间片（方案 B）；浏览仍可后台化非 H3 部分 |
| 工作线程误碰 Godot API | 崩溃/断言/随机挂起 | 代码边界评审 + 仅允许 `World.Logic`/`World.Data` 类型；CI 静态检查关键字 |
| 分帧装配仍超 200 ms | 帧时间探针报警 | 减小每片规模；把纹理烘焙移到工作线程（仅颜色字节，主线程建纹理） |
| 取消/释放竞态 | 退出或离开演化页后崩溃、泄漏 | 每层检查 token；完成后校验页面实例有效；测试覆盖“退出应用取消”与“演化页离开取消” |
| 进度不真实 | 抽检 50% 与实际不符 | 权重按实测校准；无法细分用不确定态；第 6 步公开校准表 |
| 并行解压结果错位 | 解码数组与块 id 不对应 | 每 worker 独立 zip 流；结果按清单块 id 归位；与单线程产物逐字节对照 |
| 生成结果漂移 | 哈希与现状不一致 | 后台化不改算法；对照测试以现有产物哈希为基线 |
| 页面加载不可取消 | 加载卡死时只能强退 | 用户已确认 1B；错误路径必须收敛并给出错误码；退出应用时取消与释放；记录启动/失败日志便于定位 |
| 计算期间切模式触发同步重烘 | 帧探针在模式切换时报警 | 模式重烘走分片；若仍超预算，模式切换临时排队到本步计算结束（需回到第 1 步改 C7） |
| 新帧重烘超 200 ms | 帧探针在切换时报警 | 纹理/河线分片；分片期间保留旧纹理，完成后替换；仍超则接受短暂禁用但记录实测 |
| 冻结输入被误判为卡死 | 用户重复点击/强退 | 遮罩上显示阶段、百分比、已用时间；进度持续更新 |
| 渲染分片破坏 LOD/拾取 | 画面缺块、点选偏移 | 分片只负责“创建同一批对象”；几何函数不变；回归截图与拾取测试 |
| 演化面板场景化后反向依赖页面 | 面板引用 `WorldRoot`/`WorldGenWorld` | 面板只接收 `LoadOperation` 与 `WorldFacts` 的只读口；依赖由 UIManager 注入 |
