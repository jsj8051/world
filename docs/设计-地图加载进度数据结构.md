## 一、类型清单

| 类型 | 形态 | 负责 | 不负责 |
|---|---|---|---|
| `LoadFlow` | enum | 标识加载入口：浏览、生成、演化 | 不携带进度 |
| `LoadState` | enum | 操作生命周期状态 | 不携带失败详情 |
| `LoadOperation` | 可变类（线程安全） | 进度、阶段、状态、取消令牌的唯一真源 | 不持世界数据、不碰 Godot 对象 |
| `LoadProgressSnapshot` | 只读结构 | 给视图轮询的一份不可变快照 | 不回写操作 |
| `LoadFailure` | 只读记录 | 失败码、阶段、消息 | 不做错误分类映射 |
| `ILoadProgressSink` | 接口 | 页面加载创建操作的入口 | 不负责渲染进度 |
| `LoadStage` / `LoadStagePlan` | 只读记录 | 阶段标识、显示文案、权重 | 不执行阶段 |
| `EvolutionProgress` | 只读记录 | 演化按步进度的计数 | 不保存帧 |
| `FrameSwapState` / `FrameSwap` | enum + 只读记录 | 新帧发布后的“冻结 → 重烘 → 恢复”状态 | 不持 `WorldFacts`、不建网格 |
| `WorkSignal` / `IWorkSignalSource` | 领域信号 | 生产侧上报阶段/完成量，不认识进度/UI | 不推进进度、不持有操作 |
| `LoadProgressMonitor` | 可选观察者 | 订阅信号源并推进 `LoadOperation` | 不生产信号、不持世界数据 |

不设缓存类型：A 决定不做校验缓存，重复打开仍走完整校验与完整解码。

## 三、关系与基数

- `ILoadProgressSink` 1 — 0..1 个非终态 `LoadOperation`（页面加载串行）。
- `LoadOperation` 1 — 0..1 个 `LoadFailure`（仅 Failed）。
- `LoadOperation` 1 — 1 个 `LoadStagePlan`（浏览/生成）或 1 个 `EvolutionProgress`（演化）。
- `WorldEvolutionSession` 1 — 0..1 个 `LoadOperation`；`EvolutionPanel` 0..1 绑定。
- `FrameSwap` 1 — 1 个 `LoadOperation`（仅重烘期间）。
- `LoadProgressMonitor` 1 — 1 个 `LoadOperation`，0..1 个已订阅的 `IWorkSignalSource`；可独立创建/销毁。

## 四、不变量

1. **进度单调**：同一操作内 `Progress` 只增不减；`[0,1]` 内；完成必为 1。
2. **终态不可变**：`Completed/Failed/Cancelled` 一旦进入，不再接受任何状态或进度变化；`Version` 只增。
3. **失败完整**：`Failed` 时 `Failure` 非空且 `Code/Message` 非空。
4. **快照一致**：`LoadProgressSnapshot` 的字段必须来自同一 `Version`，不得出现“旧进度 + 新状态”。
5. **单一活动操作**：同一 sink 同时最多一个非终态操作；新操作必须等旧操作终态。
6. **阶段真实**：`Progress != null` 时 `Stage` 非空；进度不得在没有阶段推进的情况下跳变（由生产者遵守）。
7. **权重合法**：每份 `LoadStagePlan` 的 `Weight > 0`、`TotalWeight ≈ 1`、`Id` 唯一、阶段数 2–8。
8. **演化计数**：`0 ≤ CompletedSteps ≤ TotalSteps`，`TotalSteps ≥ 1`；`SingleStep` 时 `Progress == null`。
9. **换帧互斥**：`FrameSwap` 同一时刻只有一份；`Freezing/Rebaking` 期间输入禁用；`CompletedSlices ≤ TotalSlices`。
10. **不持久化**：本轮所有加载类型只存在于运行期；不新增 `user://` 文件，不改 `.wmap`。
11. **生产/监控分离**：`World.Logic`、`World.Data.Work`、生成/读取/演化生产侧只发 `WorkSignal`，不引用 `LoadOperation`/`ILoadProgressSink`/UI；监控器可不存在。

## 五、标识与生命周期

- **LoadOperation**：`Guid` 在 `Begin` 时生成，不持久化；终态后由视图解绑并等待 GC；`Token` 随操作存活。
- **LoadProgressSnapshot**：每次轮询现造，生命周期一次读取。
- **LoadStagePlan**：静态只读，进程生命周期；不重建。
- **EvolutionProgress**：每次上报现造；不缓存。
- **FrameSwap**：一次发布一份；`Completed/Failed` 清理后回到 `Idle`；无 Id。

## 六、状态机

### 6.1 LoadOperation

```text
创建(Running)
  ├─ Report(progress, stage) → Running（进度单调）
  ├─ Complete() → Completed（Progress=1）
  ├─ Fail(failure) → Failed（Failure 必填）
  └─ Cancel() → Cancelled（Token 取消）

Completed / Failed / Cancelled → 任何事件：忽略（终态吸收）
```

| 当前 | 事件 | 目标 | 效果 |
|---|---|---|---|
| Running | `Report` | Running | 更新 `Progress/Stage`；小于当前值则钳到当前值 |
| Running | `Complete` | Completed | `Progress=1`；`Version+1` |
| Running | `Fail` | Failed | 写入 `Failure`；`Version+1` |
| Running | `Cancel` | Cancelled | 取消 `Token`；`Version+1` |
| 任意终态 | 任意 | 不变 | 无操作 |

非法输入（NaN/Inf、越界、空阶段）由生产者错误处理：抛 `ArgumentOutOfRangeException`/`ArgumentException`；终态后的上报不抛，静默忽略（容忍后台线程竞态）。

### 6.2 FrameSwap

```text
Idle → Freezing → Rebaking → Completed → Idle
         └──────────┴────────► Failed → Idle
```

| 当前 | 事件 | 目标 | 效果 |
|---|---|---|---|
| Idle | `BeginSwap` | Freezing | 禁用输入；准备发布 |
| Freezing | `FactsPublished` | Rebaking | 开始分片重烘 |
| Rebaking | `SliceDone`（未完成） | Rebaking | `CompletedSlices+1` |
| Rebaking | `SliceDone`（最后一片） | Completed | 进度 100% |
| Freezing/Rebaking | `Fail` | Failed | 恢复输入；报错 |
| Completed/Failed | `Cleanup` | Idle | 解除绑定 |

非法迁移（如 `Idle → Rebaking`）抛 `InvalidOperationException`，视为逻辑缺陷。

## 七、序列化 / 持久化

- **本轮不持久化任何加载状态**：进度、快照、失败、演化计数、换帧都只存在于运行期。
- 不新增 `user://` 文件；不做校验缓存、不做解码缓存、不做世界事实缓存。
- `.wmap` 文件格式、字段与逐块 SHA-256 校验语义不变。
- 因此没有缓存 schema、没有迁移脚本、没有回滚数据。

## 八、迁移

无。A 决定删除了唯一的持久化候选（校验缓存），本轮没有需要迁移或兼容的旧加载数据。

## 九、校验与错误形态

- `LoadOperation` 构造：`Title` 空/超长抛 `ArgumentException`；`Flow` 未定义抛 `ArgumentOutOfRangeException`。
- `Report`：NaN/Inf、越界抛 `ArgumentOutOfRangeException`；`Stage` 空抛 `ArgumentException`；终态后忽略。
- `Complete`：终态后忽略；`Fail`：`failure == null` 抛 `ArgumentNullException`；终态后忽略。
- `ILoadProgressSink.Begin`：已有活动操作抛 `InvalidOperationException`；`Evolution` 流抛 `ArgumentOutOfRangeException`。
- `LoadStagePlan` 静态构造：权重 ≤0、总和偏差 >1e-6、Id 重复、阶段数越界，均在类型初始化时抛，阻止进程带病运行。
- `FrameSwap` 非法迁移 → 抛 `InvalidOperationException`；失败必须回到 `Idle` 并恢复输入。
- 用户可见错误只经 `LoadFailure`；内部异常不直接拼进界面。
