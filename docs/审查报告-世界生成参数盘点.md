  的要求是"退化档区域粒度**逐字等于既有常量**（不得改成字面量——那样常量与默认档会分叉）"。
  保留**具名常量 + 等值断言**正是该测试的设计意图；内联成字面量会把它降级成"再抄一遍数字"。

### 1.5 ★顺手修复：`World.Tests.Local` 的悬空引用（**旧债，非本次引入**）

盘点时按纪律手工构建两个**不在 `world.sln`** 的项目，发现：

| 项目 | 结果 |
|---|---|

**根因**：`LandSeaParams` 已在 **2026-10-09 数据层迁移**中搬到 `World.Data`

⇒ 全限定名绕过 using，指向旧命名空间。**它不在 `world.sln` 里，所以 solution 门禁抓不到**

## §二 参数全景：三种角色（这是本次盘点的主结论）

扫描面 `scripts/Logic/{WorldGen,Data,Constant}/**/*.cs`（不含 `_removed/`）：
共 **89 条** `const` / `static readonly` 声明行（其中 **6 张 LUT/表**；成对写法如 `MinRadiusKm, MaxRadiusKm` 按 1 行计，
多声明行 1 行含 2 个常量）。

盘点后把全部常量按**角色**分三类——**这个分类比"数量"重要得多**：

| 角色 | 定义 | 是否应参数化 | 本仓实例 |
|---|---|---|---|
| **A 世界参数** | 决定"**这是个什么世界**"——尺度、气候、密度、阈值 | ✅ 是（`WorldSpec` 的最终归属） | `LandFraction` / `TargetRegionAreaKm2` / `BaseHeightM` / `PlateauTargetElevM` / `RiverThresholdAreaKm2` / `CoastDecayKm` …（约 **48 个标量 + 4 张表**） |
| **B 模型内部权重** | 决定"**算法怎么打分/迭代**"——改了是换模型，不是换世界 | ❌ 否，保持 `const` | `GeologicalRegions` 的 14 个打分系数 + `SoftmaxTemperature` + `LloydIterations`；`MountainSkeleton` 的峰垭带/细节幅度/转角尺度；三处**帽几何系数** |
| **C 结构·单位·词表** | 单位换算、派生端口 salt、LUT 曲线数据、表现线宽 | ❌ 否 | `Thermal`（4）·`SeedDerivation`（14 salt + `AllTags`）·`KelvinToCelsius`·`RiverSymbolWidth`（表现，9 行）·`PrecipitationModel` 两张 LUT |

★**为什么必须先分角色再谈合并**：`B` 类若被当参数暴露，症状是"用户改一个数就把类型分布搞崩"（配额/Softmax 失去可解释性）；
`C` 类的 salt 改了 = **换世界线**（同 seed 不再复现），这是存档级后果。⇒ 只有 `A` 类进并入参数化的讨论。

## §三 合并候选

### 3.1 ✅ 建议合并（有真实收益，共 2 处）

| # | 对象 | 现状 | 建议 | 收益 |
|---|---|---|---|---|
| **M1** | `TectonicField.TypeIntensity` | 硬编码 `switch`（7 个 `RegionType` → 强度，含 `_ => 0.3f` 兜底） | 抽成 `static readonly float[]`（按 `RegionType` 下标） | **形态一致**：同一个"RegionType → 值"映射，本仓已有两张表（`GeologicalRegions.TypeQuota[7]`、`BaseElevBandM[7]`），第三张却写成 `switch`。成表后①一眼看出"区域类型还有第三张映射表"②参数化时三种表可同批搬进 spec |
| **M2** | **帽几何公式**（真重复） | `GeologicalRegions.BuildBaseCaps` 与 `TectonicField.BuildIntensityCaps` **逐行相同**：`equiv = √(area/π)` → `σ = equiv × 1.4 / R` → `cut = 2.5σ` → `cutR²`；连 `BaseElevationAt` 与 `IntensityAt` 的 Shepard 帽核也同形 | 抽 `static` 纯函数（σ / cutR² 两个口） | ⚠️ **这是真重复不是同值巧合**：两处必须同步改，否则**基座场与构造场的帽范围错位**（症状：区域类型驱动的位置与基座插值范围对不上，且不报错）。两个消费者 ⇒ 过防膨胀第③问 |

### 3.2 ❌ 不建议合并（同值 ≠ 同义）

| 对象 | 为什么不合并 |
|---|---|
| `RegionalLandforms.MaxBasinsPerLandmass = 2` ／ `VolcanoField.MaxPerLandmass = 2` | 数值相同是**巧合**：一个是"每陆块盆地数上限"（配套 `TypeQuota` 把 BASIN 压到 0.06，防内流盆地泛滥），一个是"每陆块火山数上限"（构造活动密度）。将来很可能分叉 |
| `MountainSkeleton.MinRangeSpacingKm(1400)` ＋ `ParallelAngleDeg(25)` | 虽只在同一条件里出现（`dist < spacing && dAz < angle`），但**各有独立物理含义**（"多远算近" / "差多少度算平行"）。合成一个"排斥强度"会丢掉可读性，且无法单独调 |
| `VolcanoField.MinSpacingKm(800)` ／ `MinRangeClearanceKm(600)` | **不同对象对**：前者"火山 ↔ 火山"，后者"火山 ↔ 山系锚点" |
| `RiverNetwork.RiverThresholdCells` ／ `RiverThresholdAreaKm2` | **都有意保留，但不是"冗余"**（D-10 口径迁移的**待接管双口径**）：`Cells` 是**拓扑口径**（只在固定 res 下有义，res1→res4 同一数字差 34 倍），`AreaKm2 = 70,800` 是**物理口径**（黄河量级，跨 res 可比）。⚠️ 实测：**`RiverThresholdAreaKm2` 在编零引用**——`PerfBench` 与 5 个测试文件全部直接写 `70_800.0` 字面量，`Generate` 的缺省是 `null`。⇒ 建议方向不是删它，而是**让调用点改用这个常量**（否则"单一真相源"没建立，改值要改 9 处） |
| `GeologicalRegions` 14 个打分系数 + `SoftmaxTemperature` | **B 类（模型内部权重）**——参数化它们 = 让用户直接改模型 |
| `SeedDerivation` 14 个 salt | **C 类（结构常数）**——改 = 换世界线 |

### 3.3 ⏸ 记下来、**本次不做**：参数化那一批的"逐对合并"

**Min/Max 值域对** 在参数化到 spec/面板时天然并入一个 `Range(min, max)`：

| 值域对 | 现在 | 参数化后 |
|---|---|---|
| `ContinentLayout.MinRadiusKm / MaxRadiusKm` | 2 常量 | 1 × `Range` |
| `ContinentLayout.MinCoastCx / MaxCoastCx` | 2 常量 | 1 × `Range` |
| `ContinentLayout.MinWeight / MaxWeight` | 2 常量 | 1 × `Range` |
| `VolcanoField.PeakTargetMinM / PeakTargetMaxM` | 2 常量 | 1 × `Range` |
| `VolcanoField.SigmaMinKm / SigmaMaxKm` | 2 常量 | 1 × `Range` |

**本次不建 `Range` 类型**：当前**零消费者**（无 spec 字段、无面板），撞防膨胀第③问「真实消费者？」。
⇒ 记为"**参数化那一批**"的既定形状，等 `WorldSpec` 真正扩到地形阶段时一起做。

### 3.4 合并的收益上限（诚实估计）

把 §3.1 两处 + §3.3 五对折算进去，`A 类`约 **48 个标量 → 约 42 条"可暴露参数"**（**约 -12%**）。
⇒ **合并解决不了"上百参数"**。真正的手段仍是上一轮已定的三件：
**按阶段分组（不是扁平滑杆）＋ `ParamDescriptor` 参数描述表（唯一真相源）＋ 分级暴露（Tier 1/2/3）**。
合并的价值在**形态一致 / 消除真重复**，不在减少条数。
