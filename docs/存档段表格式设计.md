# 存档段表格式设计（Chunked Archive）

> 2026-08-23 · 目标：根治"版本号=全局互斥锁"——加新系统不再 bump 版本、不再手工维护兼容列表。
> 适用：`.mpa`（MapArchive）、`.cmp`（CivMapArchive）；`.gmp` 为中间格式，见 §5 分期。

## 1. 背景与问题

现状两种模式都已接近极限：

| 格式 | 现状 | 痛点 |
|---|---|---|
| `.mpa` v5 | 固定头 + 10 个尾部扩展段，"剩余长度 ≥ 段长"探测 | 已踩坑 3 次（psi 段错位、strength 判断、河流段错位）；每加系统改读端 |
| `.cmp` v14 | 手工 `CompatibleArchiveVersions` 列表（5 版本）+ Peek 按版本 switch 跳字段（5 分支） | 版本号全局互斥：改一段 → 全档版本+1 → 兼容列表重写 |

**核心问题**：系统级兼容信息被压进一个全局版本号里，无法独立演进。

## 2. 段表容器物理布局（skeleton v9 / v17）

所有三种存档统一容器（magic 不变，靠版本号区分新旧格式）：

```
[4B]  magic           "MPA1" / "CMP1" / "GMP1"（不变）
[2B]  skeletonVer     .mpa=9（v9：CIVI 功能定性——STTL 删 Level 加条件，2026-08-23）, .cmp=17（v17：同上——聚集地功能定性，2026-08-23）
[2B]  reserved        （保留，当前 0）
[..]  数据区          各段依次排列（每段：[4B] segMagic + [2B] segVer + 数据）
[12B×K] 段表（文件尾部，ZIP 式尾目录）{ [4B] type | [4B] offset | [4B] length }
[12B] 尾目录          { [4B] 段表偏移(相对文件头) | [4B] 段表字节数 | [4B] tailMagic "CHKT" }
```

- **段表放文件尾**（ZIP central directory 风格）：写端顺序写头+数据区，边写边记录各段 offset/length，最后写段表+尾目录——**无需回填**；读端 `Seek(Length-12)` 读尾目录 → 定位段表 → 任意段 Seek 直达（随机访问）。
- **每段首 6 字节 = [4B] segMagic + [2B] segVer**（段内小版本）。字段增删只 bump 段内版本，骨架版本不动。
- **未知 type 跳过**：读端只认识注册表内的 type，遇到不认识 → 按 length 跳过，日志提示"检测到新段 type=X（未来版本），已跳过"。
- IO 层：从 Godot `FileAccess` 全面迁移到 `System.IO.Stream`（`BinaryWriter`/`BinaryReader`，小端序与 FileAccess 一致）——**存档往返因此可进单元测试**（旧约束：测试进程禁碰 FileAccess → 存档 IO 不可测；迁移后解除）。路径转换：`ProjectSettings.GlobalizePath("user://...")` → `File.Open`。

## 3. 段 type 注册表

type 用 4 字符 ASCII（可读、可 grep）。`[segVer]` 是段内版本，从 1 起。

### 3.1 `.mpa`（MapArchive）段

**原则：一系统一段，段边界 = 系统边界**——独立系统绝不合包（旧格式"河流段里嵌套湖泊/矿藏/土壤"的
长度探测正是错位 bug 根源；段表格式下每段独立存在性，缺段 = 现场重算，不再有任何段内探测）。

| type | segVer | 内容 | 说明 |
|---|---|---|---|
| `HEAD` | 1 | seed / radiusKm / n / minElev / maxElev / minTemp / maxTemp / minPrecip / maxPrecip / prograde / rotationSpeed / axialTilt | 固定字段汇总（原头部+自转参数） |
| `VERT` | 1 | 顶点单位方向 Verts（12n） | 必需段（缺 → 拒绝） |
| `ELEV` | 1 | 海拔场（4n） | |
| `TEMP` | 1 | 年均温场（4n） | |
| `PREC` | 1 | 年降水场（4n） | |
| `BIOM` | 1 | 生物群系（n） | |
| `OCEN` | 1 | 洋流 dirs 12n + warmth 4n + strength 4n + psi 4n | 段存在即蓝藻完整；psi 强制写满（null→补零，沿用 v4 教训） |
| `RIVL` | 1 | 河流级别（n） | 独立段（旧格式与 flow 合包，现拆开） |
| `RIVF` | 1 | 河流流向（4n） | |
| `RIVV` | 1 | 河流流量（4n） | |
| `LAKE` | 1 | 湖泊级别（n） | |
| `MINE` | 1 | 矿藏（n） | |
| `SOIL` | 1 | 土壤肥力（n） | |
| `MONO` | 1 | 季风强度（n） | |
| `MPRC` | 1 | 月降水（12n） | |
| `MTMP` | 1 | 月温度（12n） | |
| （未来） | | 任意新系统 | 注册新 type，独立段 |

> 读端语义：段缺失 = 旧档没有该系统 → 现场重算兜底（与项目"不信任存档"约定一致）。
> 例：旧档无 `OCEN` → OceanCurrent.Compute 现场算；无 `MONO` → 季风现场重算。

### 3.2 `.cmp`（CivMapArchive）段

| type | segVer | 内容 | 说明 |
|---|---|---|---|
| `HEAD` | 1 | seed / tick / years / rngState / cultKey / cultgKey / relKey / nextPolityId | 原 42B 头 |
| `NATR` | 1 | GameMapArchive.WriteBody 全量（自然层快照） | 复用现有 WriteBody/ReadBody，**零改动** |
| `TRIB` | 1 | 实体段（alive count + 部落表） | 沿用 CivArchiveSchema 清单驱动 |
| `LAND` | 1 | 土地挂钩：Cultivation n + CellOwner n + LockedUntil n | |
| `STTL` | 1 | 聚落段（NextHabitationId + Habitations[]） | |
| `WARS` | 1 | 战争段（Wars[]） | |
| `EVNT` | 1 | 文明事件段（tick + typeIndex + subject/target id + value） | 段缺失 = 无历史，读端兜底为空 |
| `STAT` | 1 | 国家档案段（EU4 式制度层持久状态：国库/稳定度/合法性/君主/都城） | 段缺失 = 空 → 自愈重建 |
| `PLAY` | 1 | 玩家会话段（0=无玩家；1=国家绑定 + 税率覆盖 + 待处理命令队列） | 读档续玩不丢 |
| `REFS` | 1 | 来源地图引用段（1B 有无 + u16 路径 + seed + 起始 tick；.sav 专属语义） | 普通 .cmp 不写 → 读端缺段 = 无引用 |
| （未来） | | 宗教传播/贸易网络/…… | 注册新 type |

> `.cmp` 的自然层不再与时间戳耦合：`NATR` 段可整体替换/重建，实体段独立演进而互不 bump。
>
> **`.sav`（2026-08-25 地图≠存档分层）**：与 `.cmp` 同段表布局（magic/版本相同），额外写 `REFS` 段（来源地图引用——"从哪张地图开的这局"）。门面 `SaveArchive` 读写经 `CivMapArchive`（`user://saves/` 目录），地图 `.mpa` 素材池与游玩存档彻底分层。REFS 读端暂只取路径（seed/起始 tick 布局保留供未来 UI 展示）。

## 4. 读端分发架构

```
Read(path):
  读 magic + skeletonVer
  if skeletonVer ≠ 当前版本 → 拒绝（旧档全删哲学——v1-v8/v1-v16 全部作废，无旧读端分支）
  else:
    读 segCount + 段表
    foreach 段 in 段表:
      switch (type):
        HEAD → 读固定字段
        ELEV → 读数组
        OCEN → 读洋流；缺失 → 标记"需现场重算"
        ...
        未知 → 按 length 跳过（LogService.Log 提示）
    读完后：对标记缺失的段执行现场重算兜底
```

- 段缺失/段损坏只影响该段，**不再导致整档错位**（每段 offset/length 显式，天然隔离）。
- Peek（列表摘要）：只读 `HEAD` 段 → offset 直达 → 秒开（比现在 Seek 跳顶点数组更简单）。
- 兼容策略改写：**不再需要 CompatibleArchiveVersions 列表**——`skeletonVer` 相同即骨架兼容；段级差异由"缺段 → 现场算 / 降级"处理。

## 6. 与现有机制的关系

- `MapArchive.Peek`（2026-08-23 新增）：读段表 → 取 HEAD 段（v9 起仅当前版本）；毫秒级。
- `GameMapArchive.WriteBody/ReadBody`：**不改**——`.cmp` 的 `NATR` 段直接复用，保证自然层布局单一来源。
- `CivArchiveSchema`：继续作为 `TRIB` 段的字段清单驱动（单源防漏字段），只是写入目标从"文件流"变为"段内流"。
- 现场重算兜底（流域/月风/洋流）：段缺失触发条件不变，只把"字段不可用"改为"段不存在"。
