# 17 · 世界管线每步开销重构 · 立项草案（v0.1，2026-09-28 深夜）

> 性质：**立项草案**（先设计文档 → 用户判读拍板 → 再写代码）。与 `13-GPU解算器立项` 并列，互不替代。
> 上游实测：`16-B路线结项与res5目标量化`（四点曲线 / L3 交叉检验 / 串行对照 / 三腿同窗表）。

## 0 入口（一句话）

res5 每宏步的**非解算部分**实测外推 **46-70 s/步**（解算器即便免费也不够）⇒ 目标 4 s/步 的瓶颈已从"解算器"转移到"**每步世界管线的访存模式**"。本立项针对后者：**把每格开销拉回缓存内线性区 + 削减每格常数**。

## 2 目标与测量项（★不设达标线，完成度由用户对照判读）

**目标**：使 res5 每步非解算开销 **数量级下降**（方向：回到"每格开销不随规模恶化" + 常数下降）。

**测量项（每期都要复测并贴原始行）**：
1. 每格 µs/格 @ res2/res3/res4（同法 `--profile`、3 步、剔事件步）；
2. 工作集估算（活跃数组字节数 × 格数）与 L3/L2 比值；
3. 分项占比（⑥/③/②b/⑤…）与每项每格成本；
4. 逐位可复现性：`--dumphash` 13 支（**红线**：改造前后必须逐位一致，除非该期明确声明"这一步允许改数值路径"并单独拍板）；
5. 墙钟**只作参考**，且必须**同批基线**（已登记纪律）。

## 3 分期（每期独立可判、可停）

| 期 | 做什么 | 交付 | 判据（跑前写死） |
|---|---|---|---|
| **P0 诊断打点** | 给三大头加**分段计时 + 访存量打点**（纯计数，不改数值路径）；做"按每格邻居访问数/池数归一"的重测，排除 res4 内容差异 | 打点表 + 归一曲线 | 打点关闭时 13 支逐位同；打点自身开销 <2% |
| **P1 融合 + 空间填充序** | ① 每格 map 类工序**融合成一遍**（读一次、写一次）；② 按**空间填充序**（H3 邻接近似）重排格序，使邻居在内存中邻近 | 重排 + 融合后的地图型 pass | 13 支逐位同（重排需保证归约序确定）；每格 µs 下降（实测） |
| **P2 顺序段改确定性归约** | ③ 通量运输（owner 字典 gather/scatter + 子步）→ **按来源分块私有 + 定点序合并**；6.4/6.5 的 scatter-add → 分块私有 delta 后合并 | 改写后的两段 | 13 支逐位同；段耗时下降（实测） |
| **P3 事件步** | 裂解步回落生产式 CG 全解（单价 ≈90× 常规步、占比 12.5% 代价）⇒ 单列并给可选降级路径 | 事件步专项读数 | 事件序列与现档一致 |

## 5 明确不做

不改方程/本构、不动解算器算法（那是 `13`/`14-1` 的范畴）、不加线程当卖点、不在本立项内跑 res5、不做"输出端限幅/截断"类补丁。

## 6 ★我方先给初值处（供否决）

1. **P1 先做"融合"还是先做"空间填充序"**：我给的是**融合优先**（不动数据序、风险小），重排放在融合之后；
2. **空间填充序候选**（H3 父格递归序 vs Morton 近似）：我先倾向**父格递归序**（与 H3 层级天然一致），但**未测量前不定死**；
3. **P2 的范围**：我先只列 ③ 通量运输 + 6.4/6.5 scatter-add，**不含** ②b 段一 Gauss-Seidel（那属解算器轴）。
