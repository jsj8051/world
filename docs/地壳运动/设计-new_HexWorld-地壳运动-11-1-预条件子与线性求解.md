## 1 现状（代码事实）

**系统**（`H3ThinSheet.Solve` → `SolveCg`）：

```
A x = b,   x = 逐格切向速度的 2 分量 (a,b)，格内基 (tu,tv)
A = Σ_边 K_k · P_k (Δ·) + gauge·I        （P_k = 切平面投影 I − r̂r̂ᵀ 在边中点）
b = −∇E_GPE·A_i / 缩放
```

**求解流程**（现状）：

| 环节 | 实现 | 位置 |
|---|---|---|
| 外层（非线性） | Picard：解 → 0.5 欠松弛 → 逐边应力帽 → 查速度更新收敛 | `Solve` :211-248 |
| 内层（线性） | 矩阵自由 CG，**Jacobi 对角预条件** | `SolveCg` |
| 预条件子 | `diag[i] = gauge + Σ_{k∈格i} K_k`（**标量**），`z = r/diag` | `SolveCg` :302-329 |
| 判敛 | `‖r‖/‖r₀‖ < CgRelativeTolerance² = 1e-6`（预条件残差） | `SolveCg` :358 |
| 上限 | `CgMaxIterations = 400` | 字段默认值 |

**实测成本**（res3，`--profile=1`）：

- `SolveCg` = **356.2 s / 5 步**（99.15% 的整步）；
- **CG 迭代 360.1 次/调用（峰 400），触顶 4/12 次**；
- 达到的相对残差 **均 1.704e-3**（最好 1.004e-3 = 恰好达标，最差 6.223e-3）；
- 每个 Picard 轮一次 CG ⇒ **12 × 360 = 4 320 次线解/步**。

## 2 病态来源（三条，均为结构性）

1. **K 跨 3 个数量级且逐边跳变**：弹性上限 `kBase = 2μ_yr·h·W`（μ = 3e23 Pa·s 档）与屈服地板 `K(η_ch) = 2·(1e20/3.156e7)·h·W`
   ⇒ 比值 ≈ 3 000；而**实测 44% 的边（峰 49%）正落在帽上**。A 的条件数被 K 的动态范围直接绑定。
2. **投影各向异性**：每条边只沿**自己的切向**耦合（rank-1 的 `P_k`）；格内两个自由度在 6 条边方向上的投影不同 ⇒
   **标量对角预条件把两个自由度当同一个刚度**，方向信息全丢。
3. **内层精度与外层需求脱钩**：外层判据是「速度更新相对范数 ≤ 1e-3」，内层却固定解到 1e-3 相对残差
   ⇒ 经典**不精确牛顿**问题，标准解是 forcing term 自适应容差，而不是固定容差。

> 另注（不在本批）：Picard 恒定 12 轮 + 每轮 CG 逼近触顶 ⇒ 外层实际在「被 400 轮截断的近似解」之间摆动。
> 治本手段之一是让帽软化**连续**（K 不再分段跳变），但那是**本构 = 物理**，超出本批授权（见上级 §9 否决项 6）。

## 3 方案（三步，按收益/风险递增）

### 3a 精确逐格块对角预条件（必做，低成本）

把标量对角换成**2×2 精确块对角**：

```
D_i = gauge·I + Σ_k K_k · (t̂_k t̂_kᵀ)|_格i      （2×2 对称正定，闭式求逆）
```

- 每条边在格 i 基下的方向 `t̂_k|_格i` = `(_edgeUnit[k]·tu[i], _edgeUnit[k]·tv[i])` —— **构造期算一次**（新增 2 float/有向槽）；
- 闭式求逆：`D⁻¹ = (1/det)·[[d22, −d12],[−d12, d11]]`，`det = d11·d22 − d12²`，`det` 加下限保护；
- **改哪一行**：`SolveCg` 里 `diag[i]` 的构造（:302-311）与 `_za/_zb` 的预条件应用（:322-328 / :353-357）。
- **落地前提已核对（2026-09-24）**：逐格切面基 `_tu/_tv`（`H3ThinSheet:87`）、逐有向槽 3D 切向 `_edgeUnit`（:91）**都在构造期就绪**；
  预条件子的构建/应用点就是 `_diag`（:99，注释已声明「CG 迭代内 edgeK 不变 ⇒ 每次 SolveCg 重算一次」）⇒ 2×2 版只需新增 **2 float/有向槽**（格基下的切向分量，≈2 MB）+ 每格 3 float 的块缓存，替换 `_diag` 的构建与应用两处，**不新增任何共享状态**。
- 预期倍数（**估算**）：迭代数 **1.3-2×**；成本增加 = 每格一次 2×2 求逆（O(N)，相对一次 Apply 可忽略）。

### 3b 重叠子域预条件（Schwarz，中等成本）

对每格取 1 环（7 格 = 14 DOF）拼局部矩阵、Cholesky 分解、施加局部解：

- **改哪一行**：`SolveCg` 的 z 更新（预条件应用）换成 `ApplySchwarz(r) → z`；新增构造期邻域表 + 每轮重建局部因子（K 每 Picard 轮变）。
- 成本：`N × 14³/3 ≈ 41k × 900 flops = 37 MFLOP/轮`；对照现状「一次 Apply = 123k 边 × ~20 flops = 2.5 MFLOP / 14 ms」⇒ 局部分解约等于 15 次 Apply 的算术量，**只有当它把迭代数降 3× 以上才净赚**（必须实测 M-2）。
- 预期倍数（**估算**）：迭代数 **2-4×**（相比 3a 再叠一层）。

> ⚠️ **分辨率纪律（关键的选型判据）**：**无粗空间的重叠子域预条件，迭代数仍随分辨率增长**（子域固定为 1 环 ⇒ 只买到常数因子）。
> ⇒ 3a/3b 的组合足以让 **res3 达标**，但**不足以让 res5 分钟级**。res5 唯一出路是**两级/多重网格**（聚合粗空间 + 1 环平滑子域，迭代数 ≈ O(1)），
> 即上级 §9 否决项 1 的升级分支。若 res5 是硬指标，**批次 1 应直接选聚合多重网格**，否则 3a/3b 会在 res5 上作废。

### 3c 内层容差自适应（forcing term，与 3a/3b 正交）

```
η_k = clamp( γ · ‖Δu_k‖ / ‖u_k‖ , η_lo , η_hi )     ← **实现采用式**（2026-09-24 落地，见 §8.2）
本轮 CgRelativeTolerance = η_k        （η 越大 = 内层解得越松 = CG 迭代越少）
```

- **实现采用 `‖Δu_k‖/‖u_k‖` 而不是相邻两轮的 Δ 比值**（本文件 v0.2 写的是后者）：两者的区别是**与外层判据同源**——
  外层（`:261`）正是在 `updateNorm ≤ tol²·scaleNorm` 判收敛，即同一个比值 `sqrt(updateNorm/scaleNorm)`；
  取 γ = 0.9 使 η 始终贴着外层的实际需求走：外层快收敛（比值 → 1e-3）时 η 自然落到 `η_lo = 1e-3` = 现状档。
  零新增物理量（外层循环本来就在算这两个量），且**末段精度自动与现状一致**。

- **★方向纪律（本文件 v0.2 曾把 min/max 写反，2026-09-24 修正）**：η 是「相对残差降幅目标」，**η 越大越松**。
  现状固定 η = `CgRelativeTolerance` = 1e-3（最紧档）。自适应只能**放松**，所以是**下界锁死**：
  `η_lo = 1e-3`（**不低于现状**——永不比现状更紧，代价方向安全）、`η_hi = 0.1`（最松档；首轮与前期用）。
  ⚠️ 写成 `min(η_hi, …)`（旧版错误）会把 η 压到 ≤1e-3 ⇒ **CG 迭代反而变多** = 与目标相反。
- `‖Δu_k‖` = 现有量 `Math.Sqrt(updateNorm/scaleNorm)`（`Solve` :234-244 每轮已算）⇒ **零新增物理量**，只需把上一轮的值留到本轮循环头；
  首轮用 `η_hi`（还没有 Δ 比值）。
- 后期 Δ 比值自然衰减 ⇒ η 收到 `η_lo` = 现状档 ⇒ **收敛末段的精度与现状一致**。
- **改哪一行**：`SolveCg()`（`H3ThinSheet:301`）加一个容差入参，内部 `:376` 的 `tol = CgRelativeTolerance²` 改为 `tol = η²`；调用点 `:226` 传 η。
- 预期倍数（**估算**）：迭代数 **2-3×**。
- **会改变解**（判据 §6.2 已放宽）；`CgMaxIterations` 兜底 + 触顶计数（M-3）保证截断不静默。

## 6 风险与回退

| 风险 | 处置 |
|---|---|
| 预条件子破坏 SPD ⇒ CG 停滞 | 3a 的 `D_i` 由构造即为 SPD（`Σ K_k t̂t̂ᵀ ⪰ 0` + `gauge·I ≻ 0`）；`det` 加保护；实测 M-3 触顶次数若上升 = 立即回退到 `Jacobi` |

**回退方式 = 枚举/参数切回旧档**（不是删代码、不是加补丁）—— 旧路径始终保留为可选项，A/B 永久可用。

### 8.1 步骤 1 —— 2×2 块对角预条件（3a）

行号基准：`H3ThinSheet.cs`（629 行版，2026-09-24，埋点已在内）。

1. 新增字段（参数区 :43-52 旁）：`public enum Precond { Jacobi, Block2x2 }`（**只两档**——`Schwarz1Ring`/`AggMultiGrid` 不预先声明，3b 启用时才加；哑旋钮纪律，见复核记录 §末）、`public Precond Preconditioner = Precond.Block2x2;`
2. **构造期**（:133-159 建边表循环内）新增逐有向槽缓存（2 float/槽，≈2 MB）：
   `_edgeUnitCellA[w] = _edgeUnit[w].Dot(_tu[i]);  _edgeUnitCellB[w] = _edgeUnit[w].Dot(_tv[i]);`
   ★必须用 `_edgeUnit[w]`（该槽 i→j 的切向），**不要用 `_edgeRadial`**。
3. **D 构建**（替换 :337-344 的标量 `diag[i]` 循环）——逐格 i：
   ```
   float d11 = _gauge, d12 = 0f, d22 = _gauge;
   for (int k = o; k < e; k++) {
       float ua = _edgeUnitCellA[k], ub = _edgeUnitCellB[k], K = _edgeK[k];
       d11 += K*ua*ua;  d12 += K*ua*ub;  d22 += K*ub*ub;
   }
   _blockD[3i] = d11; _blockD[3i+1] = d12; _blockD[3i+2] = d22;
   ```
   ★**`meanDiag` 必须保留旧口径**（`gauge + Σ K_k`，另跑一趟求和）：现状标量 diag **不含投影权重**（等价于假设每边在格基下的切向范数 = 1）；
   若把 `meanDiag` 也换成 `(d11+d22)/2`，会连带改掉 `opScale`/`solScale`（缩放基准）⇒ 整个解的数值被搬动，A/B 无法归因。**2×2 只替换"预条件逆"，不碰缩放基准。**
4. **预条件应用**（**两处**：:357-359 初始化、:396-399 迭代内）：
   ```
   float s11 = _blockD[3i]*opScale + 1e-30f, s12 = _blockD[3i+1]*opScale, s22 = _blockD[3i+2]*opScale + 1e-30f;
   float det = s11*s22 - s12*s12; if (det < 1e-30f) det = 1e-30f;
   _za[i] = ( s22*_ra[i] - s12*_rb[i]) / det;
   _zb[i] = (-s12*_ra[i] + s11*_rb[i]) / det;
   ```
   ★SPD 依据：`D` 是二次型 `αu²+2βuv+γv²` 的系数矩阵 ⇒ `det = αγ-β² ≥ 0`（Cauchy–Schwarz）；ε 保护退化格。
   ★`rsOld/rsNew` 的求和式（:360、:399，`r·z` 口径）**不变**。
5. 步骤 1 单独验收（**先不动 forcing**，两批独立归因）。
6. **★覆盖口必须作用到全部薄席实例**（原实施单的遗漏，2026-09-24 移交后补上）：
   本项目有**三个** `new H3ThinSheet` 点 —— `H3DynamicTectonics:_driveSheet`（:711，逐宏步驱动）、
   `H3DynamicTectonics:_riftStrainSheet`（:1284，每 `StrainRefreshEverySteps` 解一次裂谷应变）、
   `HexDynamicDiag:_strainSheet`（:291，诊断自建，`--strain=1`）。
   只覆盖 `_driveSheet`，则**「旧档」跑里第二个解算器仍在用新档** ⇒ **A/B 不可归因**、且**回退口不完整**
   （`_riftStrainSheet` 的应变场经 `TrySplit` 的裂解种子回流进物理 ⇒ 回退必须能回到旧**数值**，不只是旧的求解器主体）；
   诊断实例不同口径则会污染 M-2/M-3/M-4（`SimProfile` 计数是全局的）。
   ⇒ 实现：共用方法 `H3DynamicTectonics.ApplySheetSolverOverrides(sheet)`，在两个实例的**使用点各自调用**
   （两实例都是 `??=` 懒建，使用点每次执行 ⇒ 覆盖不会漏）；诊断自建实例同口径。

### 8.2 步骤 2 —— 内层容差 forcing（3c）

1. `SolveCg()` → `SolveCg(float relTol)`；`:376` 改 `float tol = relTol * relTol;`
2. Picard 循环（:224）头：
   ```
   float eta = (pic == 0) ? ForcingEtaHi
             : MathF.Clamp(ForcingGamma * prevRatio, ForcingEtaLo, ForcingEtaHi);
   ```
   `prevRatio = sqrt(updateNorm_prev / max(scaleNorm_prev, 1e-30))` —— :234-244 已经在算这两个量，**只需把上一轮的值留到循环外保存**；调用点 :226 → `SolveCg(eta)`。
3. 参数：`ForcingEtaLo = 1e-3f`（**下界** = 不低于现状）、`ForcingEtaHi = 0.1f`、`ForcingGamma = 0.9f`。
   ⚠️**方向**：**η 越大越松**。写成 `min(...)` 会把 η 压到 ≤1e-3 ⇒ **CG 迭代反而变多**（设计 11-1 §3c 已标注此坑）。
4. 在步骤 1 之上再验收一次，看增量。

### 8.4 CLI（按现有 override 风格，`HexDynamicDiag` :78-91）

```
--precond=0|1     0 = Jacobi（现状档，永久保留 = 回退口） / 1 = Block2x2（本批默认）
```
