## 1 现状与为什么不能直接 `Parallel.For`

现在唯一的多线程设施是 `scripts/Utils/ParallelLoops`（确定性并行地图循环）：

- 只用于**地图型**核函数（写只落 `i` 自己的输出位，迭代间无读写耦合）；
- **约简型循环禁止走它**（浮点求和不满足结合律，调度一乱就破坏逐位一致；整数计数走线程局部 + 整数合并）。

薄席解算**全部串行**，而 `Apply` 恰是**散射累加**型，不满足地图型条件：

```csharp
// Apply（现状，逐边：j > i 槽位）
f[i] -= force;      // 同一目标格会被多条边反复 +=/−=
f[j] += force;      // 累加序 = 外层 i 的升序 + 各格槽位序 ⇒ 结果的一部分
```

⇒ 直接 `Parallel.For` 会让 `f[i]` 的累加序随调度变化：**每次运行结果都可能不同**（连"同 seed 同结果"都保不住）。
这不是「精度差异」，是**跨运行不确定**——判据红线（上级 §6.1-1）不允许。

**收益集中度**：`Apply` = 整步的 **89.6%**；薄席里其余子阶段合计 < 0.3%（体力 0.02%、帽 0.23%、应变率 0.03%、GPE 平滑 ~0%）。
⇒ **批次 2 的全部价值来自 `Apply` 的并行化**，其余循环并行化是顺带（可以先不动）。

## 2 方案 A（推荐）：`Apply` 改**纯地图型**——每格自算其全部有向槽

### 2.1 等价性论证

设格 i 的槽 k 指向 j，反向槽 k' 指向 i。代码在 `CapEdgesByYield` 里**同步维护对向槽位同值**（`_edgeK[_off[j]+back] = kNew`），
且 `_edgeRadial` 相同、`_edgeUnit` 反向 ⇒ 对同一条无向边：

```
t_k  = (v_j − v_i) − r̂ (v_j − v_i)·r̂         （沿 k 槽的切向差）
t_k' = (v_i − v_j) − r̂ (v_i − v_j)·r̂ = −t_k
K_k  = K_k'                                  （构造 + 帽更新保证）
⇒ force_k' = K_k' t_k' = −force_k
```

于是逐格视角下，格 i 的合力可以**只用自己的槽表**算出来：

```
f[i] = Σ_{k ∈ 格i 的槽}   s_k · K_k · t_k ,   s_k = (j > i ? −1 : +1)
```

（`j > i` 的槽给 −force，`j < i` 的槽给它的反向力 = +force）——**与现状逐位同源的代数，只是累加序不同**。

> ★ **前提已在代码核对（2026-09-24），不是假设**：`_edgeK` 的声明即写明「对向槽位同值」（`H3ThinSheet:95`），且 `CapEdgesByYield` 每轮同步维护对向槽
> （`(j,i)` 槽写同一个 `kNew`）；`_edgeRadial` 对向槽相同、`_edgeUnit` 对向槽反向（构造期一 basis 一次算出）。
> ⇒ 「K_k′ = K_k 且 force_k′ = −force_k」成立 ⇒ 逐格 map 式与现状**代数等价**。
> ⚠️ 反过来说：**「对向槽位同值」是本方案的正确性不变量**——将来任何只改单侧槽的代码都会静默破坏它 ⇒ 建议在本批加一条断言（Debug 下校验）或单测。

### 2.2 关键性质

| 性质 | 说明 |
|---|---|
| **零归约** | 每个线程只写自己负责格的 `f[i]`，**无原子、无跨线程累加、无需块缓冲** |
| **天然确定** | 每格的求和序 = 该格自己的槽表序（构造期固定）⇒ **与线程数、分块、调度完全无关** |
| **算术代价 ×2** | 每条无向边被算两次（两个方向各一次投影）。**但**：批次 3 的实测已证明逐边成本由内存往返主导而非 ALU（四个性质不同的循环单价同为 89-153 ns/边）⇒ 多一倍算术近似免费 |
| **与旧版差异** | 逐格内累加序变化 ⇒ 末位差（判据 §6.2 允许，不是红线） |

### 2.3 实现落点

> ★ **2026-09-25 开工前核查修正（性能专家）**：本节写作时的行号与结构已随批次 1/spike-a 漂移——
> `Apply` 现为**派发口**（`H3ThinSheet.cs:565`）+ `ApplyBaseline`（散射档，散射段 = **:588-605**）+
> `ApplyCompact`（spike-a 单侧紧凑档，11-1 §8.11）。下述「拆成三段」落在 `ApplyBaseline` 的散射段上；
> **map 型档与 spike-a 紧凑表正交**：map 型逐格遍历**自己的全部槽**（走 `_off`，非单侧 `_hOff`）。

- **改哪一行**：`H3ThinSheet.ApplyBaseline` 的第二段逐边循环（**:588-605**，散射）拆成两个地图型段：
  1. 段一（并行，地图型）：`vel[i] = tu[i]·a[i] + tv[i]·b[i]`（现状 :583-587，本来就是 map）；
  2. 段二（并行，地图型）：逐格遍历**自己的全部槽**，`f[i] += s_k·K_k·t_k`（无跨格写）；
  3. 段三（并行，地图型）：`f[i] += gauge·vel[i]`；`ra/rb = f[i]·(tu,tv)`（现状 :606-611，本来就是 map）。
  ⇒ 三段都走 `ParallelLoops.For`，且**段的边界不参与浮点累加**（段间只读 `vel[]`）⇒ 确定性由构造保证。
- ★ **口径细化（对 §4 dumphash 红线）**：指纹逐位对照**只在 PerCellMap-vs-PerCellMap 之间成立**
  （每格求和序 = 自己槽表序，与线程数/分块无关）；**Scatter-vs-PerCellMap 是 §6.3 的 1e-12 等价性门**、
  **不是**指纹对照——累加序不同 ⇒ 末位差经 CG 放大 ⇒ 轮数账可能 ±几轮、指纹必然不同（**预期内，非回归**）。
- `ComputeBodyForces` / `ComputeStrainRates` / GPE 平滑 / `CapEdgesByYield` 本来就是 map 型（逐格写自己的输出）⇒ 同一批接入 `ParallelLoops.For`。
- **`CapEdgesByYield` 顺带去掉 `FindBackSlot` 线性扫描**（现行 **:742 调用 / :750 定义**）：改逐**有向槽**自算（`stress_k = K_k·|t_k|` 与其反向槽同值 ⇒ 两侧独立算出同一个 `kNew`，不需要找对向槽）⇒ 少一趟 O(6) 扫描 + 去掉跨格写。
  ★此项**数值逐位同**（同公式同输入，"算一次写两槽"变"算两次各写一槽"）⇒ **拆为子步 2a 先行独立落地**，
  用现有 13 支指纹仪器做**逐位同**强验收，再上子步 2b（map 型）——两子步各自独立可验收、独立可回退。

### 2.4 分块与线程数

- `ParallelLoops` 已有 `MinCellsForParallel = 32 768` 门槛与 `WorkerCount = ProcessorCount`；
- **本批新增**：`For` 的并行范围**固定按常量块数划分**（`blockCount = WorkerCount` 固定），不依赖运行时调度器给出的动态分区 —— 这是「跨运行确定性」在框架层的兜底（即使将来加入归约型循环，划分也固定）；
- 调度开销账：`Apply` 单次 14 ms，`Parallel.For` 的分区 + 线程池往返 ~几十 µs ⇒ **< 0.5% 开销，可忽略**（对照：对薄席里 0.1 ms 级的小循环并行化则得不偿失，这也是本批只动 `Apply` 的原因）。

## 3 方案 B（备选）：固定分块归约

保留原散射结构，改成「B 份 `f` 缓冲 + 固定块序求和」：

```
每线程处理固定的有向槽区间 [b·S/B, (b+1)·S/B)，累加到自己的 f_b 缓冲
归约：f[i] = f_0[i] + f_1[i] + … + f_{B−1}[i]（固定块序 = 与线程数无关）
```

- 优点：保留原算式与累加结构（差异更小）；
- 代价：额外内存 `B·N·12 B`（B=8, N=41k ⇒ **4 MB**）+ 一遍归约读写（`B·N` = 328k 次加法 ≈ Apply 逐边量的 2.7×）；
- 结论：**方案 A 更优**（零归约 vs 2.7× 归约量）。方案 B 仅作为方案 A 等价性出问题时的备选。

## 4 跨运行确定性的**验证口**（本批必须落地）

判据红线需要可执行、可复现的验证手段，而"跑两次肉眼看数字"不够。新增诊断口：

```
HexDynamicDiag --dumphash=1
  → 每步对全部状态场（7 个质量池 + HeatDeficit + PlateId + Age + Displacement）
    按「场序 → 逐格 → 逐 float 的原始 4 字节」做 FNV-1a 64 位哈希，打印 16 进制
```

- **最小验证**：同 seed 同参数跑两次 ⇒ 每步哈希必须逐位相同；
- 也用于批次 1/2/3 之间登记「是否逐位一致」（批次 3 期望相同，批次 1/2 期望不同但差异只落在末位）。

## 6 验证方法（本批）

1. **M-6 跨运行逐位一致**（红线）：`--dumphash=1` 两次运行哈希对照；
2. **M-6 并行加速比**：`WorkerCount = 1/2/4/8` 扫描（同批次内 A/B），报实际加速比与拐点；
3. **等价性对照**：`ApplyMode = Scatter`（单线程）vs `PerCellMap`（单线程）⇒ 逐格 `f` 场的最大相对差应 **≤ 1e-12**（累加序差异的合理量级，用于抓"漏项/反号"这类真 bug）；若出现 O(1) 差异 = 代数等价性论证有洞；
4. M-8 物理量对照表 + M-9 全量单测。

## 7 风险与回退

| 风险 | 处置 |
|---|---|
| 等价性论证有洞（漏项/反号/边界五边格） | 第 6 节第 3 条的 1e-12 对照是**强制门**，先单线程对照通过再开并行；五边格（`Length==5`）与度为 6 的格同式，但对照要覆盖 |
| `PerCellMap` 的 2× 算术在 ALU 饱和的机器上反而是负收益 | M-6 实测；若单线程 `PerCellMap` 慢于 `Scatter` 超过 1.3×，方案作废改走 B |
| 并行后残留的隐式共享（`_gauge`/`_edgeK` 只读，安全；但 `f` 的复用缓冲要确认无跨段别名） | 段间加显式注释 + 对照测试 |
| `ParallelLoops` 引入归约型调用破坏确定性 | 框架层注释硬约束（既有）+ 本批新增固定分块；`dumphash` 红线每次跑 |

**回退 = `ApplyMode = Scatter`**（旧路径保留为枚举值，永久 A/B 可用）。
