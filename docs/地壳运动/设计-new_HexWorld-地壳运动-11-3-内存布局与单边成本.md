# 11-3 · 内存布局与单边成本（批次 3）

> 上级：[设计-11 薄席解算器性能二期](设计-new_HexWorld-地壳运动-11-薄席解算器性能二期.md) §4 批次 3
> 层级归属：P 过程层 · **纯实现**（`H3ThinSheet` 的边表布局与循环实现）·**可做到与前一版逐位同值**

---

## 1 现状：边表是五条平行数组

`H3ThinSheet` 的压平边表（构造期建一次，逐有向槽一列）：

| 数组 | 内容 | 每槽字节 |
|---|---|---:|
| `_nbi` | 邻居格号 | 4 |
| `_edgeUnit` | 切向单位向量 | 12 |
| `_edgeRadial` | 中点径向单位向量 | 12 |
| `_edgeDist` | 物理格距 | 4 |
| `_edgeK` | 刚度（**每次 Picard 轮被帽改写**） | 4 |

总有向槽 = **246 960**（无向边 123 480）。同一次 Apply 内这五条表被**同一个 `k` 同步索引** ⇒ 一次边访问触及 **5 条不同 cache line 的头部**。

## 2 实测单边单价与「本机标定」

| 循环 | 每个无向边的耗时 | 说明 |
|---|---:|---|
| `Apply`（投影 + 散射） | **113 ns/边** | 14.0 ms / 123 480 边 |
| `CapEdgesByYield`（~10 flops + `FindBackSlot` 线性扫描） | **110 ns/边** | 13.6 ms / 123 480 边 |
| `ComputeBodyForces`（梯度累加，无散射） | **89 ns/边** | 11.0 ms / 123 480 边 |
| `ComputeStrainRates`（含 `Length()`=sqrt） | **153 ns/边** | 18.9 ms / 123 480 边 |

**本机标定**（同进程内最简循环，用于判断"是机器慢还是代码慢"）：

| 循环 | 每格耗时 | 体内含 |
|---|---:|---|
| ①a 热亏缺累积（41 162 格 / 1.0 ms） | **24.3 ns/格** | 1 除 + 1 乘 + **1 `exp`** + **1 `sqrt`** + 1 存 |
| ①b 派生场刷新（41 162 格 / 2.1 ms） | **51.0 ns/格** | 派生 Age/PlateId 多场写 |

⇒ 本机的标定是「含 exp+sqrt 的格级循环 ≈ 24 ns/格」，**机器不慢**。
而 `Apply` 的 **113 ns/边**（≈ 4.5 倍于"一整格含两个超越函数"的代价）里没有任何超越函数、只有约 20 次浮点乘加 ⇒ **代码层面有 3-4 倍量级的空间**（**估算**，实测由 M-5 定）。

## 3 成因（三条，按贡献排序）

1. **依赖加载链**：`k → _nbi[k] → vel[j]`（指针追逐，第二跳的地址依赖第一跳的结果），
   加上 `_edgeRadial[k]`、`_edgeK[k]` 各自另起一条 line ⇒ 每条边 3-4 个独立 miss/半 miss 的加载。
2. **五条平行表 = 5 条 cache line**：虽然总字节数不变（约 9 MB），但**每条边的五个字段分散在 5 处**，
   顺序扫描时每槽必跨 5 条 line（预取器可以缓解但无法消除）。
3. **每次访问的边界检查 + Godot `Vector3` 逐分量运算符**：`_f[j] += force` 的散射（load-modify-store 到随机 `j`）
   还有 store-forward 冲突惩罚；这是 `CapEdges`（无散射）与 `Apply` 单价接近但仍都远高于预期的共同背景。

> 注：**`Apply` 单价 113 ns 与 `CapEdges` 110 ns 几乎相同**（一个含投影+散射、一个含线性扫描+除法）——
> 这种"不同算式同单价"的形态本身就是**每边固定开销主导**的证据（上级 §2.5-3）。

## 4 方案

### 4a 单条 `Edge` 结构（主力）

```csharp
struct Edge {                 // 每条有向槽一条记录（顺序扫描友好）
    public int   Nb;          // 邻居格号
    public float K;           // 刚度（每 Picard 轮被帽改写）
    public float Dist;        // 物理格距
    public Vector3 Unit;      // 切向单位向量
    public Vector3 Radial;    // 中点径向单位向量
}                             // 36 B → 按 40/48 B 对齐 ⇒ 1 条 cache line 覆盖一条边
```

- **改哪一行**：`H3ThinSheet` 的五个字段（:88-94）与全部消费点（`Apply`、`CapEdgesByYield`、`ComputeBodyForces`、`ComputeStrainRates`、构造 :132-159）；
- 预期倍数（**估算**）：**1.3-2×**（每边 line 数 5 → 1~2，依赖链少一跳）；
- 内存：`247k × 40 B = 9.9 MB`（与现状 9 MB 同量级，不新增压力）。

### 4b 去边界检查与冗余遍历

- `ref` 局部 + `MemoryMarshal.GetArrayDataReference`（去 `_off`/`_f`/`vel` 的每次下标边界检查）；
- `CapEdgesByYield` 的 `FindBackSlot` 线性扫描由**逐有向槽自算**取代（与 11-2 §2.3 同一改动：两侧槽独立算出同一 `kNew`）⇒ 去掉每边一次 O(6) 扫描；
- `Apply` 段三（`gauge` + `ra/rb`）与段二（`f[i]` 的逐格累加）**融合**成同一趟逐格循环（省一遍 N 长的 `f` 读写）。
- 预期倍数（**估算**）：**1.2-1.5×**（叠加在 4a 之上）。

### 4c **不做**的事（说明为什么）

| 想法 | 为什么不做 |
|---|---|
| 把投影换成预存的 2×2 张量 | `P = I − r̂r̂ᵀ` 的独立分量就是 `r̂` 的 3 个 float（12 B）——**没有比现在更省**；换成"格内 2D 基下投影"会丢掉跨面分量 ⇒ 改动数值（本批的卖点是逐位同值） |
| 段一（`vel[i]` 装配）与段二融合 | 段二需要**全部** `vel` 已算完 ⇒ 存在数据依赖，融合会改数值 |
| GPE 平滑与体力融合 | 平滑需要全部平滑值才能算梯度 ⇒ 同样的依赖 |

## 5 逐位同值纪律（本批的独特价值）

批次 1/2 都改变解的末位（判据 §6.2 已放宽），**只有批次 3 能做到与前一版逐位同值**——条件是：

1. **不改任何算式与运算顺序**（只改数据摆放与调用结构）；
2. 不用 `FMA`/`MathF.FusedMultiplyAdd`、不用 `Vector2/Vector4` 打包重写算术（打包会改逐元素语义的顺序）；
3. C# 不允许浮点重结合 ⇒ **纯布局改动下 JIT 的向量化不会改变逐位结果**（此行是有条件的期望，**必须用 `--dumphash=1` 断言**，不是先验保证）。

⇒ 批次 3 因此也是整条链的**不变量锚**：它的哈希应与批次 2 后版本**完全相同**（若不同 = 布局改动里混进了算式改动，必查）。

## 6 参数表（本模块初值）

| 参数 | 落点 | 初值 | 说明 |
|---|---|---|---|

| 边界检查消除 | 同上 | 开 | `ref` 局部 / `GetArrayDataReference` |
| 融合段二+段三 | 同上 | 开 | 逐格单趟 |

## 7 验证方法（本批）

1. **M-5 每边单价**：四个逐边循环各自的 ns/边（Apply / 帽 / 体力 / 应变率），与 §2 表格同口径对照；
2. **逐位同值**（M-6 的 `--dumphash=1`）：与批次 2 后版本**每步哈希完全相同** ⇒ 这是本批的强制门；不同则必须定位到具体算式差异；
3. M-1 同批次 A/B 墙钟 + M-8 物理量对照（应逐位相同 ⇒ 自然一致）+ M-9 全量单测。

## 8 风险与回退

| 风险 | 处置 |
|---|---|
| 布局改动里混进算式改动（哈希变化） | 哈希门 + `EdgeLayout` 枚举 A/B（旧档保留） |
| `StructEdge` 因记录较大反而降低预取效率 | 40 B / 48 B / 64 B 三档 A/B（M-5 定档） |
| `GetArrayDataReference` 的 unsafe 面 | 只在 `H3ThinSheet` 内部使用，不动公开 API；单测覆盖 |
| 逐位同值不成立（JIT 行为差异） | 若哈希不同且算式确未改，则记录在案并按判据 §6.2 用物理量对照验收 |

**回退 = `EdgeLayout = ParallelArrays`**（旧档永久保留）。
