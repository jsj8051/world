# 阶段3设计：派生状态架构化 —— 根治"读档续跑分叉"（T04）类 bug

> 2026-08-18 · 用户拍板方案 D（派生状态架构化）。**已实施完成**（本文件为设计+实施记录）。
> 背景：T04（读档续跑无分叉）反复出现。根因不是运气差，而是三处架构缺陷的必然结果。
> 目标：把"读档续跑无分叉"从"不断打补丁"变成"架构保证"。
>
> **实施结果（2026-08-18）**：7 步全部落地，全量回归 51 PASS / 5 FAIL（与重构前逐位一致，**零行为漂移**）；
> 新增 T04b 守卫 PASS；存档版本 bump v11（IsBigMan/IsChief/ChiefdomId 移出入档）；性能无劣化。

---

## 一、根因模式：三类状态混在一个 Context

`CivSimContext` / `Tribe` 里混着**生命周期不同的三类状态**，这是所有分叉的土壤：

| 类别 | 定义 | 例子 | 入档？ |
|---|---|---|---|
| **持久状态** | 跨 tick 有语义，是演化的"真身" | P、IsFarming、TechKeys、Cell、CellOwner、Cultivation、Rng、NextTribeId、各种 cooldown、key 计数 | ✅ 手写入档 |
| **派生状态** | 每 tick 从持久状态确定性重算，是"缓存" | FLast/FHunt/FHerd/FFarm/FBerry、CellF/CellPop/CellFarmPop、TerritoryCells/Dists/Id/Size、CarryMult、CapMask、ChiefdomId/Size、IsBigMan/IsChief | ❌ 不入档 |
| **统计/运行时** | 诊断输出或 GC 优化 | Fissions/Migrations/Conflicts、BfsStamp、KeyBuf、_liveIdSet | ❌（无所谓） |

### 三处架构缺陷（每个都能独立引爆 T04 类 bug）

**缺陷 1：派生状态被当"记忆"跨 tick 边界使用，tick 边界语义不清**
- `FLast` 是 **tick 内中间量**（Harvest Order 9 算出 → Growth/Energy/Prestige 同 tick 读），却存在实体字段上。
- 读档恢复的是"tick N 结束"的持久态，但 `FLast` 的"正确值"取决于从哪个方向看边界（N 内 Harvest 后？N+1 开头 RefreshCellState 前？）——**天然歧义**。
- 本次根因正是：Run 结尾的 `FLast`（末 tick Harvest 值）≠ 读档重算的 `FLast`（末态领地重算值），差 243 格 CellF → 种子压力门判定不同 → RNG 消耗不同 → 级联分叉。

**缺陷 2：重算路径不统一，演化与读档各写一套**
- 演化路径：每 tick `RefreshCellState` → 各模型（Influence→Harvest→…）
- 读档路径：`BuildLayer1` → `RebuildInfluence` → `TerritoryModel.Rebuild` → `RecomputeProduction` → `RefreshCellState`（手写拼装）
- 两套顺序/时机靠人肉保持一致，**任何一边漏一步 = 分叉**（本次漏了 Run 结尾重建领地、漏了空领地归零分量）。

**缺陷 3：存档字段清单手写，漏字段 = 分叉 bug**
- Write/Read 两处手写字段清单（当前 ~26 个实体字段 + 3 个格场）。
- 历史漏过：CultureGroupKeyCount（v6 才补）、NextTribeId（v8 才补）、酋邦层（v10 才补）、IsFarming 语义澄清……**每次都是靠 T04 红一次才发现**。

## 二、目标架构

### 2.1 核心原则

1. **派生状态 = 单一 tick 缓存**：生命周期明确为"本 tick 内有效"，由**唯一入口**在每 tick 开头重建；模型禁止读取"上一 tick 的派生值"（代码审查规则 + 编译期辅助）。
2. **单一重算入口**：`CivEngine.SettleDerived(ctx)` 是**唯一**重建派生状态的地方，演化每 tick 开头、读档后、Run 结尾都调它 → 三条路径代码上是同一个函数，不可能各写一套。
3. **持久/派生声明式清单**：字段分组集中在一张表（本文件 §4），Write/Read 由清单驱动生成 → 漏字段从"人肉风险"变"清单一眼可查 + 测试可验"。
4. **T04 升级为架构守卫**：保留 T04（读档续跑无分叉），新增 T04b（任意存档 tick 下，`SettleDerived` 重算 ≡ 内存态同 tick 派生值——纯函数验证）。

### 2.2 单一重算入口 `SettleDerived(ctx)`（已落地）

```csharp
// CivEngine.SettleDerived：唯一派生重建入口（2026-08-18 已实施，CivEngine.cs）。
// ⚠️ 实施中修正（设计稿依赖序有误）：ChiefdomModel.Rebuild 读取 FHunt/FHerd/FFarm（DomOutput）
//   与 IsChief/IsBigMan（凝聚条件）→ 酋邦必须在"派生产出"和"领袖派生"**之后**，不是之前。
public static void SettleDerived(CivSimContext ctx)
{
    RefreshCellStateCore(ctx);                       // ① CellTribes/CellPop/CellFarmPop/CarryMult/CapMask（幂等）
    ctx.RebuildInfluence();                          // ② CellOwner/TerritoryCells/Dists（内部含 RebuildTerritory）
    RecomputeProduction(ctx);                        // ③ FLast/FHunt/FHerd/FFarm/FBerry（先归零分量）
    for (...) DeriveLeadership(ctx.Tribes[i]);       // ③b IsBigMan/IsChief（Prestige+ReligionShare 纯派生）
    TerritoryModel.Rebuild(ctx);                     // ④ TerritoryId/Size
    ChiefdomModel.Rebuild(ctx);                      // ⑤ ChiefdomId/Size（读③ F 分量 + ③b 领袖 + ④ 领地）
    RefreshCellStateF(ctx);                          // ⑥ CellF 聚合
}
```

**调用点（三条路径同一函数）**：
- 演化 Run 结尾（RemoveAll 死实体后）
- 读档后（CivMapArchive.Read 结尾，取代旧手写拼装）
- Continue 结尾

**演化 tick 内流程保持现状**（RefreshCellState 开头 + Orders）——FLast 仍由 Harvest(9) 本 tick 算
（依赖本 tick Cultivate 更新的 Cultivation，不能移进 tick 开头）→ **零行为漂移**。

### 2.3 各路径统一走 SettleDerived

| 路径 | 现状（已落地） |
|---|---|
| **演化每 tick 开头**（CivEngine.Run 循环） | 保持现状 `RefreshCellState`（= Core + AccumulateGoods + F）——FLast 由 Harvest 本 tick 算 |
| **读档后**（CivMapArchive.Read 结尾） | `SettleDerived(ctx)`（取代手写拼装 BuildLayer1/RebuildInfluence/TerritoryModel.Rebuild/RecomputeProduction/RefreshCellState） |
| **Run 结尾**（CivEngine.Run 收尾） | `SettleDerived(ctx)`（RemoveAll 死实体后） |
| **Continue 结尾** | `SettleDerived(ctx)` |

> 设计权衡记录：原本考虑把 Influence/Territory/Chiefdom 从 Order 移到 tick 开头（数值漂移可接受），
> 实施中发现 **Harvest(9) 依赖本 tick Cultivate(6) 更新的 Cultivation**，FLast 不能移进 tick 开头；
> 且 tick 内 Influence(8) 本就用"上 tick 末 P/TechKeys"（Growth/Invention 在其后）→ 与边界态重算天然一致。
> 故采用**保守方案**：演化循环不动（零漂移），SettleDerived 仅作为边界态（读档/Run结尾/Continue）唯一入口。
> 这同样根治缺陷 ①（边界语义唯一化）+ ②（三条路径同一函数），只是不迁移 Order。

### 2.4 声明式存档清单（§4 是唯一真源）

- 新增 `CivArchiveSchema`：一个静态清单，按序声明每个持久字段（名称、读写函数、版本引入号）。
- `CivMapArchive.Write`/`Read` 改为**遍历清单生成/读取**（保持现有字节布局不变 → 存档格式版本仍 v10，无需迁移）。
- 校验：启动时清单字段与 `Tribe`/`CivSimContext` 反射比对（字段名存在性），字段新增时漏加清单 → 测试红。

## 四、实施步骤（每步可独立验证）

1. **拆分 RefreshCellState**：`RefreshCellStateCore`（纯派生）+ `RefreshCellStateF`（CellF 聚合）+ `AccumulateGoods`（副作用）。验证：T02 实体往返、T03 复现性、T20 全链确定性全 PASS，存档字节不变。
2. **新增 `SettleDerived(ctx)`**：按 §2.2 顺序实现，内部用步骤 1 的拆分函数。验证：在现 Run 结尾/Read 处替换现有手写拼装（等价替换，先不迁移 Order），全量回归数值与当前一致（T04 保持 PASS）。
3. **迁移演化循环到 SettleDerived**：Run 每 tick 开头改调 SettleDerived，Influence/Territory/Chiefdom 从 Order 8/45/46 移除（模型改空壳或删除），**数值会漂移**——全量回归，确认 T14（农业涌现）/T21（人口梯度）/T22（领地涌现）/T16（时代金字塔）仍 PASS，必要时校正常数。
4. **IsBigMan/IsChief/ChiefdomId 移出入档**：改为 ChiefdomModel/声望派生重算；存档版本号不变（读旧档时这 3 字段忽略，重算覆盖）。验证 T04 + 酋邦测试 T43-T52。
5. **声明式清单 `CivArchiveSchema`**：§3 表格落地为代码清单，Write/Read 改由清单驱动（字节布局不变）。验证：全量回归 + 旧档（v10 现有档）可读。
6. **新增 T04b**（派生纯函数守卫）：读档后 `SettleDerived` 跑两遍结果一致（幂等）；演化中随机抽 tick，`SettleDerived` 结果 ≡ 该 tick 内存派生值。验证：全 PASS。
7. **收尾**：更新文档（本文件 §3 为真源）、删探针、全量回归、提交。

## 六、为什么这能根治（对照缺陷）

| 缺陷 | 方案 D 的消除机制 |
|---|---|
| ① 派生跨 tick 边界歧义 | 派生 = 单 tick 缓存，唯一入口重建；模型不读旧派生值（SettleDerived 保证开头已重建） |
| ② 重算路径不统一 | 演化/读档/Run 结尾三条路径调**同一个** `SettleDerived` |
| ③ 手写清单漏字段 | 声明式清单单源 + 反射校验 + T04b 纯函数守卫，漏字段当场红 |
