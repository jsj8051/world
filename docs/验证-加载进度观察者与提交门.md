# 验证 · 加载进度观察者与迟到提交门

- 状态：第 6 步可验证产物（第 5 步逻辑实现已通过）
- 日期：2026-11-11
- 依据：[设计-地图加载与进度实现方案.md](设计-地图加载与进度实现方案.md)
- 范围：应用内加载/生成/演化三条链路的进度显示方式与迟到结果提交边界；不含 `.wmap` 格式、生成算法、渲染算法。

## 1. 这次改动要证明什么

1. 进度只有一个状态源：`LoadOperation`。旧的 `OperationContext` / `SceneInitializationState` / `MapOperationState` 已删除。
2. 进度 UI 改成观察者：`LoadOperation.Subscribe` 在状态锁外投递不可变快照，UI 用 `LoadProgressMailbox` 收件、在主线程消费。**不再轮询操作状态。**
3. 后台线程不碰 Godot 对象；主线程只做 UI 与 Godot 对象装配。
4. 结果落主线程前过 `LoadCommitGuard`：页面或操作换代、页面生命周期取消、操作取消时，迟到结果一律丢弃。

## 2. 环境前提

- Windows、.NET 8 SDK、Godot 4.7.1 Mono（控制台版即可）。
- res4 地图包一份（`%APPDATA%\Godot\app_userdata\world\maps\*.wmap`），用于浏览链路；没有时可跳过第 3.2 步。
- 命令均在仓库根目录执行。

## 4. 手工演示（点几下就能看）

前提：Godot 编辑器按 F5 启动主场景（不要 F6 单跑页面，页面依赖 `AppRoot` 注入）。

1. **浏览地图的进度**：主界面 → 地图库 → 选一张 res4 地图 → 「浏览所选地图」。观察进度层：标题「加载地图」、阶段在「读取与清单 / 并行解压/解码 / 世界事实装配 / 画面装配」之间推进、百分比单调不减、已用秒数在无新上报时也持续走动。装配完成后进度层消失，相机与点选可用。
2. **生成的进度**：主界面 → 地理演化 → 直接点「生成」（默认配置已应用，无需先点应用）。阶段依次为板块 / 地形 / 气候 / 水文 / 空间索引 / 画面装配。
3. **演化计算面板的进度**：进入世界后，在演化面板单步或跳转。面板内进度条随构造步进推进；跳转显示「构造步进 N/M」，单步为不确定态。
4. **重复点击不会叠加**：加载期间再点一次「浏览所选地图」或「生成」，不会出现第二个进度层，也不会并发跑两个任务。

## 6. 已知限制

- **进度层在终态瞬间隐藏，不显示 100%**：沿用改动前行为，本次没有借机改交互。
- **演化面板的观察操作不链接页面令牌**：解绑不能取消世界侧计算，因此只靠稳定的面板身份与显式解绑，不靠取消令牌。
- **`maxGap` 不是承诺值**：它受机器负载影响明显。本次有一次 633 ms 的测量，事后定位为两条未退出的 `--generate` 检查进程一直在后台跑世界生成（分别消耗 70 s 与 742 s CPU）；清理后复测回到 98–211 ms。对照 HEAD 的交替测量显示生成管线本身没有变慢（`build` 7004/7460 ms vs 基线 8224/7696 ms）。
- **「并行解码」阶段文案与实际解码阶段不完全一致**：读包的并行段做的是解压/校验/取原始字节，类型化解码仍在后续步骤。这属于评审里单列的 B 项，未获批准，本次未动。
- **未做真实窗口下的手工回归**：本轮验证是无头链路 + 纯 C# 并发测试；第 4 节的手工步骤需要你在有窗口的环境里走一遍。未生成截图/录屏。
- **只验证了「页面加载不可取消」这一既有约定**：用户无法中途取消浏览/生成，只能退出应用；退出时的取消路径由单元测试与 `_ExitTree` 覆盖，未做手工验证。
