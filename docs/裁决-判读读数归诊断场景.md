## 一 为什么"搬"而不是"删"

删掉最省事，但会**断掉验收链**。`[WORLDGEN-TIMING]` 是全部跨 seed / 跨档位验收与
"改公式后逐字段回基线"的**唯一 CLI 读数口**（本项目的验收口径一直是
`Godot --headless … | grep WORLDGEN-TIMING`）。删了它，就没有任何不依赖单测的生成结果读数。

⇒ 选择"搬"，并**保留判读能力**（这正是诊断场景带 `--res` / `--radius` 参数的原因）。

---

## 二 为什么"读数等价"

三处读数里：

| 读数 | 依赖 | 能否等价搬走 |
|---|---|---|
| `[WORLDGEN-PARAMS]` | `WorldParamStore.Load()` + `spec` | ✅ 纯逻辑（存储层现住 `World.Assets`） |
| `[WORLDGEN-TIMING]` | `Sim.Ball / LandSea / Terrain / Climate / Hydrology` | ✅ 纯逻辑（Sim 与 Godot 无关） |
| `[WORLDGEN-READY]` | `BallView` / `RiverLineOverlay` 构建 | ❌ **表现层** ⇒ 不搬，随生产类一起消失 |

实测（诊断场景输出，与搬走前主场景输出**逐字段相同**）：

```
[WORLDGEN-PARAMS] seed=42 陆块=7 陆占比=29.0%
[WORLDGEN-TIMING] n=288122 res=4 land=29.0% regions=95 meanP=1098mm/年 meanT=76.0C
                  ridges=71 basins=6971(endorheic 0) lakes=3439 thr=0.636
  PASS WorldGenReadout | res=4 n=288122 land=29.0% regions=95
```

## 三 有意保留的三处（**不是**遗漏）

1. **`BuildSpec` 的 `GD.PushWarning`（读表报告）**——报坏档 / 首跑拷出玩家档。
   搬走会让**"坏档静默"** ⇒ 属功能回退。它是**错误可见性**（生产可靠性），不是判读读数。
   边界判据 = **"这句话是给人看世界算得对不对，还是给人看有没有出错？"** 前者搬，后者留。
2. **`WorldGenManager` 的 `[WORLDGEN-PICK]`**——**交互式**点选判读，需真实鼠标点击，
   无法在 headless 诊断场景复现 ⇒ 另案（本契约只覆盖 `WorldGenPlanet`）。
   注：同一信息 `CellInfoCard.ShowCell` 已在屏幕上显示，控制台那份是**冗余副本** ⇒ 将来可考虑直接删。
3. **`ProductionRes` 常量**——它是"生产分辨率 = res4 冻结"这条**架构事实**，被
   `SpatialScaleTests` 反射钉住，也是 CivSim `HumanInputGrid` 契约（ADR-0005 I1）的基准。
   它是**生产常量**，不是测试内容。⚠️ 但它目前**寄生在场景层 Node 类**上（同型先例：
   `TargetRegionAreaKm2` 曾寄生在生成器、`ContinentAnchor` 曾寄生在 `ContinentLayout`）
   ⇒ **归位逻辑层常量族是待办**，不属本次变更边界。

---

## 四 代价

1. **主场景 headless 完全静默**：`WorldGenWorld.tscn` 跑完不再有任何 `[WORLDGEN-*]` 输出。
   判据只剩"零 ERROR + 场景挂载成功"（`Cannot load C# script` 仍会被抓）。
2. **`[WORLDGEN-READY]` 读数消失**：表现层构建耗时（`ViewCtor` / `BuildChunks` / `RiverLinesBuild`）
   不再有任何自动产出，要看去主场景实机跑。**这是本次唯一净损失**。
3. **res4 在 verify.sh 里跑两次**（主世界一次 + 读数诊断一次），回归时间增加约 2–3 s。
   这是"生产静默"换来的必然代价——主世界那一次仍必要（它验的是**场景挂载**，
   而诊断场景不挂任何生产节点）。
