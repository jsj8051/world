| 项 | 改动 |
|---|---|
| **唯一入口** | `World.WorldGen.WorldParamTable`（`scripts/Logic/WorldGen/Params/`）＝"世界定义从哪来"的**唯一**答案 |
| **两个文件** | **默认档** `data/world_params.json`（正库，随游戏走，只读）｜**玩家档** `userdata/params/world_params.json`（首跑整份拷贝，不入库） |

## 一 六轮收敛（每轮都由"这东西为什么存在"触发）

| # | 用户质疑 | 当时的错 | 结论 |
|---|---|---|---|
| 1 | 「默认值是不是散落在各个地方」 | 默认值分散在 `[Export]` 初值 + 生成器缺省参数 + `LandSeaParams` 内联初值 | 建 `WorldParamRegistry` + `ParamDescriptor` + `ParamTier`（**描述表**） |
| 2 | 「为什么还要有这么复杂的登记 `WorldParamRegistry`，不是直接取 key-value 就行了吗」 | 描述表 = 自造"key 清单 + 字段类型表"，而 spec 类型**已经**是清单 | **删注册表族**，改"`key → double` 字典 + 反射装配" |
| 3 | 「既然建立了参数管理系统了，那么 spec 那些文件就可以拿过来当参数的存储类了吧，没必要建立好几套体系」 | key 字典＝**平行存储结构**（第二份真相源） | **spec 类型自身即存储类**，管理器退化为纯转换器 |
| 4 | 「`WorldSpecDefaults` 这个名字为什么叫 defaults」→「为什么这里要留个默认值，默认值不能也放到 json 文件里面吗」 | 代码里留一份默认值 = 与 JSON 争夺真相源 | **默认值全进 `data/world_params.json`**，`WorldSpecDefaults` **删除** |
| 5 | 「还有 json 解析等工具应该有现成的吧，不需要自己来造」 | 手写 JSON 读写 | 改用 **`System.Text.Json`**（`JsonNode` 合并 + `UnmappedMemberHandling.Disallow`） |
| 6 | 「读取数据和写数据应该交给逻辑层来做吧，场景那里不需要做这些，export 也不需要，然后读取参数的活交给参数管理器干吧，从 `WorldGenPlanet` 拿出来」 | 磁盘 I/O 留在场景层（`WorldParamsSource` / `WorldParamFile`）＝**Scene↔Logic 中间桥层**红线违例 | **磁盘 I/O 下移到逻辑层的管理器**；场景层 `[Export]` 全删 |

★**同一型错误的统一教训**（用户四次同型反馈）：**先把结构建出来、再补消费者或守卫，顺序反了**。
正确顺序 = **先问"既有事实里有没有现成的？"**（防膨胀三问之③：**真实消费者？无 ⇒ 不建**）。
第 2/3/4 轮的删减都是这一条的直接结果。

## 二 为什么"正库默认档 ＋ 玩家档"两份文件（解决鸡生蛋）

**问题**：默认值要进 JSON ⇒ "世界定义的唯一来源是那个 JSON" ⇒ 但玩家改了 JSON 就没法回到出厂状态；
且"改默认世界"（会影响全部诊断读数与跨 seed 验收）与"我自己玩的时候想调一下"是**两件事**，
在同一个文件里做必然互相踩。

**解**：

| 文件 | 身份 | 谁改 |
|---|---|---|
| `data/world_params.json` | **正库存档**：默认世界的唯一定义（代码里没有第二份），随游戏打包 | 改它 = 改**默认世界**（谨慎，须同步过 `WorldSpecTests` 守卫） |
| `userdata/params/world_params.json` | **玩家档**：首跑由默认档**整份拷贝**（连注释一起），之后只改它 | 玩家随便改；**删掉它 = 恢复出厂设置** |

⇒ "恢复出厂设置"这个能力**本身**就是"删一个文件"，不需要任何额外代码路径。

## 三 为什么必须"合并"而不是"直接反序列化文件"

若 `JsonSerializer.Deserialize<WorldSpec>(玩家档文本)`：

- spec 日后**新增字段** ⇒ 老玩家档缺的那一项被读成 `0`（`LandFraction = 0`、`TargetRegionAreaKm2 = 0`…）
  ⇒ **世界静默改变，编译与既有测试全绿**。这是最坏的失败模式。

**做法**：把玩家档当成**补丁**，`JsonNode` 递归 `Overlay` 到默认档对象上，再整体反序列化。
未写的字段天然保持默认档值；**空玩家档 = "没有任何覆盖"＝正常状态**（不报问题）。

实测（2026-10-10）：玩家档只写 `{"LandSea":{"LandFraction":0.5}}` ⇒
`[WORLDGEN-PARAMS] 参数表与默认档不同；seed=42 陆块=7 陆占比=50.0%`
（`Seed` / `ContinentCount` 等全部从默认档补齐，`land=50.0%`、`thr=0.446`）。

## 四 坏数据不静默

| 情形 | 行为 |
|---|---|
| 玩家档 JSON 语法错 / 根不是对象 | 记问题 + **全部回落默认档**，世界仍可跑 |
| 玩家档字段名拼错 / 类型不匹配 | `UnmappedMemberHandling.Disallow` 报错 + 回落默认档（实测：`The JSON property 'LandFractionn' could not be mapped to any .NET member ...`） |
| 玩家档文件缺失 | **正常**：从默认档整份拷出，记一条提示 |
| **默认档**坏掉 / 找不到（向上 10 层） | **致命**：返回 `default(WorldSpec)` + 报问题；**故意不**偷偷用某个内置默认值——那等于把默认值又搬回代码里 |

## 五 刻意不做的三件事

1. **不建分级暴露面板**：本轮只做"入口唯一化"。编辑器里做只读面板 / 参数分组属下一批（
   `docs/审查报告-世界生成参数盘点.md` §四）。
2. **不做"参数一变自动重算"**：生效点**只有** `Regenerate()` 一处。res4 全量 ≈ 1.9–2.1 s，
   自动重算会暴露"半更新的世界"（用户改一个字段触发一次全量重算，且期间世界处于中间态）。
   ⇒ **改完 JSON 后显式调 `Regenerate()`**。
3. **不把 `ResLevel` / `Radius` 收进参数表**：它们是**构造参数**（决定球壳规模
   `GetNumCells(r)=2+120·7^r`），不是"世界定义"；且 `WorldGenSimulation` 是**重建型**
   （构造后无运行期滑杆）——世界参数走 `Run(WorldSpec)` 才是**重算型**。

## 六 精度纪律

精度**只在字段类型上定义**（`float` 7 位 / `double` 16 位），读、写、比较、诊断文案**四处口径一致**。

- 起因：读取小数时出现 `0.0000000001` 这类长尾——`0.29`(JSON/double) ≠ `0.29f` 加宽成 double，
  差约 `8.3e-9`；四处口径不一致就会各自"差一点点"。
- 解：`System.Text.Json` **按属性 CLR 类型**读写 ⇒ `float` 字段读成 `float`；
  拷贝默认档原文时保持 float 最短往返格式（`0.29` 就是 `0.29`）。
- 测试 `FloatValue_IsReadAtFloatPrecision` 钉住这一条。

## 八 代价与遗留

1. **丢了编译期检查**：默认值在 JSON 里，类型/字段名错误要跑起来（或跑测试）才发现。

## 九 第七轮：`BuildSpec` 收敛（删第二入口 ＋ 诊断不再撒谎）

触发（2026-10-10）：用户问「**那现在 scene 里面的 `BuildSpec` 是干什么的**」——
仍是"这东西为什么存在"的同一型追问。查完发现：**方法本身必要，但里面有三行问题**。

### 9.1 `BuildSpec` 为什么必须存在（不能删）

`BuildSpec() = Regenerate()` 的私有辅助，**唯一职责 = 回答"这一次重算用哪份世界定义"**：
问 `WorldParamTable` 要一份生效的 `WorldSpec`，交给 `Sim.Run(spec)`。

**为什么读表这一步不能下沉进 `WorldGenSimulation`**：铁律是 **参数流 `Scene → Logic`**、
`Run(spec)` 显式传参、`Sim` 零参数字段、逻辑入口引擎 API 为零。若让 `Sim` 自己读表，
"世界定义由谁决定"就从装配层滑到逻辑层，且 `PerfBench` / 单测**再也无法喂任意 spec**。
本类在这一步只做"接线 + 打印"（打印要用 `GD.*`，逻辑层不让碰）。

### 9.2 删掉"第二参数入口"：`ApplyWorldSpec` / `_specOverride`

| 理由 | 说明 |
|---|---|
| **零消费者** | 全仓搜索（含测试）**0 处调用**；是为"将来的存档 / UI"提前建的空壳 ⇒ 撞防膨胀第③问 |
| **它本身就是第二个入口** | 从外面塞一套 spec ＝ 绕开"世界定义**只有参数表一个来源**"，与上一轮刚定的原则直接冲突 |

**将来存档要恢复世界怎么办** ⇒ **写一份玩家档 JSON 再 `Load`**（参数表本来就是干这个的），
而不是另开一条注入通道。契约测试 `WorldParams_AreReadOnlyByTheLogicLayerGate` 增加 ①b
钉住 `ApplyWorldSpec` / `_specOverride` 不得复活；确要开新通道须显式改契约并留决策记录。

★这条本身也是第 2/3/4 轮同型错误的**第二例**（第一例见 §一）：**先建结构，再等消费者**。

### 9.3 修掉"撒谎的诊断"

原第三行：

```csharp
(spec.Equals(WorldParamTable.Preset(out _)) ? "一致（未做改动）" : "不同")
```

两个毛病：
- **重复读盘**：`Load()` 内部已经读过默认档，`Preset()` 又读一遍 ⇒ 每次组装默认档被读 2 次；
- **出错时撒谎**：玩家档坏掉 ⇒ 回落默认档 ⇒ `spec` 恰好等于默认档 ⇒ 打印"一致（未做改动）"，
  而真相是"**读失败**，只好用默认"。实测（字段名拼错）：

```
WARNING: 玩家档字段无法装配成 WorldSpec：... could not be mapped to any .NET member ...
WARNING: 玩家参数表装配失败 ⇒ 全部使用默认档。
[WORLDGEN-PARAMS] 参数表与默认档一致（未做改动）；seed=42 ...   ← 假的
```

**改法**：不比较，**直接打印生效值**——用户改完 JSON 后一眼看生效了没：

```
[WORLDGEN-PARAMS] seed=42 陆块=7 陆占比=29.0%
[WORLDGEN-PARAMS] seed=42 陆块=7 陆占比=29.0%（见上方 WARNING）   ← 有报告时（坏档 / 首跑拷出玩家档）
```

★原则：**打印"是什么"，而不是"和另一个东西像不像"**——后者既贵（多读一次盘）又会被
"因为失败才相等"骗到。
