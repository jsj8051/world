ArrayMesh 数组渲染：代码在做什么

以 new_HexWorld/BallView.cs → RenderMesh() 为例 —— 一句话：先把"画面"翻译成三张平行表，再按引擎规定的槽位一次上交，之后 GPU 每 3 个索引连一个三角形画出来。

① 全景：数据从哪来、经过谁、到哪去

1数据层 BallPositions[]每个 H3 共享角点的球面坐标（位置只存一份）
2BallMesh 建表BuildTileMeshData每格把角点坐标拷进自己的块 → 产出三张表（见 ②）
3装箱RenderMesh把三张表放进"槽位信封"（arr[Vertex/Color/Index]）
4一次上交AddSurfaceFromArrays引擎收走数组 → 建成网格资源（顶点/索引缓冲），一次 interop 调用全量提交
5入场景MeshInstance3D数据(ArrayMesh) + 画法(Material) + 摆放(节点 Transform) 三分离；每帧 RotateY 只转节点，几何不动

② 三张表 → 三角形（核心）

一个六边形格子的 6 个角点存为顶点表 1 块（下标 0–5）；颜色表和顶点表平行（同下标 = 同顶点的属性）；索引表每 3 个一组指向顶点，就是一个三角形。fan 三角化：(v0,k,k+1) 绕枢纽 v0 转一圈。

顶点表 DisplayVerts每行 = 一个 Vector3（球面坐标）
下标本格角点
颜色表 colors（平行）同下标 = 同顶点的颜色
下标颜色值
索引表 DisplayIndices每 3 个一行 = 一个三角形
三角形索引三元组
格内三角（鼠标悬停表格行 ↔ 图形高亮联动）
枢纽顶点 v0 —— 被 4 个三角形共用，索引的意义
为什么要索引？枢纽 v0 同时属于 4 个三角形。没有索引表就得把 v0 的坐标+颜色在顶点表里重复写 4 份（"三角形汤"）；有了索引表，v0 只存 1 份、被引用 4 次 → 显存省、且改一个点只需改一处。
引擎文档原话：加入索引数组后曲面进入 "index mode"——"顶点等数组成为数据源，索引数组决定顶点顺序"。

相邻两格的角点是"复制"的，但不裂

H3 里相邻格共享角点（同一个全局顶点 id）。BallMesh 的做法是每格独立成块，把共享角点的坐标各写一份——表里重复，几何上坐标相同：

格 A（一整块 6 角点，同色）
格 B（自己的块，可不同色）
共享边两端：同一个球面点，两块各存一份坐标 → 完全重合 → 水密无缝；两格颜色不同 → 这条边就是可见的蜂窝分界

③ RenderMesh 逐行拆解

Color[] colors = _mesh.BuildTileColors(_ball, c => Color.FromHsv(H3.GetBaseCellNumber(c)/122f, 0.8f, 0.9f));
// ① 颜色表 = 每格 1 个颜色 → 展开成 6 份（6 个角点同色）
//   色相 = 基底格编号/122 → 122 个基底族各一色：能看清蜂窝结构和 12 个五边形的位置

var arr = new Godot.Collections.Array();        // ② "槽位信封"：Variant 数组（不是 C# List！），
arr.Resize((int)Mesh.ArrayType.Max);            //    开够引擎规定的全部槽位：Vertex/Normal/Color/…/Index/Max
arr[(int)Mesh.ArrayType.Vertex] = _mesh.DisplayVerts;    // ③ 槽[0]  顶点坐标
arr[(int)Mesh.ArrayType.Color]  = colors;                //    槽[3]  每顶点颜色（平行表）
arr[(int)Mesh.ArrayType.Index]  = _mesh.DisplayIndices;  //    槽[·] 索引 → 进入 index mode
//    没填的槽（Normal/TexUV…）= null = "这格没数据" → 引擎就不启用对应通道

mesh.AddSurfaceFromArrays(Mesh.PrimitiveType.Triangles, arr);
// ④ 引擎解析信封：收走数组 → 建 RenderingServer 网格资源（顶点缓冲 + 索引缓冲）
//   PrimitiveType.Triangles = 告诉 GPU："索引每 3 个连一个三角形"（不是 Line/Point）

new StandardMaterial3D { ShadingMode = Unshaded, VertexColorUseAsAlbedo = true };
// ⑤ 没给 Normal（法线）槽 → 材质必须是无光的（Unshaded 不打光、不需要法线）
//   VertexColorUseAsAlbedo = 把顶点色当"固有色" → 三角形内部每个像素的颜色
//   = 三个顶点颜色的插值 → 同格 6 顶点同色 ⇒ 插值恒等 ⇒ 整格纯色

_meshInstance = new MeshInstance3D { Mesh = mesh, MaterialOverride = mat }; AddChild(_meshInstance);
// ⑥ 几何(ArrayMesh)/画法(Material)/位置(节点)三分离；_Process 里 RotateY 只改节点 Transform —— 每帧成本≈0
为什么是"数组套槽位"这么别扭的写法？因为 Godot 的网格定义是"一条龙约定"：一个曲面可能带顶点/法线/切线/UV×2/顶点色/骨骼权重/索引……引擎把每种数据编成固定槽位号。arr.Resize(Max) 就是"按约定把信封隔层全开好"，你只往用到的隔层里塞数据，其余留 null。引擎拿到信封后一次 interop 调用就解析完所有层——这正是和 ImmediateMesh 逐顶点调用的本质区别（36k 顶点逐点调 ≈ 7–15ms/帧，批提交 ≈ 3–4 次调用）。

④ 四个"为什么"（把代码看明白的关键）

  • 为什么颜色要和顶点"平行"一一对应？GPU 只认识"顶点属性"。一个三角形 3 个顶点各带颜色，片元着色器按像素离三个顶点的远近插值出每个像素的颜色。同格 6 角点同色 → 格内处处同色；邻格颜色不同 → 交界处硬切换。给"面"上色 = 给这个面的所有顶点上同一个色。
  • 为什么顶点是每格复制一份，不共享？因为每格要能独立上色（每格 1 色），共享顶点会互相抢颜色。复制坐标换独立着色，几何上坐标一致所以不裂——这是"按格着色"与"顶点共享"不可兼得时的取舍。
  • 为什么 Unshaded？光照需要法线（Normal 槽），我们没填；Unshaded 直接输出颜色，正好只给了颜色的数据。想上光照 = 补一个法线数组进信封即可。
  • 为什么只在 _Ready 建一次？球是静态几何，变化的是节点 Transform（自转）。数据只上交一次；之后每帧 RotateY 转节点 → GPU 侧只是换了个矩阵，零几何成本。若每帧改网格（如洋流/河流图层）才需要 ClearSurfaces() + AddSurfaceFromArrays() 重交（本仓库动态网格纪律：预分配精确大小数组，每帧仅 3–4 次 interop）。
