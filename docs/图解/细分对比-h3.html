球面细分：我们（三角 n 等分 + Goldberg 对偶） vs Uber H3（aperture-7 六边形层级）

结论：同根（都是 icosahedron 六边形球面网格），但细分机制、层级缩放、朝向、目的完全不同——是两套体系。

我们的方案自研

Icosahedron.Subdivide(n)：每条边 n 等分 → 三角网格 → GoldbergBuilder 对偶 → 每顶点一个六边形（12 个五边形）。顶点数 = 10n² + 2。

Uber H3业界标准

专用旋转朝向的 icosahedron + 面上 (i,j,k) 六边形晶格；分辨率 +1 = aperture-7（每六边形分为 1+6 个子六边形）。索引 = 64 位整数。
维度本项目（自研）Uber H3
基础单元三角网格顶点（对偶后六边形）面内直接铺六边形晶格
分辨率参数n 任意整数（32/64/96/120/128/256 全用过），n² 面积缩放res 固定档 0–15，每级面积 ÷7（aperture-7）
层级嵌套精确嵌套：2n 细分 ⊇ n 细分，粗顶点在细网格中坐标重合相邻 res 中心对齐，但非简单顶点嵌套
icosa 朝向标准朝向（12 顶点在 ±φ 轴）旋转定制朝向（12 个五边形避开主要陆地，利于地理应用）
索引体系顶点 id（int），无全局编码64 位 H3 索引（层级 + faceijk 位置编码），全球统一
设计目的程序化随机星球的任意分辨率模拟/渲染地理空间索引、聚合统计、行政区划（全球一套编码）
对本项目的影响：「再细分一次给渲染层」继续用 Subdivide(2n) 正确——它在自身体系内的自然延伸（精确嵌套归属、任意 n、10n²+2 存档公式全项目唯一）。若引入 H3 式分层反而会破坏三件事：任意分辨率（n=120 分析档、n=64 快速档都是特意选的）、2n 精确嵌套（RenderSphere 归属映射就靠它）、存档公式的单一来源。
