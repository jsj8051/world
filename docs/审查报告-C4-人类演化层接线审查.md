## 1 「人类演化层」到底是什么（命名与边界钉死）

### 1.1 它是代码实体，不是隐性概念

| 项 | 值 |
|---|---|
| 物理目录 | `scripts/CivSim/`（55 个 `.cs` / 7622 行） |
| 命名空间 | `World.CivSim`（子目录不进命名空间） |
| 入口类型 | `CivEngine.Run(grid, seed, originCount)` / `CivEngine.Continue(ctx, ticks)` |
| 输入载体 | `GameGrid`（`World.LogicGrid`） |
| 输出载体 | `CivSimResult { Context, FinalTick }` |

### 1.2 ★关键澄清：项目里**不存在**"人类演化层 = 世界事实层"

`grep -rn "人类演化" --include=*.md --include=*.cs .` 的全部命中都在 **2026-10-06 之后新增的文档**
（`审查报告-CivSim人类演化层取证.md` / `ADR-0005` / `MEMORY.md`）——**代码里没有这个概念**。

⇒ "人类演化层"是**我们本轮对话引入的称呼**，指的就是 `World.CivSim`。
它在既有架构里的**正式身份**已经写死在契约测试里：

> `World.CivSim` 与 `World.LogicGrid` 是**领域消费者**（消费世界，不生成世界），被明确保留。
> —— `tests/World.Tests/ArchitectureContractTests.cs:98`

**⇒ C-4 的第一条结论：不要把它当"世界事实层"来设计。它是消费者。**
（这也解释了为什么"它是否承担了生物群系事实链"这个问题会显得错位——见 §5。）

## 2 输入来自哪些 Final 层事实

### 2.1 实测输入面（`GameGrid` 字段级）

`grep -rn "grid\.[A-Z]…|Grid\.[A-Z]…" scripts/CivSim/` 聚合结果，去重后 **15 个字段 / 8 个自然量**：

| `GameGrid` 字段 | 自然量 | Provenance（见取证的 §七） | CivSim 用途 |
|---|---|---|---|
| `Elev`（经 `IsLandCell` / `IsCoast`） | 高度 | Legacy（新线有 `HeightM`，**未接线**） | 海陆边界、海岸判定（**整个模拟的空间骨架**） |
| `Temp` | 年均温 | **Legacy-only（不可重建）** | `BuildLayer1` → `R` 的根；冰盖归零；`ClimateSim`；`WarWeather` |
| `Precip` | 年降水 | **Legacy-only** | `R` 的根；`WildCrops` 适宜度 |
| `Biome` | 群系 | **Legacy-only** | `WaterRich` / `TerrainCost` / `EnvMatches` / `PreyFrac` |
| `SoilLevel` | 土壤 | **Legacy-only** | `AlluvFactor`；`InventionModel` 种子门槛 |
| `LakeLevel` | 湖 | Legacy（新线有 `LakeState`，**未接线**） | `WaterRich` / `LakeFishAccess` / `RiceSuit` |
| `MonthTemp` | 月温 | **Legacy-only** | `Suitability`（5 种子生态位）；`WarWeather` |
| `MonthPrecip` | 月降水 | **Legacy-only** | 同上 |
| `WildCrops`（经 `EnsureWildCrops`） | 野作物位 | **Derived**（`Domain/WildCropsSystem` ← 上面 6 个 Legacy 量） | `InventionModel` 驯化门槛 |
| `WildLivestock`（经 `EnsureWildLivestock`） | 野牧位 | **Derived**（同上） | `CapabilityTable.Livestock`；`FFarmTerritory` |
| `N` / `Neighbors` / `CellAreaKm2` / `DistKm` | 几何 | Legacy `HEAD` | 全体几何基础 |

**CivSim 完全不读**（与取证一致）：`RiverLevel` / `RiverFlow` / `RiverVolume` / `MineralLevel` / `MonsoonLevel` /
`CurrentDirs` / `CurrentWarmth` / `CurrentStrength` / `Psi`（**零消费者**）。

### 2.2 Final 层事实的输入量 = **0**

| 事实类 | 是否被 CivSim 消费 |

| `FinalGeography.FinalLand` / `FinalLandFraction` / `FinalLandmassId` / `FinalDistToCoast` / `FinalDistToLand` / `FinalRegionOfCell` | ❌ **0** |
| `FinalSpatialIndex`.*（nearest landmass/region/river/mountain/volcano） | ❌ **0** |

而 `IsLandCell`（CivSim 实际用的）判据是 `Elev > 0`；`FinalLand` 的判据是 `HeightM > 0`
—— **同谓词、不同实现、不同世界线**（见 §4.4 D1）。

## 4 反向依赖 / 重复计算 / 越层读取

### 4.1 反向依赖：**0（双向）**

```bash
grep -rn "CivSim" scripts/WorldGen/ --include=*.cs          # → 空（0 命中）
grep -rn "WorldGen\|World\.WorldGen" scripts/CivSim/        # → 仅 2 处注释（行 301、681，均说明 Riparian）
```

⇒ **两条世界线在类型层面完全隔离**（比"单向依赖"更强：连单向都没有）。
⇒ 已有契约 `NewWorldLine_DoesNotDependOnLegacyWorldLine` + `LegacyWorldGenerationChain_IsGone` 覆盖了**旧线**方向。

### 4.2 回写自然层：**0**

```bash
grep -rn "Grid\.[A-Za-z]*\[…\] *=[^=]" scripts/CivSim/      # → 空
```

⇒ 自然层只读是**代码级成立**的，另有运行时硬验收 `T01 自然层零改动（逐格比对）`。

### 4.3 越层读取：**0**

CivSim 唯一的世界读取面是 `GameGrid`（`World.LogicGrid`），且 `World.LogicGrid` 在**既有依赖白名单**内
（`ArchitectureContractTests.cs:107-111`）。**没有**从 Placement / Composition / Features 层直接取数。

### 4.4 重复计算 / 语义重复：**5 项**

| # | 重复内容 | A 侧 | B 侧 | 性质 |
|---|---|---|---|---|
| **D1** | **海陆谓词** | `GameGrid.IsLandCell` = `Elev > 0` | `FinalGeography.FinalLand` = `HeightM > 0` | 两条世界线各自的同义实现——**合法但口径必须分开记**（混用即"换世界"） |
| **D2** | **陆地连通分量** | `OriginModel.ComputeContinents`（BFS flood fill，n 格） | `FinalGeography.FinalLandmassId` 与 `H3LandSeaProjector.LandmassId`（同算法） | 同算法 **3 份实现**；CivSim 那份作用于 Legacy 图，无法复用新线结果 |
| **D3** | **邻接表** | `GameGrid.BuildNeighbors`（LogicGrid） | `Ball.BuildNeighbors`（`World.Spatial`，新线） | 两套 H3 邻接；`GameMapArchive` 明确"邻接不存档" |
| **D4** | **距离场 / 邻域查询** | `CivSimContext.BfsRadius`（O(n) 每调用） | `FinalSpatialIndex`（预计算 nearest/distance/within）+ `HydrologyRoutingSurface` | 新线已把距离场做成**基础设施**；CivSim 仍自驱 BFS |
| **D5** | **★ 生态位派生（职责错位，非单纯重复）** | `Domain/WildCropsSystem`（`Suitability` / `ComputeLivestock`）+ `CivSimContext`（`WaterRich` / `PreyFrac` / `FishFrac` / `AlluvFactor` / `IrrigFactor`） | **新线侧：无**（零分类器 / 零温度模型 / 零土壤模型） | **"生态事实"由"被模拟者"自己算**——见 §5 |

> **D1–D4 的判定**：**不是"要合并的重复代码"，而是"两条世界线各自的等价能力"**。
> 它们的存在正是"桥未接线"的**症状**：新线算了一遍（`FinalLand`/`LandmassId`/邻接/距离场），
> 旧线又算了一遍（`Elev`/`ComputeContinents`/`BuildNeighbors`/`BfsRadius`），而两者**互不相识**。
> ⇒ 这是**迁移时的对照基准**，**不是**清理对象（第 11 条：不得范围膨胀）。

## 5 C-5 回答：人类演化层是否已承担"生物群系事实链"职责？

### 5.1 事实

| 生态位/群系相关派生 | 当前位置 | 输入 |
|---|---|---|
| `WildCrops`（5 位作物位）/ `WildLivestock` | `scripts/Domain/WildCropsSystem.cs` | Legacy `Temp`/`Precip`/`Month*`/`Biome`/`LakeLevel`/`Elev` |
| `Suit[,]`（种子适宜度） | `CivSimContext` ← 调 `WildCropsSystem.Suitability` | 同上 |
| `WaterRich` / `PreyFrac` / `FishFrac` / `ForageShares` | `CivSimContext` | `Biome` / `LakeLevel` |
| `AlluvFactor` / `IrrigFactor` | `CivSimContext` | `SoilLevel` / 邻水 |

新线侧对应物：**不存在**（WorldGen 有 Geography + Hydrology + Precipitation，**无 Climate / Biome / Ecology / Soil**）。

### 5.2 结论

**是的——"生态事实链"事实上已经在人类演化层（及其紧邻的 `World.Domain`）里，而不是在世界生成层里。**

但这不是"人类演化层承担了职责"，而是 **职责错位** 的两种表现：

1. **生产者缺失**：`BiomeType.Riparian` 在**全仓只被读、从不被写** ⇒ 3 条 CivSim 判定
   （`WaterRich` 的 Riparian 分支 / `IrrigFactor` / `PreyFrac` 的 Riparian 分支）**恒不命中**。
2. **消费者越位**：为把模拟跑起来，CivSim 不得不**自己算** `WildCrops` / `WaterRich` / `PreyFrac`
   —— 而这些语义上属于"世界事实"。

### 5.3 **Riparian 这类事实应该由谁提供？**

**答：由 WorldGen 侧（`Ecology` / `Biome` 事实层）提供——当前无人提供，属职责悬空。**

- **不应由人类演化层补**：否则生态事实成为"人类演化的产物"，
  形成 **事实层 ← 决策层 的反向依赖**（正是用户本轮提出的规则要挡的东西）。
- **也不要现在补**：2026-10-06 用户已拍板 **② Riparian 取消**——理由正是
  "它不是缺失的一条分支，而是被清退的整条气候/群系链留下的幽灵接口"。
- **正确做法**：把它登记为 **`World → Human Input Bridge` 的 Phase 4 交付物**
  （`Temperature → Biome → Soil → Resource Potential`），而不是当成一个独立缺口去堵。

### 5.4 ★由此确立的架构规则（与用户本轮判断一致，建议纳入 C-6）

> **`SubsistenceReadout`（及其同类"判读层"）可以读取环境事实与人类演化事实，
> 但任何 `SubsistenceReadout` 不得成为这些事实的生产者。**
> 判读层是**汇（sink）**，不是**源（source）**。

对应到本项目的既有原则：**事实只能由事实层写；消费者只能读。**

## 6 C-6 的输入：契约缺口清单（本轮只列，不改）

### 6.1 已有的契约（3 条，已生效）

| 契约 | 钉住什么 |
|---|---|
| `NewWorldLine_DoesNotDependOnLegacyWorldLine` | 新线 ⟂ 旧线（4 命名空间黑名单） |
| `LegacyWorldGenerationChain_IsGone` | 全程序集扫描：旧世界生成命名空间已无类型存活（**结果**钉） |
| `RetainedDomainConsumers_OnlyDependOnAllowedNamespaces` | 领域消费者**白名单**（CivSim/LogicGrid/WildCropsSystem） |
| `FinalGeography_DoesNotReferencePlacementProjector` / `HeightComposer_…` / `FinalGeography_…ConcreteFeatures` | Final 层与生成依据/具体 Feature 解耦 |

### 6.2 ★缺口

| # | 缺口 | 为什么现在测不出来 |
|---|---|---|
| **G1** | **没有契约钉住 `World.CivSim ⟂ World.WorldGen`** | 现有白名单只扫 **3 个入口类型**（`CivSimContext` / `GameGrid` / `WildCropsSystem`），且 `ReferencedTypes(t)` **只取直接成员签名/字段 + 基类**（`ArchitectureContractTests.cs:493`，**非传递**）。⇒ 在 `GrowthModel.cs` 里加 `using World.WorldGen;` **不会被任何测试拦住**。今天"CivSim 不依赖 WorldGen"是**巧合成立**，不是**契约成立** |
| **G2** | **"Final 层零外部消费者"这个事实没有被钉** | 无测试断言 `FinalGeography` / `FinalSpatialIndex` 的消费者面。桥一旦接线（或误接），**没有任何信号** |
| **G3** | **生态事实无归属层** | `World.Domain` 同时装"领域词汇"（`BiomeType`）与"领域模拟"（`WildCropsSystem`）。语义上后者属**世界事实**，但被放在消费者侧 ⇒ 白名单把 `World.Domain` 对 CivSim 全面开放，**掩盖了这条错位依赖** |
| **G4** | **两条世界线的同义谓词无对照钉** | `IsLandCell(Elev>0)` vs `FinalLand(HeightM>0)`、两套 `LandmassId`、两套邻接表（D1–D3）——无测试记录"它们是两条线各自的等价实现"，未来容易被误当"重复代码"清理或误当"同源"混用 |
