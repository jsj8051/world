### 🔴 S-1｜MCP 调试服务器：无鉴权监听全网卡 + 任意代码执行工具已启用

**涉及**：`addons/godot_mcp/native_mcp/mcp_http_server_legacy.gd:105-107`、`:391-394`；`addons/godot_mcp/tools/debug_tools_native.gd:3197-3211`、`:3469-3484`；`addons/godot_mcp/native_mcp/mcp_server_core.gd:94-98`
**磁盘配置**：`%APPDATA%/Godot/app_userdata/world/mcp_settings.cfg`（已确认存在）

**表现**：
```gdscript
_tcp_server.listen(_port)          # 未传 bind_address → Godot 默认 "*" = 0.0.0.0
if _auth_manager and not _auth_manager.validate_request(...)   # _auth_manager 为 null → 整段跳过
```
```ini
transport_mode="http"    http_port=9080
auth_enabled=false       auth_token=""
allow_remote=true        cors_origin="*"
```
同时 `mcp_tool_state.cfg` 中 `execute_script=true`、`execute_editor_script=true`。

**根本原因**：HTTP 传输 + 鉴权默认关闭 + 绑定全网卡 三者叠加；且远程代码工具默认开放。
链式完整利用路径（已验证代码连贯）：
1. 局域网任意主机 POST `http://<你的IP>:9080`（无需凭据）；
2. 调用 `execute_editor_script` → `script.set_source_code(wrapped_code)` + `script.reload()` + `script.new()` → **编译并执行任意 GDScript**；
3. GDScript 内可再调 `OS.execute()` 落系统命令。

放大因素：`mcp_server_core.gd:97-98` 把 `apply_confirmed`/`allow_open_world` **硬编码为 true**，使 `tool_policy.gd` 的危险操作确认机制**永不触发**。`debug_tools_native.gd:3146` 的工具描述自称 "Uses Godot's Expression class for **safe** evaluation" —— 与实际能力严重不符。`mcp_http_server.gd:30` 的 loopback 限制**只保护 `/cli/v1`**，主 JSON-RPC 端点不受限。

**影响范围**：当前 `auto_start=false` 且日志显示上次未启动，**暂未被监听**；一旦用户点编辑器面板 Start、或带 `--mcp-server` 启动、或被 AI 助手拉起 → 局域网（含公共 Wi-Fi）任何人可完全控制开发机。`cors_origin="*"` 额外打开浏览器侧 DNS-rebinding 面。这是全项目**唯一可被外部利用**的高危通道。

**修复方向**：① `listen(port, "127.0.0.1")` 显式绑定回环；② 立即改配置为 `auth_enabled=true` + 32 位随机 token + `allow_remote=false`；③ 默认关闭两个 execute 工具，改 opt-in；④ 让 `apply_confirmed` 由真实确认驱动，而非硬编码 true；⑤ 不需要时从 `project.godot` 的 `[editor_plugins]` 移除该插件。

### 🔴 S-2｜构建中切换图层 → 星球网格永久丢失（地图永远打不开）

**涉及**：`scripts/MapView/MapViewer.cs:432-441` + `scripts/MapView/MapViewer.Colors.cs:41-64, 77`

**表现**：
```csharp
// MapViewer.cs —— 闸门提前打开
_tiles = tiles;  _geometry = geometry;
_geometryReady = true;                              // ← 435 行：闸门开
PrecomputeTileValues(map, tiles, token, ...);       // ← 439 行：_cache(487)/_ctx(540) 在【这里】才创建
```
```csharp
// MapViewer.Colors.cs
if (!_geometryReady || _tiles == null) { _pendingRecolor = true; return; }   // ← 只闸 _geometryReady
...
if (LayerRegistry.Of(layer).NeedsPowerBorders && _cache.TilePower != null)   // ← 77 行 _cache 仍为 null → NRE
```
`MakeColorFn` 返回的闭包是 `t => strat.ColorOf(_ctx, t)`，`_ctx` 在 540 行才赋值。

**根本原因**：作者已意识到"构建中切图层会取消当前构建并重启"这个坑（`Colors.cs:34-36` 有明确注释），并加了 `_geometryReady` 闸门来防。**但闸门位置放错了** —— 它在 `_cache`/`_ctx` 就绪**之前**就置 true，闸门因此完全失效。这是一个"修了一半反而更隐蔽"的缺陷：注释让人以为已防护，实际没有。

**影响范围**：首次/重建构建进行中（几何已建、预计算未完成；n=163,842 时该窗口达 **数秒**）用户点图层按钮，或任何代码写 `Layer` 属性。后果链条：
1. `BuildColorsTask` 立即 NRE；
2. `RebuildColors` 同时 `_cts?.Cancel()` 取消正在跑的 `BuildAll`；
3. `FinishGenerate(旧version)` 因版本不符被丢弃，`FinishGenerate(新version)` 因 `_buildTask.Result` 抛异常进 catch；
4. **两条路径都不再 `AddChild` 星球网格 → 地图黑屏/卡在进度条，且无法自愈**。

**修复方向**：把 `_geometryReady = true` 移到 `PrecomputeTileValues` **之后**（435 → 441 行后）；或在 `RebuildColors` 补 `_cache != null && _ctx != null` 闸门。前者是根治。

### 🔴 S-3｜风蚀堆积场复杂度错误：`Array.Clear` 写进内层循环 → O(n²)

**涉及**：`scripts/MapGen/Model/ClimateFields.cs:122-135`

**表现**：
```csharp
var visited = new bool[n];            // 防环
for (int i = 0; i < n; i++)           // 源格循环
{
    if (e[i] < OceanLevel) continue;
    ...
    if (src < 1e-5f) continue;
    net[i] -= src;
    System.Array.Clear(visited, 0, n);   // ← 135 行：每个源格清一遍【全表】
    visited[i] = true;
    for (int s = 0; s < MaxSteps && remain > 1e-5f; s++)  // 内层最多 100 步
```
**根本原因**：防环表的清空粒度错了。内层路径最多 100 步，却清 n 个元素 —— 实测 `< 3 天` ~ `> 数十分钟` 的性能悬崖全在这一行。

**影响范围**：任何含陆地的星球都会走此路径。n=10,242（res2）约 1e8 字节写（几秒）；**n=163,842（res4）约 2.7e10 → 分钟级到小时级**。UI 表现为进度条不动、生成管线假死。无崩溃，但功能在高分辨率档实质不可用。

**修复方向**：换成 `(格, 步)` 时间戳数组（`visitStamp[i] == i` 判重，零清空），或每次只清路径上实际访问到的格子（≤100 个）。一行改动消除 O(n) 因子。

### 🔴 S-4｜后台线程直调 Godot 引擎 API，违反项目自身纪律 ADR-0004

**涉及**：`scripts/CivSim/Engine/CivEngine.cs:96, 101, 103`；`scripts/Diagnostics/PerfLog.cs:22, 24, 33`；`scripts/CivSim/Tables/TechTable.cs:115, 118, 166`；调用方 `scripts/UI/CivEvolveMenu.cs:235-239`、`scripts/UI/MapGenMenu.cs:484-488`

**表现**：`CivEngine.Run` 被包在 `Task.Run` 里，其内部却：
```csharp
World.Diagnostics.PerfLog.Append("civsim", ...);   // → PerfLog.cs:22/24/33 用 FileAccess（引擎 API）
if (hisCnt > 0) GD.Print(...);                     // → 引擎 API
```
项目自己的纪律写得清清楚楚 —— `scripts/Services/LogService.cs:8`：「⚠️ 纪律：后台线程禁止调用」。代码里 38 处 `GD.Print` 都乖乖带注释说明为何例外，但 `PerfLog` 这条路径绕过了。

**根本原因**：把生产链路（`CivEngine`）和诊断/表加载（会碰引擎 IO）混在同一段后台代码里，且无 `#if` 隔离（全项目条件编译数为 **0**）。

**影响范围**：Godot 4 的 `FileAccess`/`GD.Print` 未声明线程安全。第二次及以后的**每次**文明演化都会走 `PerfLog.Append` + `GD.Print`（`hisCnt > 0` 分支）→ 必现违规。后果通常是偶发崩溃/编辑器卡死/日志错乱，非每次必崩，但不可预测。

**修复方向**：把 `PerfLog.Append` 与 `TechTable.Load` 从 `CivEngine.Run` 的后台路径剥离，改为 `CallDeferred` 回主线程；或给诊断访问加 `Thread.CurrentThread.IsBackground` 断言在开发期暴露。

### 🔴 S-5｜洋流图层每帧全量重建 ArrayMesh（唯一每帧掉帧源）

**涉及**：`scripts/MapView/Layers/CurrentFlow.cs:196-203`、`:513-517`、`:602-612`

### 🔴 S-6｜Zoom｜地形/地质生成全在主线程同步执行，首帧冻结数十秒

**涉及**：`scripts/noise_world/NoiseTerrain.cs:210-221`；`scripts/noise_world/worldgen/GeologicalRegions.cs:106-110, 179-208, 349-362`；`scripts/noise_world/worldgen/MountainSkeleton.cs:185-217`；入口 `scripts/noise_world/worldgen/WorldGenPlanet.cs:45-100`

实测 `scripts/noise_world/` 全目录 **`Parallel.For`/`Task.Run`/`Thread` 数量为 0**（排除 hoax：`scripts/Utils/ParallelLoops.cs` 是零调用点死代码）。

**表现与量化**（res4 ⇒ n=288,122）：

| 位置 | 问题 | 开销 |
|---|---|---|
| `NoiseTerrain.SampleRawFields` | 每格 23 次 Perlin（含 warp 3×4 octave） | 288k×23×8 ≈ **5.3e7** 次哈希 → 1.5–4 s |
| `MountainSkeleton.InfluenceAt` | 逐格 × 帽内全脊 × 脊上全点，`MathF.Acos` | **2e8–8e8** 次 Acos → 数十秒 |
| `MountainSkeleton.cs:209` | `_rugged.Sample(dir)` 只依赖 `dir`，却放在**脊循环内** | 每条命中脊重复算 → 放大 5–20 倍 |
| `GeologicalRegions.AssignRegions` | 调用 3 次（1+Lloyd 2），每次 `WarpDir`(9 Perlin) + ≤14 Acos | **7.8e6** Perlin + **1.2e7** Acos |
| `HeightComposer.cs:60` | 每格调 `RegionIndexAt(dir)` → 又一次 `WarpDir` + O(Regions≈100) Acos | **2.9e7** 次超越函数 |

**根本原因**：三个"每格独立纯函数采样"场景全部单线程，且存在**明显的重复计算**（`:209` 的噪声、每格多次 `WarpDir`）本可用缓存消除。

**修复方向**：① 先把 `_rugged.Sample(dir)` 提出脊循环、`WarpDir` 结果缓存（纯收益，改动小）；② 三个逐格循环改 `Parallel.For`（写 `arr[i]` 独立槽位，天然无竞态）；③ 整体搬进 `Task.Run` + 进度条。注意不要顺手并行 currently-serial 的 `OceanCurrent` SOR（见 M-6，Gauss-Seidel 不可直接并行）。
