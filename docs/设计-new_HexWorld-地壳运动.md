## 1. 路线与纪律（v9/v10）

1. **一次静态生成**：`CreatePlates` 生成全球海陆初始地壳场——抽种归并分板（01 §2，直接长在 H3 格邻居图上，v11 弃胞切分层），海陆 = 板块属性（二元），Crust 两级料场（陆 35 km felsic / 洋 7 km mafic）。**无演化步进**。
2. **不做机制演化**：板块运动、边界过程（俯冲/碰撞/洋脊注入）、均衡、冷却段——全部作废；地形不是"演化涌现信号"。
3. **地形要素按需生成**：将来要山带/洋脊/海沟/裂谷等 = 写静态「要素生成器」，按 §6 地形清单直接修改厚度/海拔场；不建演化循环。
4. **海拔场（v10 引入；v12 修订口径）**：静态生成随厚度场一并产出 `Elevation` 初值——陆性板 = 平均高程、洋性板 = 平均深度（两级常量起步，§3.3），服务「海拔图」地图模式（§2.5）。海拔场与厚度场同为逻辑层**权威数据**；渲染层只读海拔场、**禁止伪造**。**v12 修订（由 02 §6 推出）**：原表述"要素生成器成对写厚度与海拔"只覆盖了海拔的机制之一——真实世界海拔有**两个**合法来源，写入必须可追溯：① **地壳厚度变化 → Airy 响应**（碰撞造山 / 火山弧 / 大陆裂谷 / 被动陆缘：写厚度，`Δh = Δt · (1 − ρ_felsic/ρ_mantle)`）；② **热状态 / 弹性挠曲几何**（洋底热沉降、海沟下弯、裂谷肩穹窿：机制登记在案、只写海拔）。**禁止"为了让某地形出现"而无机制地直改海拔**——判据：任何要素增量都必须等于 02 登记的机制公式在测试中的独立重算值（02 §10「机制可审计」）。
5. **场为唯一数据权威**：Crust 场（厚度/年龄/海拔）是唯一权威数据；渲染/显示/统计一律由场派生，不另设平行数据层。

## 2. 架构分层（逻辑层 / UI 层 MVVM）

**总则**：Crust 厚度场 = 唯一权威数据。UI 与逻辑分两层，**依赖单向：UI 层 → 逻辑层**，逻辑层绝不反向依赖 UI。UI 层内部按 **MVVM**（View–ViewModel）组织：View 不直接持有/修改 Model 数据，一律经 ViewModel 派生（用户拍板 2026-09-07）。

### 2.1 逻辑层（Model —— 无 UI 依赖）

- 内容：`H3Plate`/`H3PlateManager`（静态生成）、Crust 场、`Ball` 网格数据（格心/邻居/格 id）、场派生的统计。
- 约束：纯 C# 数据与算法；允许 Godot 数学类型（`Vector3`/`Basis`）与 H3 门面；**不引用任何 Node/Control/场景/CanvasLayer/渲染 API**。
- 派生缓存：统计（板格数/占比）等**由场驱动的重算缓存**可驻留本层（场变 → 重算），但绝不允许成为可独立漂移的数据源。

### 2.2 UI 层（View + ViewModel —— 单向依赖逻辑层）

- **ViewModel 按视图拆分**（用户拍板），每 VM 只从 Model 派生显示状态 + 持有该视图的交互状态：
  - 球视图 VM（如 `HexWorldViewModel`）：当前显示模式（uniform 值）、边界描边格边集（2026-09-09 v1.1 起边粒度记账，弃链几何线层）、逐格区域数据派生口（海拔/板号/陆性——View 烘数据纹理用，v11）、全局统计（陆/洋占比、板格数、板属性）；
  - 格信息面板 VM（如 `CellInfoViewModel`）：拾取格 → 派生条目（格子/板块/陆海/经纬）；
  - 坞 VM（如 `DockViewModel`）：模式列表/当前模式（将来时钟）。
- **绑定机制 = 轻量事件**（用户拍板）：VM 暴露**只读派生属性 + 变更信号**（C# 事件或 Godot `[Signal]`，无第三方框架）；View 订阅信号后**拉取刷新**。
- View（Godot 场景/节点）：`BallView`（球渲染）、`HexInfoPanel`、`HexDock`、状态栏——只显示、只把输入事件上抛 VM，不碰逻辑层。
- 场景根 `BallManager` = **组装器**：创建逻辑层 → 创建各 VM 并注入 Model → 把 VM 挂给 View；承担输入路由（点击/按键转发给对应 VM），不承载业务数据。

### 2.3 数据流与禁令

- 数据流：**Model（唯一权威）→ VM 派生（只读）→ View 渲染/显示**；交互走 View 事件 → VM（本阶段无写路径；将来写 Model 也经逻辑层命令，不经 View）。
- 禁令：
  1. View 直接读/写 Model 数组（颜色投影必须经 VM 派生口）；
  2. VM 保存可与 Model 漂移的**平行数据副本**（派生投影可缓存，Model 变更即失效重算）；
  3. 逻辑层引用任何 UI/Godot 节点类型。

### 2.4 本阶段实例化约定（NewBall 场景）

`BallManager._Ready`（组装器 = 全部 Model 的构造权）：① 构造 `Ball`（网格数据）并 `BallView.Init` 下行注入 → 建 `H3PlateManager`（逻辑层，生成静态 Crust 场）→ ② 建 `HexWorldViewModel`（注入 Crust/网格；生成后只读派生：显示模式 + 逐格区域数据 + 边界描边角点集 + 统计）→ ③ `BallView.Bind` 一次性提交静态表面 + 烘数据纹理完成首帧渲染；`HexDock.BindModes` 与模式注册表对账（按钮文案同源、数量不符当场抛）、`HexInfoPanel` 各自 VM 注入后接线；`BallManager` 只留输入路由。

### 2.5 地图模式体系（照搬老树图层策略架构 · 接 MVVM）

> 照搬老树 MapView 图层体系（`MapLayer` 策略 + `LayerRegistry` 注册，2026-08-21 重构版），语义对齐 new_HexWorld 的「地图模式」（HexDock 模式行）。**新增模式 = 新建策略类 + 注册一行 + 坞场景加一个按钮**，不碰 View/VM 主体（老树同款扩展方式）。

- **`MapMode` 抽象策略**（UI 层，位于 VM 与 View 之间，由 VM 调用；每模式一个文件，如 `new_HexWorld/UI/Modes/`）：
  - `Id` / `Name`（坞按钮文案单一事实源——`HexDock.BindModes` 启动时取此填按钮并对账数量；`Id` 同值 = 全域材质 `display_mode` uniform，shader 分支同表）；
  - 格取色 `Color CellColorAt(int cellIdx)`：从逻辑层场派生格色（v11 起只喂格信息面板色块；球面渲染改片元侧按数据纹理派生）；
  - `bool ShowPlateBoundaries`：该模式是否叠加板块边界线层；
  - 格信息条目 `IReadOnlyList<TileInfoEntry> TileInfo(int cellIdx)`（照搬老树 `TileInfoEntry` 形态：标签/值/色块）。
- **`MapModeRegistry`**：模式有序注册表（Id 表，供坞按钮遍历与 VM 查询）。
- **投影执行（v11 全域材质）**：坞 VM 持有当前模式（交互状态）；模式切换 → 坞 VM 事件 → 球视图 VM 换 `DisplayMode` → `BallView` 只改材质 uniform（零几何重交、零 CPU 逐格取色）；格信息面板 VM 的条目按当前模式策略生成。球面区域外观 = `region_data` 数据纹理（每格 1 纹素：R 海拔归一 / G 板号色相 / B 陆性）在 `sphere_region_material.gdshader` 片元侧派生——"材质覆盖整个球、对应区域显示对应材质"；新增显示分支 = shader 加一个 `display_mode` 分支。
- **模式清单（v11 起）**：
  | Id | Name | 数据源 | 边界线 | 说明 |
  |---|---|---|---|---|
  | 0 | 海拔 | `Elevation`（米）→ 海拔色带 | ✓ | 默认模式；0m 硬台阶即海陆分界（海陆模式 v11 删除，观感由此承载），照搬老树 `ElevationLayer`（色带/分带/图例见 01 §5A） |
  | 1 | 板块 | PlateId → 板色 | ✓ | 板色纯色 + 边界描边带（2026-09-09 拍板，弃旧整格暗化） |
- 图例（海拔图模式需要色带图例）：照搬老树 `LegendBuilder` + `ColorRamp.RampLegendColors`（与画面同源），UI 接线按需。

### 2.6 实例化约定更新（模式切换路径）

`BallManager` 输入路由把坞模式点击转发坞 VM → 坞 VM 发模式变更事件 → 球视图 VM 换策略重投影 → `BallView` 订阅刷新。格信息面板在点击时经面板 VM 向当前模式策略取条目。

## 3. 场与常量（一次定义，子文档引用不重复）

### 3.1 全局地壳场（与 `Ball.CellIds` 对齐，长度 = H3 格数）

```csharp
public class Crust
{
    public int[]   PlateId;        // 每格归属板块（静态生成铺满全球，01）
    public float[] FelsicThick;    // 长英质厚（m）——陆壳本体（陆性板 35000，洋性板 0）
    public float[] MaficThick;     // 镁铁质厚（m）——洋壳本体（洋性板 7000，陆性板 0）
    public float[] SedimentThick;  // 沉积物厚（m）——暂不使用，全 0
    public float[] Age;            // 年龄（My）：陆格 1000（标记，无演化）；洋格 v12 起 = 热沉降年龄真值（离脊距离 ÷ 半扩张速率，02 §4）
    public float[] Elevation;      // 海拔（m，0=海平面）——陆基准 +LandElevM；洋基准 v12 起 = −(2500 + 350·√Age)（热沉降，02 §4）；要素增量见 02 §5
}
```

### 3.2 板表（静态）

每板 = Id、Seed（种子格心方向，诊断/将来扩展用）、IsLand（陆性标记）、Ω/R 占位（无运动；字段为将来扩展预留，不演化）。

## 4. 分辨率与尺度（静态生成同适用）

| res | 格数 N = 2+120·7^r | 格面积 | 格宽 w（对边距） | 用途 |
|---|---|---|---|---|
| 3 | 41,162 | ~12,400 km² | ~120 km | 当前测试 |
| 4 | 288,122 | ~1,770 km² | ~45 km | 当前测试 |
| **5** | **2,016,842** | **~253 km²** | **~17 km** | **最终目标世界** |

1. 一切以格为单位的量必须参数化（物理尺度 ÷ 当前格宽），换 res 不改机制。
2. 板块数 P 与 res 无关（P ≤ N 即可；v11 起无胞数 K——归并直接长在格上）。
3. 可分辨地形单元 ≥ 1–2 格；亚格细节不进模拟层，需要时渲染层装饰。**形态判读口径 = res4 起**（v12.2）：res3 格宽 111 km 下弧带（偏移 120 km / 半宽 90 km）塌成单格环、与海沟环相邻，沟-弧二元结构不可分辨；res3 只作结构不变量断言。
4. 编辑器旋钮 `BallManager.ResLevel` = **闭集枚举** `HexResLevel{Res3, Res4, Res5}`（只含本表三档；`res ≥ 6` = 14.1M 格，耗时与内存都不可承受——非法档在 inspector 里**不可表示**，好过填错跑起来才发现卡死），默认 `Res3`。`HexResLevel_ClosedSet_MatchesEntryDocResTable` 单测把取值域钉到本表（加档/删档必打到断言）；命令行诊断同一取值域（`HexTerrainShotDiag --res=` 越界直接判失败退出）。
