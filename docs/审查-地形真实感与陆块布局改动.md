## 二、架构审查

### 2.1 做得好的四处

1. **算子化分层落地**。`TerrainManager` 只做装配；`DomainWarpOps` / `HighlandOps` / `ErosionOps` / `RemapOps` / `OceanDepthOps` 均为纯静态算子，除 `Vector3` 外不碰引擎；新增文件一文件一顶层类型、file-scoped namespace、命名空间归属正确（`World.Data` / `World.Logic` / `World.Render`）。
2. **世界尺度改成定义值**。`SphericalFbmNoise.EarthRadiusKm → WorldRadiusKm` 不只是改名：值由"每格 5 km² × 格数"反推，`SpatialScale` / `DistanceFieldOps` / `SnowOverlay` 的 km 换算全部走它；`PlanetGeometry` 只保留渲染半径。渲染尺度与物理尺度被分开，这是正确的方向。
3. **领域规则变成守卫类**。`NoiseSampling` 把"最细倍频层 ≥ 3 格"从散落注释变成可调用的截断函数，① 阶段四处使用；域扭曲与细化也用了它。
4. **扩既有算子而不是分叉**。`DistanceFieldOps.Build` 增加 `passable` 谓词，山带"只在同板块内扩散"直接复用多源 Dijkstra，没有另造"板块内距离场"。

### 2.2 结构上值得商榷的四处

**A. ① 阶段认识 ⓪ 的策略枚举，耦合方向反了。**
`ContinentLayout` 是 ⓪ 的壳型分配策略，但 `TerrainManager.Run(..., ContinentLayout layout)` 只为用 `ArchipelagoBaseDropM` 就接收整个枚举。枚举现在在三个类各 switch 一次：

- `ContinentLayouts.Resolve` 定档；
- `PlateManager.AssignCrustTypes` 定块数与挑法（`PlateManager.cs:191-221`）；
- `TerrainManager.Run` 定基线压低（`TerrainManager.cs:92-94`）。

建议让 ⓪ 产出"本次世界的陆面基线偏移 `float landBaseDropM`"，① 只收这个数；`Resolve` 从 `WorldGenSimulation` 收进 `PlatePipeline`。新增第 5 档时只改 ⓪ 一处，`WorldGenSimulation.Layout/Seed/SeaLevelM` 三个"预留属性"也可随之删掉。

**B. `TerrainManager` 的职责与自身注释不一致，且新藏了数。**
类注释写"本类只负责：铺陆面基底、串联两者、把结果合成"（`TerrainManager.cs:20-21`），紧接着写"本类不藏数"（`:23`）。实际它负责 8 件事：建 6 个噪声场、建 2 层域扭曲、算近岸扭曲、调 `HighlandOps`、做 remap、算 `aboveSea`、调 `OceanDepthOps`、做平原下切。并且 `:108` 的 `SmoothStep(8f, 30f, …)` 是典型的世界形状带宽参数，没进 `TerrainSpec`；`:75` / `:79` 的域扭曲层数硬编码为 `2`。

建议把"陆面基底 + 两层次扭曲"抽成 `LandFieldOps`（返回 `HeightM` + 采样方向），`TerrainManager` 回到"调 3 个 Ops + 合成"；近岸带 8/30 km 要么进 spec（如 `CoastWarpBandKm` / `CoastWarpFadeKm`），要么在 spec 头部注明"实现常量"。

**C. 表现层重新计算世界事实。**
新 `TerrainMode` 用 `h > 0f` 判陆海（`TerrainMode.cs:35`），而同轮新增的 `WorldGenSimulation.SeaLevelM` 零消费者。同目录 `CoastDistanceMode` 已示范正确读法：`f.FinalLand[i]`。`SeaLevelM` 现为 0 时看不出差别，改海面标高后"地形"模式的海岸线就会与世界事实分叉。建议读 `Facts.Final.FinalLand`（或至少 `_p.SeaLevelM`）；`SeaLevelM` 要么被消费，要么删。

**D. 布局策略三份常量、两个近名类型。**
`ContinentLayout`（枚举）与 `ContinentLayouts`（策略类）只差一个字母；`ManyExtraPlates = 1` / `ArchipelagoExtraPlates = 3`（`ContinentLayouts.cs:18-21`）能改变世界形态，却住在 Logic，不在 `WorldSpec`。MEMORY §四 还记录旧 `ContinentLayout` 作为"无谓中转类"被删过，同名新类型容易让后来人翻错历史。建议枚举改名 `ContinentLayoutKind`（或 `WorldLayout`）、策略类改名 `ContinentLayoutPolicy`；两个增量若要可调就进 `WorldSpec`，否则注明"实现策略"。

### 3.5 边界与健壮性

1. **`capKm ≤ 0` 会让生成直接抛异常**。`DistanceFieldOps.Build` 在 cap ≤ 0 时 `throw`（`:58`），而以下调用把带宽旋钮直接乘 4 当 cap：
   - 裂谷：`4f * spec.RiftBandKm`（`HighlandOps.cs:124-125`）
   - 活动边缘：`4f * spec.ActiveMarginBandKm`（`OceanDepthOps.cs:99-101`）
   - 洋中脊：`max(RidgeAgeSpanKm, 4*RidgeBandKm)`（`:107-109`）
   - 大陆架：`ShelfMaxWidthKm + SlopeSpanKm`（`:114-115`）

   这些字段都可从参数档置 0，而 spec 没有"必须 > 0"的约束。建议 cap ≤ 0 时跳过，或让 `DistanceFieldOps` 返回空场——与 `Band(w ≤ 0) = 0` 统一成"0 = 关断"。

2. **`ErosionSteps = 0` 并不等于"关断侵蚀"**。`ErosionOps.cs:149` 只跳过水力迭代；细化照做，`:233` 的热力侵蚀是编译期 `TalusPasses = 2`，**无条件执行**。spec 注释写"侵蚀迭代步数（0 = 关断）"，MEMORY 也写"关断：ErosionSteps = 0"，与实现不符。要么把热力侵蚀也放在 `steps > 0` 下，要么拆出 `TalusPasses` 并改注释。

3. **`Quantiles` 的抽样注释与实现不符**。`HighlandOps.cs:348-355`：`stride = count / 262144`，在 `count < 524288` 时恒为 1，循环在 `samples.Count == cap` 时截断 ⇒ 实际取的是**按格索引的前 262144 个陆壳格**（地理上有偏），不是"隔格取样"。当前布局最多 5/8 陆壳（< 262144），**尚未触发**，但注释承诺的均匀性不成立。建议 `stride = (count + cap - 1) / cap`。

4. **`TerrainMode` 的第一条等高带从 25 m 起跳**。`h > 0` 时 `center = floor(h/50)*50 + 25`（`TerrainMode.cs:37`），海岸第一格直接取 25 m 颜色，与 0 m 的沙滩色之间有一道视觉跳变。

5. **`ErosionOps.DetailOctaves` / `FlowConcentration` 声明但未接线**。`DetailOctaves = 4` 从未使用（`:122` 只调 `SafeOctaves`，忽略"最多 4 层"的意图）；`FlowConcentration = 4f` 未使用（`FlowWeight` 硬写 `drop⁴`）。前者是潜在功能 bug（基波长调大时会叠出超请求层数）。

## 九、结论

- **架构**：8/10。算子化、确定性、尺度分离都到位；两处耦合（①→⓪ 枚举、表现层→世界事实）需要解。
- **实现习惯**：6.5/10。异常消息、并行纪律、契约注释质量高；重复数值助手、未接线常量、手写字段搬运拖后腿。
- **文档一致性**：5/10。同一份设计文档内部矛盾、§16 数字过期、注释与实现多处不符。
- **可验证性**：3/10。测试工程缺失，CI/pre-commit 曾是空门槛；本轮已把门槛改成"不说谎"的状态，但真正的回归测试仍需重建。

**可以按现结构继续开发，但这一包要先修 P1、再按 §7 拆分提交；测试/诊断代码不再回生产树。**
