# 设计 · 文明时代2 式战略层（初步框架）

- 状态：**方案待拍板**（2026-10-21；2026-10-22 按地球尺度更新数字）
- 前置资产：已有的自然地图——球面 H3 网格 res4、288,122 格、每格 **1,770 km²**、R ≈ **6,371 km**，
  地形 / 气候 / 水文 / 河流全部就绪（`WorldFacts` 只读快照）。
- 一句话：**在只读的自然地图上派生「省 → 国 → 回合」三层，做 AoH2 的骨架，不做它的全部血肉。**

---

## 一、先对齐：AoH2 的骨架其实只有四件事

1. **省**是地图原子：连续、有归属、有人口/经济，一切操作以省为单位。
2. **国** = 若干省 + 首都 + 国库 / 人力 / 科技。
3. **回合** = 玩家下令 → AI 下令 → 统一结算（移动、战斗、占领、经济、外交）。
4. **内容** = 场景文件（地图 + 国家 + 省份归属 + 事件），所以它才那么容易被 mod。

映射到本项目，**不需要**地图图片、`provinces.bmp`、重画海岸线：

| AoH2 的概念 | 本项目对应物 |
|---|---|
| 地图位图 | 已有：`Ball`（H3 格 + 邻接表） |
| 省 = 位图上同色像素 | 省 = 一组连续格（`int[] ProvinceOfCell`） |
| 省相邻 = 位图邻接 | 省相邻 = 格邻接跨省边界 |
| 国家颜色 | 国色 → 逐格上色（政区模式） |
| 回合 | 管理器上的显式 `EndTurn()`，**不是**逐帧 Tick |

> 也就是说：自然地图已经完成了 AoH2 里最贵的那部分（地形底图），剩下的是**离散化 + 规则层**。

## 二、规模测算（用现有数值，不拍脑袋）

球面总面积 = 4πR² ≈ **5.10 亿 km²**；按 `ContinentalRatio=0.38`，陆地约 **1.9 亿 km²**（待实测）。

| 每省格数 | 每省面积 | 全省数（按 1.9 亿 km² 陆地） | 观感 |
|---:|---:|---:|---|
| 120 | 21.2 万 km² | ≈ 920 | 碎，像 CK 的男爵领 |
| **200** | **35.4 万 km²** | **≈ 550** | **推荐：省界看得到、点击不累（≈ 德国大小）** |
| 300 | 53.1 万 km² | ≈ 370 | 偏大，适合"小场景" |
| 500 | 88.5 万 km² | ≈ 220 | 太粗，战略纵深不足 |

> ⚠️ 世界尺度 2026-10-22 从 R = 338.586 km 换成地球尺度 R = 6,371 km：格数不变 ⇒ **省数不变**，
> 但每格面积 ×354 ⇒ **每省面积 ×354**（200 格从 1,000 km² 变成 35.4 万 km²）。
> 城市 / 行军 / 视野的尺度感要按这个重估，别沿用旧数字。

**建议起点**：`TargetCellsPerProvince = 200`，全国 **25–30 国**，平均每国 18–22 省；
**1 回合 = 1 个月**，陆军每回合走 1 省（有道路/港口再 +1）。这个尺度下，一场战争 3–8 回合能打完。

## 三、分层与目录

沿用现有四层纪律（`Data / Logic / Scene / Render+UI`，Logic 不 `using Godot`）：

```
scripts/Logic/Strategy/            纯逻辑，可单测，不认识 Godot
  Partition/ProvincePartitioner.cs     格图 → 省（多源 Dijkstra）
  Partition/PartitionSpec.cs           分省参数（目标格数/阻力/种子）
  Gen/NationSeeder.cs                  首都选址 + 初始领土 + 配色
  Model/StrategyState.cs               可写状态（国/省/军队/战争）
  Model/ProvinceMap.cs                 只读省几何（格→省、省邻接、汇总属性）
  Tick/TurnResolver.cs                 回合结算（唯一写状态的地方）
  War/BattleResolver.cs                战斗/占领/和约
  Ai/NationAi.cs                       每国三条决策
scripts/Scene/StrategyManager.cs       持 State、驱动回合、向外发事件
scripts/Render/Modes/PoliticalMode.cs  政区上色（MapMode）
scripts/Render/Overlays/BorderOverlay.cs 省界线（仿 RiverLineOverlay）
scripts/UI/ProvincePanel.cs            省面板 / 顶栏 / 宣战与和谈
res/strategy/scenarios/default/*.json  内容
```

数据流（单向，不回头）：

```
WorldFacts（只读自然事实）
      │  一次性派生
      ▼
ProvinceMap（只读省几何） ──► PoliticalMode / BorderOverlay（只读）
      │  初始化
      ▼
StrategyState（可写） ──► TurnResolver ──► 新 State ──► 重烘政区 + UI
```

三条硬规矩：

1. `StrategyState` 只被 `TurnResolver` / 玩家命令改，渲染与 UI **只读**。
2. 省几何（`ProvinceMap`）生成后不再变；易主只改 `int[] OwnerOfProvince`。
3. 逐格数组只服务上色（`ProvinceOfCell[cellIndex]`），回合逻辑只在**省粒度**循环（550 个省，不是 28 万格）。

## 四、核心数据模型

```csharp
// 只读几何：一次生成，存盘只存参数，读档重算
sealed class ProvinceMap
{
    Ball Ball;
    int[] ProvinceOfCell;          // 逐格省号（海格 = -1），政区上色 O(1)
    Province[] Provinces;
    int[] BorderCellA, BorderCellB; // 省界格对（给 BorderOverlay，只存跨省边）
}

sealed class Province
{
    int Id;
    int[] Cells;                   // 连续、非空
    int[] NeighborProvinceIds;     // 由格邻接去重得到
    float AreaKm2;
    float Habitability;            // 0..1：由坡度/降水/温度/距河/距海合成
    int PopCapacity;               // 由 Habitability 与面积算出，人口增长的上限
    Vector3 CentroidDir;           // 省名标签/相机聚焦用
}

// 可写状态：存档存这一份
sealed class StrategyState
{
    int Turn; DateOnly Date;
    Nation[] Nations;
    ProvinceState[] Provinces;     // Owner / Controller / Pop / Dev / 驻军
    Army[] Armies;
    War[] Wars;
    ulong RngSalt;                 // 确定性随机的盐
}
```

> 为什么用 `ProvinceOfCell` 而不是 `Province.Cells` 做上色：政区模式每格取色是热路径
> （28 万次/次重烘），数组直查比二分/字典快一个量级；`Cells` 只给汇总与调试用。

## 五、省界生成（自然地图 → 省）——本方案的技术核心

目标不是"均分网格"，而是**让省界落在河、山脊、海岸上**，看起来像人划的而不是机器切的。

1. **候选点**：可居性加权的最远点采样（Mitchell's best-candidate）
   ——候选点评分 = 可居性高、离已选点远、优先河口/港湾；点数 = 目标省数。
2. **多源生长**：以候选点为源做 Dijkstra（或带桶的 BFS），
   边权 = 格心距 × 地形阻力：
   - 跨河 +2.0（河是天然界）
   - 坡度 > 8% 的脊线 +1.5（山脊是天然界）
   - 海岸线 +0（沿海省更容易连成一条）
   - 同权时按格 id 排序 ⇒ 确定性。
3. **容量约束**：每省格数目标 200，生长时超 1.35 倍停止扩张，让邻省接手。
4. **收尾**：< 40 格的碎片并入邻省；每省做一次连通性检查（BFS），
   断开的部分归给接触它最多的邻省；处理"省包省"的飞地。
5. **命名**：音节表 + 地形后缀（川/原/岭/港/湾），同 seed 同名去重；
   有河/湖的省优先用河流名（可直接取 `WorldFacts.Rivers` 的干流名，若有）。

**验收（M0 的硬指标）**：

- 100% 陆地格有省，海格恒 −1；每省连通、非空；
- 面积 p10–p90 落在目标 ±35%；
- 同 seed + 同参数 ⇒ 逐格完全一致（哈希比对）；
- 全省数在 400–700；边界跨河率 > 60%（说明阻力生效）；
- 全量分省 < 1.5 s（单线程，C#）。

## 六、开局国家

- **首都**：可居性 top 5% 的省，优先"河口/港湾 + 位于大陆内部"，
  首都之间球面距离 ≥ 0.25R（避免开局贴脸）。
- **初始领土**：从首都按省邻接 BFS 抢 8–20 省，按面积/人口加权，形状自然（不画圆）。
- **配色**：色相均分（黄金角）+ 明度/饱和度抖动；对省邻接图做贪心着色，
  保证相邻国不同色（政区图的第一观感全在这）。
- **属性不手填**：人口 = Σ省容量 × 0.6，收入/人力由省汇总，科技从 1 起步。

## 七、回合结算顺序（唯一写状态的地方）

| 序 | 步骤 | 要点 |
|---:|---|---|
| ① | 玩家命令入队 | 移动/招募/宣战/和谈，先校验再入队 |
| ② | AI 决策 | 每国只看自己的省与邻国，产出同构命令 |
| ③ | 移动与战斗 | 同时结算，避免"先手必胜"；战斗用确定性随机 |
| ④ | 占领与围城 | `Controller` 翻转；首都陷落给战争分数加成 |
| ⑤ | 经济 | 收入 = Σ(人口 × 税率 × (1+开发)) − 军队维护 |
| ⑥ | 人口 | 逻辑斯蒂增长，上限 = `PopCapacity`；饥荒/战乱减产 |
| ⑦ | 外交 | 战争分数 → AI 接受和约；停战期倒计时 |
| ⑧ | 事件 | 场景 JSON 里的条件事件（可选，M3） |
| ⑨ | 快照 | 重烘政区纹理、刷新面板、自动存档 |

随机数统一走 `DeterministicRandom(hash(worldSeed, rngSalt, turn, step))`，
**不碰 `System.Random`**，否则读档重放会漂。

---

## 八、战争最小闭环（够玩就行）

- **军队**：`Army { NationId, LocationProvinceId, Strength }`，一省可叠多支。
- **移动**：每回合 1 省；进入敌省若遇守军即战斗，否则直接占领（无城防的省）。
- **战斗**：`power = strength × (1 + 0.1×tech) × 地形系数`，
  守方 × (1 + 0.3×山地 + 0.2×跨河 + 0.2×城防)；差值比 → 双方损失，败方退邻省。
- **战争分数**：占领省按 `人口/总面积` 计分，首都 ×2；≥ 60 分 AI 求和。
- **和约**：胜方拿占领省（或索贡），败方签停战 N 回合；**不做好战度/厌战度**（M3 再加）。
- **叛乱**：新占领省每回合有小概率起义（用 `Habitability` 与占领时长算），给玩家找麻烦即可。

---

## 九、AI 最小可行（三条决策）

1. **预算**：国库的 60% 补军、30% 投资、10% 留底（按性格系数抖动）。
2. **扩张**：对每个邻省打分
   `score = 敌国弱度 × 省价值 × 接壤数 − 多线作战惩罚 − 停战期`，
   最高分超过阈值才宣战；否则和平期攒兵。
3. **和谈**：战争分数 < −30 或国库见底 → 主动求和；> 60 → 索省。

每国每回合只做 3 次决策，550 省规模下 AI 开销可忽略；先求"不犯傻"，不追求"像人"。

## 十、表现与交互

- **政区模式**：`PoliticalMode : MapMode`，`CellColorAt(i)` 返回
  `Nation.Color` 的海格保持地形色；未归属陆地用灰。
  每次易主/选中后 `View.RefreshColors()`（28 万格重烘，实测可接受）。
- **省界线**：`BorderOverlay` 仿 `RiverLineOverlay` 的做法——
  取 `BorderCellA/B` 的公共边中点连成短线段，屏幕空间恒 1.5 px，
  按"国界 2.0 px 深色 / 省界 1.0 px 半透明"两级。
- **点选**：现有 `PickedCell` 通道不变 → `ProvinceOfCell[cellIndex]` → 省面板；
  再次点击邻省 = 移动军队（选中态由 UI 管，地图只画高亮）。
- **顶栏**：国名/国色、国库、人力、回合与日期、"结束回合"按钮。
- ⚠️ **坞按钮数量耦合**：`MapDock.BindModes` 按数量校验，
  新增"政区/外交"两个模式必须同步 `scenes/render/MapDock.tscn` 的 `ModeRow` 按钮。

## 十一、存档与内容

**存档**只存"世界种子 + 分省参数 + 状态"，几何读档重算（≈1 s，远小于存档体积）：

```json
{
  "version": 1,
  "world": { "seed": 42, "specHash": "sha256:...", "res": 4 },
  "partition": { "targetCells": 200, "seed": 7, "riverCost": 2.0, "ridgeCost": 1.5 },
  "turn": 12, "date": "1201-01",
  "nations": [ { "id": 0, "name": "岚", "color": "#c94f4f", "capital": 37, "treasury": 240 } ],
  "provinces": [ { "owner": 0, "controller": 0, "pop": 15200, "dev": 3 } ],
  "armies": [ { "nation": 0, "at": 37, "strength": 4200 } ]
}
```

读档校验：重算后比对"省数 / 每省格数哈希 / `specHash`"，不一致则拒绝载入并提示
（世界生成参数一改，旧档地形就变了——必须挡住，不能静默错位）。

**场景内容**（M3）：`res/strategy/scenarios/<id>/` 下
`scenario.json`（开局年份、国名/旗帜/首都、省归属覆盖）、`events.json`、`flags/*.png`。
配一个最简**编辑器模式**：点省 → 改归属/开发度 → 存 JSON。这就是 AoH2 内容产线的等价物。

## 十二、里程碑

| 阶段 | 交付 | 验收 | 估时 |
|---|---|---|---|
| **M0 省界 + 政区图** | Partitioner、ProvinceMap、PoliticalMode、点选查省、调试面板 | §五 五条硬指标全过；能看着球面说"这是省" | 2–4 天 |
| **M1 国家 + 回合** | NationSeeder、StrategyState、TurnResolver（经济/人口）、顶栏、存读档 | 30 国跑 50 回合不崩、收入曲线合理、读档一致 | 2–3 天 |

M0–M1 结束就有"能点的世界"，M2 结束就是**可玩的最小 AoH2**。

## 十三、风险与不做清单

**风险**

1. **尺度**：世界周长仅 ≈2,127 km（R=338.6 km），真实地球比例下这是"一个大陆"。
   所以省数、国家数都按小世界配，别照搬 AoH2 的四千省；运输/补给按"天"算会失真，用回合抽象掉。
2. **确定性与浮点**：分区用整数权重 + 有序遍历；跨机器不要依赖 `Dictionary` 枚举序。
3. **重烘成本**：政区每次易主全量重烘 28 万格；连续动画不要每帧调，只在回合末/选中时调。
4. **坞按钮耦合**：加模式必须同步 tscn，否则启动即抛（已知设计，不是 bug）。
5. **`_removed/CivSim` 的诱惑**：它是"细胞级深模拟"（文化/宗教/贸易/战争全套），
   与 AoH2 的"省粒度轻规则"不是一个物种。**不要整体复活**，只在 M3 之后按需搬
   `WarAims` / `StateAssign` 这类纯函数（见附录 A）。

**不做（MVP 明确砍掉）**

- 实时制、单位级战术战斗、地形形变；
- 贸易路线、王朝/人物、宗教/文化传播；
- 海军与跨洋登陆（M3 之后再加，先用"港口省相邻"近似）；
- 多人联机。

## 附录 A：与 `scripts/_removed/CivSim` 的关系

那套代码是**按格模拟**的文明演化（`CivSimContext` 70 KB、政体/战争/文化/宗教/贸易齐全），
已整体移出程序集等"正确时机"。本方案**不建议**把它移回来当底座，原因：

- 粒度不匹配：AoH2 的乐趣在"省 → 国"的棋盘感，不在每格人口演化；
- 复杂度不匹配：它的战争/外交模型远重于 MVP 需要，接进来会拖慢 M0–M2；
- 它自带一套世界假设（部落→酋邦→国家），与"直接开局 25 国"冲突。

可复用清单（M3+）：`Polity` 的命名/政体枚举、`WarAims` 的和约条件、
`StateAssign` 的归并判据、以及那批测试的构造器写法。

## 附录 B：如果你指的是"给 AoH2 游戏本体做 mod"

那是另一条路，与本项目不共享代码：

1. 地图：`provinces.bmp` 每省一个唯一 RGB 色块（不能用保留色/抗锯齿）；
2. 场景：`scenarios/<name>/` 下的国家、省归属、人口、旗帜；
3. 用官方地图编辑器刷省界，或写脚本把一张"自然地图"按流域/山脊切成色块。

优点：直接得到成品游戏的全部系统；缺点：地图是**平面位图**，用不上本项目的球面世界、
气候与河网事实，省界也只能手工/图像算法切。要做的话我可以另出一份"图片地图 → 省份位图"的转换方案。
