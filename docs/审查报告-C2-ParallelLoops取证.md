## 1 ① S-6 当时到底解决了什么（沿描述反查）

### 1.1 S-6 原始症状（`docs/审查报告-2026-10-03.md:190-202` 原文）

> **🔴 S-6｜Zoom｜地形/地质生成全在主线程同步执行，首帧冻结数十秒**

量化（res4 = 288,122 格）：

| 位置 | 问题 | 开销 |
|---|---|---|
| `NoiseTerrain.SampleRawFields` | 每格 23 次 Perlin（含 warp 3×4 octave） | 288k×23×8 ≈ **5.3e7** 次哈希 → 1.5–4 s |
| `MountainSkeleton.InfluenceAt` | 逐格 × 帽内全脊 ×脊上全点，`MathF.Acos` | **2e8–8e8** 次 Acos → **数十秒** |
| `MountainSkeleton.cs:209` | `_rugged.Sample(dir)` 只依赖 `dir`，却放在**脊循环内** | 每条命中脊重复算 → **放大 5–20 倍** |

### 1.3 S-6 的实际解决方式（决策 04 原文）

`docs/newdecision/设计-世界生成空间-04-山脉骨架.md:24`：

> **性能**：逐脊**角帽预筛**（帽 = 脊点包围 + 3σ 余量；`exp(−9)≈1e-4` 截断）
> + 海格跳过。**res4 全链 11.8 s，骨架增量 ~0.1 s** —— 空间索引待实测超预算再立。

现行代码（`scripts/worldgen/MountainSkeleton.cs:198, 207, 211`）可见该优化：

```csharp
if (dir.Dot(ridge.Center) < MathF.Cos(ridge.CapRadiusRad)) continue;   // 帽外截断
...
float envelope = MathF.Exp(-(dMin * dMin) / (sigmaRad * sigmaRad));
if (envelope <= 0f) continue;                                          // 3σ 截断
```

★**S-6 的解决手段 =算法级剪枝（把 2e8–8e8 次 Acos 降到实际命中量）**，
**不是并行**。且 `NoiseTerrain`（S-6 三热点之一，1.5–4 s 那条）已随B 线清退整体删除。

## 5 三值结论

| 结论 | 含义 | 本例是否 |
|---|---|---|
| 继续保留 | S-6 职责仍无人承担，不能删 | ❌ |

| 历史资产 | 不再有生产职责，但算法本身有独立历史价值，应封存而非生产保留 | ⚠️ **见下** |

### 倾向「可删除」，但建议按「历史资产」处置

**理由**：`ParallelLoops` 的**确定性并行**设计本身有独立价值 ——
它解决的"多worker 并发下连 `max` 都可能丢更新"（`:40` 原文实测抓到过）是
**真实存在的工程陷阱**。删掉文件等于丢掉这段知识。

⇒ **建议处置**（与 B 线封存同一模式）：
1. **生产代码删除**（零引用、无职责、无消费者）
2. **设计知识封存**到 `docs/newdecision/封存-NoiseWorld设计史料.md` 或新建并行化笔记：
   记录① 确定性并行的三种写法（`For` / `ForWithLocal` / `ForFixed`）与各自的陷阱
   ② "max 丢更新"这个实测抓到的竞态
   ③ **S-6 的真正解法是算法剪枝而非并行**——这条是最有价值的教训
