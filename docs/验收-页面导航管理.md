## 环境与入口

- Windows、.NET 8 SDK、Godot 4.7.1 Mono；使用 Mono 控制台可执行文件，而非非 .NET 版 Godot。
- 以下命令均在仓库根目录执行。其他机器需调整 `$godot`，不需要修改系统脚本执行策略。
- 人工入口为 [AppRoot.tscn](<../scenes/app/AppRoot.tscn>)，可在 Godot 编辑器运行该场景。不要单独运行配置页；独立运行时不会注入导航和配置会话。
- 页面每次进入都创建新实例，生成配置会话在同一次应用运行中保留；无页面实例缓存、返回栈或自动页面发现。

### 地图浏览与加载转交

需要一份本工程支持的 `.wmap` 地图包。下面使用本机已存在的地图，不生成或覆盖地图文件：

```powershell
$mapsDirectory = Join-Path $env:APPDATA 'Godot/app_userdata/world/maps'
$map = Get-ChildItem $mapsDirectory -Filter *.wmap -ErrorAction SilentlyContinue |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $map) { throw 'Generate and export a map first, or specify a supported .wmap path.' }
& $godot --headless --path . --log-file .godot/navigation-browse-check.log res://tests/scenes/MapBrowserLoadCheck.tscn -- $map.FullName
if ($LASTEXITCODE -ne 0) { throw 'Map browse navigation check failed.' }
```

预期：`[BROWSE-CHECK] ok=True screen=MapBrowser ...`。本次使用已有 288122 格地图，实测加载和页面构建结束，进入浏览页；耗时 11383 ms，仅作本机记录，不是性能验收阈值。

没有地图包时，可在应用中生成地图，然后通过生成世界的菜单执行“导出地图数据”。如果使用自定义 Godot 用户数据目录，应手动指定地图包路径，而不是使用上面的默认目录。

## 人工操作

1. 运行应用根场景，在主菜单进入“地理演化”，修改种子但不应用，返回主菜单再进入，确认草稿仍在。
2. 应用配置并生成地图，确认进入世界页面；通过菜单返回主界面。
3. 进入地图库，打开一份有效地图，确认加载完成后进入浏览页；从浏览菜单返回地图库，再返回主菜单。
4. 确认重复进入不会叠加多个可见页面。需要检查具体清理时，使用 Godot 远程场景树确认页面容器在旧页面延迟释放后只保留当前页面。

## 扩展入口

新增普通页面时，定义对应请求并在 [AppPageFactory.RegisterPages](<../scripts/Scene/Navigation/AppPageFactory.cs#L23>) 显式登记创建委托；页面通过 [IPageNavigator](<../scripts/Scene/Navigation/AppContracts.cs#L12>) 提交请求，无需向导航接口逐页添加方法。

涉及异步加载、生成或带条件的跨页面流程时，还需接入对应的流程协调与生命周期，不应只登记一个场景就绕过业务前置条件。
