## 环境与入口

- Windows、.NET 8 SDK、Godot 4.7.1 Mono；使用 Mono 控制台可执行文件，而非非 .NET 版 Godot。
- 以下命令均在仓库根目录执行。其他机器需调整 `$godot`，不需要修改系统脚本执行策略。
- 人工入口为 [AppRoot.tscn](<../scenes/app/AppRoot.tscn>)，可在 Godot 编辑器运行该场景。不要单独运行配置页；独立运行时不会注入页面动作端口和配置会话。
- 页面每次进入都创建新实例，生成配置会话在同一次应用运行中保留；无页面实例缓存、返回栈或自动页面发现。
- 页面跳转是"组合根创建 + 宿主换子节点"：具体页面类型只出现在 [AppShell.cs](<../scripts/Scene/Navigation/AppShell.cs>) 与 [AppPageFactory.cs](<../scripts/Scene/Navigation/AppPageFactory.cs>)，`AppPageHost` 只持槽位与生命周期。

## 自动检查

### 编译

```powershell
dotnet build world.csproj --no-restore
if ($LASTEXITCODE -ne 0) { throw 'Debug build failed.' }
dotnet build world.csproj --no-restore --configuration Release
if ($LASTEXITCODE -ne 0) { throw 'Release build failed.' }
```

预期：两种配置均构建成功。首次拉取仓库尚未恢复依赖时，先执行 `dotnet restore world.csproj`。


日志中还会出现一行 `ERROR: [PAGE] 页面装配失败：... broken page`，这是检查故意挂载的失败页面（验证"装配失败保留当前页"），不是故障。

[PageShellCheck.cs](<../tests/scenes/PageShellCheck.cs>) 使用模拟宿主、模拟开图器、内存配置存储和真实页面工厂（真实场景、未入树）检查组合根行为：动作端口 → 创建 → 挂载、会话懒创建与复用、生成失败退回；不依赖截图或人工目视结果。

### 地图浏览与加载转交

需要一份本工程支持的 `.wmap` 地图包。下面使用本机已存在的地图，不生成或覆盖地图文件：

```powershell
$map = Get-ChildItem $mapsDirectory -Filter *.wmap -ErrorAction SilentlyContinue |
```

预期：`[BROWSE-CHECK] ok=True screen=MapBrowserView ...`。本次用无头生成的样本包（`userdata/saves/map_20261114_183708_449.wmap`）实测：`ok=True screen=MapBrowserView ms=11807 maxGap=242`，退出码 0；耗时仅作本机记录，不是性能验收阈值。

没有地图包时，可在应用中生成地图，然后通过地理演化页的菜单执行“保存地图”。存档固定写到游戏目录的 `userdata/saves`，不使用 AppData，也不提供自定义目录。

## 人工操作

1. 运行应用根场景，在主菜单进入“地理演化”，修改种子但不应用，返回主菜单再进入，确认草稿仍在。
2. 应用配置并生成地图，确认进入世界页面；通过菜单返回主界面。
3. 进入地图库，打开一份有效地图，确认加载完成后进入浏览页；从浏览菜单返回地图库，再返回主菜单。
4. 确认重复进入不会叠加多个可见页面。需要检查具体清理时，使用 Godot 远程场景树确认页面容器在旧页面延迟释放后只保留当前页面。

## 限制与回归说明

- 自动检查聚焦组合根行为（端口 → 创建 → 挂载）与配置/生成流程，不新增 UI 排版或截图验收。
- 空创建结果、会话复用与生成失败退回有独立断言；真实场景文件缺失、后台生成失败以及所有取消时序未逐一注入故障验证。
- 本轮删除导航层、收敛页面上下文、删除加载页容器（世界页直接占槽位，进度回到协调器的覆盖层）、把世界生成搬到协调器持有的 `WorldGenerationFlow`，并把进度显示收敛为 `LoadProgressPresenter`（覆盖层与演化面板共用）；未重构异步加载协调、生成算法或世界页结构（世界页现在只做装配与交互）；不增加导航历史、缓存和插件扫描。
- Release 程序集构建通过不等于 Windows 独立发布包验证通过；本需求未导出或验证独立发布包。
- 原有 [verify-approot.ps1](<../tests/verify-approot.ps1>) 在本机直接运行受到系统签名策略阻止。本次直接运行编译、逻辑测试、组合根/配置、真实生成与往返检查命令，没有改变系统执行策略。
- 自动检查会读取正式配置档案；组合根检查使用内存配置存储，不写正式档案。显式执行人工保存或地图导出时，才由对应功能写入用户数据。

## 扩展入口

新增普通页面：新增页面场景与脚本（实现 `IAppPage`），在 [AppPageFactory.cs](<../scripts/Scene/Navigation/AppPageFactory.cs>) 加一个创建方法并在其中注入页面需要的动作端口，再在 [AppShell.cs](<../scripts/Scene/Navigation/AppShell.cs>) 加一个动作方法（或实现该页面自己的端口）。宿主 `AppPageHost`、`AppRoot` 与页面上下文都无需改动。

页面契约在 `scripts/Application/Pages/`（`IAppPage`、`PageContext`、`IPageHost` 与宿主端口），加载模型与流程在 `scripts/Application/Loading/`；`scripts/Scene/Navigation/` 只保留页面槽位、组合根与加载协调器。

新增一个宿主动作（例如"打开设置页"）：在应用层对应的 `I*PageActions` 端口加一个方法，由 `AppShell` 实现它；不要给页面注入任何"跳转任意页面"的能力，也不要传裸 `Action`——只回主界面的场合用 `IMainMenuReturn`。

涉及异步加载或生成时，页面只读 `PageContext.Progress` 与 `Lifetime`；长任务、进度显示与操作转交归 `AppLoadCoordinator`（覆盖层由它按需创建、终态由它在 `_Process` 释放），页面不要自己创建进度层或拼 `PageContext`。

新增一种长任务流程（如导入、导出）：照 `MapBrowseFlow` / `WorldGenerationFlow` 写一个只认"操作 + 绑定 + 当前页 id"的流程类，在 `AppLoadCoordinator` 里加一个启动方法与轮询分支，由组合根注入"完成后挂哪个页面"的回调（`Action<TResult, LoadOperation>`）。流程参数用运行期选项类型承载，不要加进 `GenerationConfig`——那份 JSON 是严格 schema，加字段会破坏旧档案。
