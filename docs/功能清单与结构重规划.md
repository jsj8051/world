## 2. 结构问题诊断（附证据）

### S1 · `worldgen/` 承载 5 个架构层，33 文件扁平堆放 🔴

**现状**（按 `WorldGenPlanet.Regenerate()` 依赖序，`WorldGenPlanet.cs:92-179`）：

```
worldgen/  ← 全部 33 个文件平铺
├─ Placement       5  ContinentLayout LandSeaFields GeologicalRegions TectonicField SeedDerivation
├─ 地貌 Feature    5  TerrainFeature MountainSkeleton RegionalLandforms VolcanoField HeightComposer
├─ 离散化桥        1  H3TerrainSampler
├─ Final + Index   2  FinalGeography FinalSpatialIndex
├─ Simulation     13  SphericalField SpatialScale SurfaceResolver H3LandSeaProjector
│                     PrecipitationModel H3Hydrology HydrologyRoutingSurface RiverNetwork
│                     RiverGraph RiverGeometry RiverPresentationSpline RiverSymbolWidth
│                     BasinGraph LakeState WaterTopology SnowOverlay
└─ 表现 + 入口     4  WorldGenPlanet WorldGenManager WorldGenMapModes RiverLineOverlay
```

**问题**：目录名 `worldgen` 不表达任何架构信息。IDE 里打开 `worldgen/` 会把「世界事实源」和「渲染 overlay」和「线求解器」混在同一个平铺列表里。这直接违反项目自己的永久原则第 8 条（**物理目录 ≠ 架构边界，按 namespace/type/dependency graph 判**）——namespace 判对了（都叫 `World.WorldGen`），但**目录没跟上**。

**注意**：这不是"要不要分目录"的审美问题。`worldgen` 内部已经**天然存在 6 个可辨识的子群**（见上），且 `Regenerate()` 的依赖序把它们排成了严格的 DAG。分目录等于把**已经存在的事实**显式化，不是新增结构。
