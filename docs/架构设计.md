# world 架构设计（Architecture）

> 中世纪 4X 国家策略（Godot 4.7.1 mono / .NET 8 / C# 12）。
> 本文档描述 2026-08 重构后的现状架构；配套《开发规范.md》管代码约定。
> 核心原则：**生成与游玩解耦**（参考 Dwarf Fortress / Civilization——地图是存档，不是场景）。

---

## 1. 总体架构：双层 + 存档解耦

```
┌────────────────────────────────────────────────────────────┐
│ 纹理层（观感，25km²/格）                                    │
│   MapViewer / Planet 网格渲染、图层着色、箭头流线             │
│   GridN 对齐模拟 n：10n²+2 顶点 = 逻辑网格顶点，无需插值     │
├────────────────────────────────────────────────────────────┤
│ 逻辑层（模拟，n=64~128 目标）                               │
│   板块 / 气候 / 河流 / 矿藏 / 土壤——全部纯 C# 数组，后台线程 │
│   Task.Run 生成，主线程只读（不碰 Node/渲染 API）            │
├────────────────────────────────────────────────────────────┤
│ 存档层（MapArchive v3，user://maps/*.mpa）                  │
│   球面顶点数据直写二进制；游戏运行时只读存档，不重新生成      │
└────────────────────────────────────────────────────────────┘
```

关键决策：
- **球面直通（v3 定案）**：模拟与显示共用同一球面顶点网格（Icosahedron 细分，顶点数 = 10n²+2），无平面中转、无投影。MapViewer 每格颜色**最近顶点直读**（数组 O(1)），Shepard 插值仅用于生成期/预览平滑。
- **热路径纯 C#**：模拟数据用 float[]/byte[]/Vector3[] 原生数组；GodotObject 派生对象只在渲染边界出现（详见《开发规范.md》性能红线）。

## 4. 生成管线（PlanetPipeline 五阶段）

```
输入：PlanetParams（Seed / 自转方向 / 倾角 / 距日 / 自转速度 / 网格 n）
      板块模拟在管线外（MapGenerator 驱动，进度 UI，产出海拔+物质场）
        │
        ▼
Stage1 气候   温度/降水/biome + 洋流场（盛行风 → 科里奥利 → 雨影）
Stage2 水文   河流迭代（动态流向 + 输沙侵蚀沉积，**可改海拔**）→ 湖泊 → 流域
Stage3 生态   河岸带（沿岸 Riparian）
Stage4 资源   矿藏（矿化强度 + 分位数）／ 土壤肥力（biome 基础 ± 地形气候惩罚）
Stage5 统计   min/max 范围 → 写存档（MapArchive v3）
```

- 纯计算：无 Godot 对象依赖、无 GD.Print（后台线程安全），同步/异步两路径共用同一 `Run()`。
- 板块模拟（`TectonicsSimulation.Run`）不在管线内：耗时长（n=64 600My ≈ 2.5~3min），由 MapGenerator 分阶段上报进度。
- 星球参数：`Seed / ProgradeRotation(顺转/逆转) / AxialTilt(0~90°) / Insolation(相对 1AU) / RotationSpeed(相对 24h) / TectonicsGridN`——五件套物理参数 + 种子，全部 [Export] 可 headless 覆盖（`-- --seed=7`）。

## 5. 存档格式（MapArchive v3，Magic "MPA1"）

```
头部（固定）        Magic 4B + version 2B + seed 4B + vertexCount 4B
                   + 顶点 12n B（Vector3）
                   + 海拔 min/max + 海拔 n×4B
                   + 温度 min/max + 温度 n×4B
                   + 降水 min/max + 降水 n×4B
                   + biome n×1B
尾部扩展（向后兼容追加式，旧版无 = 默认值）
   ext1 自转方向 1B + ext2 自转速度 4B
   ext3 洋流：方向 3×4B + 冷暖 4B + 强度 4B（每顶点）
   ext4 河流：级别 n×1B + 流向 n×4B (+ 流量 n×4B)
   ext5 湖泊：级别 n×1B
   ext6 矿藏：级别 n×1B（(富度<<4)|矿种）
   ext7 土壤：肥力 n×1B（1-5）
```

兼容策略：**版本只增不减，尾部追加**。`Version = 3`，读端 `ver > Version` 拒绝；旧存档缺尾段 = 默认值（无洋流/无河流）。v2 平面存档写/读保留（调试对比用）。

## 6. 图层系统（MapViewer 10 层）

| # | 图层 | 数据来源 | 渲染 |
|---|---|---|---|
| 0 | 海拔 | elev | 连续高度色带（非线性分段） |
| 1 | 温度 | temp | 色带 |
| 2 | 降水 | precip | 色带 |
| 3 | 生物群系 | biome | BiomeColors 分类色 |
| 4 | 盛行风 | WindField | 箭头/流线稀疏采样（非涂色） |
| 5 | 洋流 | 存档 ext3 | 闭合环流圈，每圈只显最外层（网上洋流图式），红=暖蓝=寒 |
| 6 | 河流 | 存档 ext4 | 每条河独立颜色，支流汇合随主河色 |
| 7 | 流域 | 现场算 | 以河流为中心的流域划分（无阈值） |
| 8 | 矿藏 | 存档 ext6 | 矿种色 |
| 9 | 土壤 | 存档 ext7 | 肥力 1-5 色 |

性能机制：构建时每格采样一次到缓存数组，**切图层 O(1) 查表只重算颜色**（秒级，不重建网格）；切图层用取消令牌中断旧任务 + 挂载新网格前清旧 `_planetMesh`。

## 7. 物理模型要点

| 系统 | 模型 | 关键机制 |
|---|---|---|
| 板块 | tectonics.js 移植（Schellart 2010 速度模型） | 板内网格 + 欧拉旋转；slab pull + 拖曳力平衡；均衡补偿；洋壳年龄重置维持密度差驱动（请求棘轮是板块数收敛主因，已修） |
| 气候 | 盛行风主导 | 风 = 科里奥利偏转 + 雨影效应；降水噪声只作小扰动，不主导（用户定案：物理主导） |
| 洋流 | 流函数法 | 闭合环流圈追踪 |
| 河流 | 动态流向 + 输沙 | 侵蚀/沉积可改海拔；内流河断流自然实现；收敛检测；河谷三角洲；河岸生态带 |
| 矿藏 | 矿化事件累积 | 裂谷/俯冲/增生热液 + 沉积 + 变质在板块演化中累积强度；**分位数模型**（倾向分 × 固定百分位 + 微扰，禁绝对阈值） |
| 土壤 | 分位数相对阈值 | biome 基础 + 冲积/火山加成 − 坡度/气候惩罚，肥力 1-5 |

## 8. 性能基线（2026-08 实测）

| 配置 | 耗时 | 备注 |
|---|---|---|
| n=16 全链路 | ≈26s | 开发验证默认档 |
| n=32 全链路 | ≈160s | 用户目标 15-30s（差 5-10 倍，需大刀：Move 板内并行已做、stepMy=4、GC 复用） |
| n=64 板块 600My | ≈2.5-3min | 7 板块基线 |
| 河流/湖泊基线 | 3258 条 / 1074 湖 | n=32 |

已知优化手段：Move 板内顶点级并行（ThreadLocal scratch 防竞态）、SimStepMy 2→4、Merge/Erode 缓冲复用。Rifting 板级并行验证无收益已回滚。

## 9. 技术决策记录（含否决项）

| 决策 | 结论 | 理由 |
|---|---|---|
| 动态 LOD | **否决 → 静态烘焙** | 反复出 bug，用户质疑成熟度；改 ChunkMeshBuilder 静态分块 |
| 平面投影中转 | **否决 → v3 球面直通** | 数据流直接性：板块本就在球面上生成，无需投影再转回 |
| 噪声生成地形 | **限制作初始条件** | 最终地形由板块物理塑造；降水由风/科里奥利/雨影主导 |
| 矿藏绝对阈值 | **否决 → 分位数模型** | 判定阈值必须相对该星球分布（通用性） |
| 显示层 Shepard 插值 | **否决 → 最近顶点直读** | 渐变观感"一团团"；Shepard 只用于生成期预览 |
