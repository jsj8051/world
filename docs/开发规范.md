# world 开发规范（Coding Standards）

> 环境：Godot 4.7.1 mono / .NET 8 / C# 12。全程中文注释与提交信息。
> 本文件是项目落地的精简约定；完整官方依据见 Hermes skill `godot-dev-standards`。

## 1. 命名

| 对象 | 约定 | 示例 |
|---|---|---|
| .cs 文件名 | PascalCase，**必须与类名一致** | `BallView.cs` |
| 类/方法/属性 | PascalCase | `Run()` |
| 私有字段 | `_camelCase`（下划线前缀，官方要求） | `_layer` |
| 局部变量/参数 | camelCase | `vertexCount` |
| 命名空间 | `World.<模块>`；★**按类型语义定位，不按目录**（子目录不进命名空间） | `World.Render` |
| 信号 | 委托名 `EventHandler` 结尾 | `[Signal] HealthChangedEventHandler` |
| 常量 | PascalCase | `public const float HighlightWidthPx = 3.0f;` |

- **标识符一律英文**（类/方法/字段/变量/参数/测试方法名均同；测试方法用 `Subject_Scenario_Expectation` 三段式）——中文只出现在注释、字符串字面量（异常消息/UI 文案/断言消息）里（2026-09-07 用户纠正）。

- Godot 派生类必须 `partial`（source generator 要求，诊断 GD0001/GD0002）。
- 类内顺序：字段 → 属性 → `_Ready/_Process` 回调 → 方法。
- `var` 仅当右侧类型显而易见（`new Vector2(...)` / 字面量 / 强转）。

## 2. 目录约定

- `scenes/core/` 只放正式流程场景；诊断/调参场景一律 `scenes/diag/`（headless 验证入口）。
- `scripts/Diagnostics/` 集中诊断脚本（命名空间 `World.Diagnostics`），生产模块目录不放诊断代码。
- 新增 C# 脚本：`scripts/<模块>/<类名>.cs`，`.uid` 文件由 Godot 生成，**必须入库**（场景 ext_resource 按 uid 引用）。
- ⚠️ **移动/改名文件必须同步改 `.tscn` 的 `ext_resource` 路径与节点名**——Godot 的场景挂载本身就是引用边，只改 `.cs` 会漏（决策 08 §4.3 实测：漏了 `NoiseCellPanel`/`NoiseDock` 两个主入口面板）。
- 文档目录 `docs/` 有 `.gdignore`（免导入）；新增文档不要删它。
- 第三方资源放 `addons/`；`project.godot` 只在需要时改。
- **H3 原生库（Uber 六边形索引，2026-09-02 接入）**：库本体在 `native/h3/`（h3.dll + 官方公开头 h3api.h + LICENSE/NOTICE，MinGW 编译，仅依赖 KERNEL32+UCRT）；托管门面 `scripts/Utils/H3/H3.cs`（`World.Utils.H3`），底层声明 `H3Native.cs`。引用 = `H3.LatLngToCell(...)` 等静态方法。重编译/升级：`bash native/h3/rebuild.sh`（拉官方 tag + CMake 构建 + 依赖校验）。DLL 由三个 csproj 的 `None+Link` 自动拷到各自输出目录，正常运行无需干预。

## 3. git 约定

- 忽略：`.godot/`、`bin/`、`obj/`、`*.lscache`、`*.old`。
- **入库**：`.uid`、`.import`（官方 VCS 指南：保证 uid 稳定）、`.sln`/`.csproj`、`.gdignore`。
- `.gitattributes` 强制 `*.cs/*.tscn/*.gdshader` LF（勿动）。
- 提交信息：中文，一句话说清"改了什么+为什么"（参考 git log 历史风格）。
- 大改动勤提交；重构/移动文件用 `git mv`（保留 rename 历史）。

## 4. 验证流程（改 C# 后必做）

```bash
# 1) 全量重编译——增量 dotnet build 会静默失败（输出重定向到 .godot/mono/temp/bin/Debug/world.dll）
dotnet build -t:Rebuild          # 必须看 0 错误；对比 DLL 时间戳确认新程序集

# 2) headless 跑（诊断场景可直接验证；世界生成主链路 res2 ≈23s，res4 更慢）
"D:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe" \
  --headless --path E:/godotGames/world --quit-after 400 res://scenes/diag/PeekDiag.tscn

# 3) 断言：tile count = 10n²+2；headless 跑诊断场景，GD.Print 断言 + 非零退出码判定失败
```

- 验证只信真实 C# 诊断 + headless 输出；**禁止用其他语言复刻行为验证**。
- 诊断场景 headless 可跑：GD.Print 输出断言数据（tile count = 10n²+2 等），配合 `--quit-after` + grep 验证。

## 5. 性能红线

- 模拟热路径：纯 C# 数组/字典/普通类（绕开 interop）；后台线程（Task.Run）**绝不碰 Node/渲染 API**。
- 对象属性查询最慢（脚本 setter → ClassDB 链）→ 热路径先存局部变量。
- GodotObject 属性循环读写先局部累加再赋值（如 `Position += ...`）。
- 判定阈值**必须相对该星球分布**（分位数模型），禁绝对阈值/硬编码参数。
- 显示层每格颜色 = 最近顶点直读数组；Shepard 插值只用于生成期预览。

## 6. 陷阱清单

| 陷阱 | 现象 | 处理 |
|---|---|---|
| CS1612 | `Position.X = 1f` 编译错 | struct 拷贝；局部变量整体赋值 |
| snake_case API | `CallDeferred("add_child")` | 用 `MethodName.X`/`PropertyName.X` |
| 改 [Export]/[Signal] 不生效 | 编辑器看不到新字段 | 必须重新 Build |
| 删 .godot/mono | 诡异构建问题 | 删掉让它重建 |
| SetScript() | 释放 C# wrapper | `GodotObject.InstanceFromId` 重取 |
| git D（deleted）状态 | 误以为异常 | 先 `git log --format='%h %an'` 看提交者再处理 |
| H3 坐标单位是弧度不是度 | 计算位置偏差 | 门面 `LatLng` 的 Lat/Lng 均为弧度（与 h3api.h 一致）；换算 `Math.PI/180` |
| H3 gridDisk/compact 输出数组内部任意位置可能留 0 | 结果多出 0 元素 | 门面已整体剔除；未来直接 P/Invoke 时须整体过滤，不能只删尾部 |
| h3ToString 缓冲区 < 17 字节 | E_MEMORY_BOUNDS(14) | 门面用 StringBuilder(17)；C 端按完整 uint64 的 16 位十六进制 + 终止符要求 |
| 五边形 cellToBoundary 顶点数可达 10 | 以为边界就是 5/6 顶点 | 是 5 原始顶点 + 5 个 icosahedron 面边穿越点（h3api.h 注释）；断言用范围 5–10；几何形状以 CellToVertexes 为准 |

## 7. 生成与验证约定（世界生成空间）

- 星球参数在 `WorldGenPlanet` 上 `[Export]`：`ResLevel` / `Radius` / `ContinentCount` /
  `LandFraction` / `Seed` / `TargetRegionAreaKm2` / `LodNearRatio` / `BackfaceCullRatio`。
- ⚠️ **`ResLevel` 只有一个来源**：`WorldGenPlanet` + 场景实例覆写。
  历史上旧线 `NoisePlanet` 曾有第二套同名导出（已随 B 线清退删除）⇒
  改分辨率只需改这一处。
- headless 调参：`-- --seed=7 -- --run 300` 覆盖导出属性（参考各诊断场景注释）。
- 生成结果对比必须**同参数同条件**（同 seed / 同 res）才有效。
- **跨 res 对比先做维数检验**（实测比 vs 格间距比），再怀疑模型——
  目标不是"res1 与 res4 每格数值一样"，而是"提高 res ⇒ 宏观统计量趋于稳定"。
- 存档永远向后兼容：新字段走尾部追加，Version 只增不减。
